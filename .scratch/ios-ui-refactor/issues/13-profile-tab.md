**判断记录（均已评估，评审阶段会再向用户确认）**

1. **摘要值的口径**：账本个数只数**自己的**账本（不含我加入的共享账本）；预算项数只数**本月「全部账本」口径**（账本专属预算不计入，与预算页默认视图一致）；分类 / 支付渠道 = 预设 + 自己未删除的。设计稿只写了「N 个 / 本月 N 项」。
2. **待确认账单用红色计数角标，不用右侧文字**（设计稿 04）；数量为 0 时不显示角标，读屏名称不带数量。
3. **「立即同步」始终显示**（待同步为 0 时也可点，沿用旧组件）；设计稿示意图画的是有待同步的状态。
4. **增强：区分「未登录」与「资料读取失败」**：旧页把读取异常吞掉后一律显示「请先登录」，会让已登录用户误以为被登出；现在读不出资料时显示「资料加载失败 + 重试」，同一用户刷新失败则保留已显示的资料并提示。不属于新功能，是展示层的错误状态。
5. **同步失败的 Toast 保留系统返回的错误文字**（既有行为，不改文案）；是否简化成面向用户的文案记为待判断项。

**契约（后续 ticket 直接使用）**

- **`SyncStatus` 现在渲染成一个 `ListCell`**：调用方负责外层 `GroupedList`、传 `UserId`、需要刷新时用 `@ref` 调 `RefreshAsync()`（子组件自己 `StateHasChanged`，见 ADR 0007 §13），同步结束经 `OnSynced` 通知。没有别的使用方。
- **「我的」摘要自动更新靠事件**：二级页面关闭（`PageClosed`，`/add-bill` 除外）→ 重读全部摘要与同步行；`BillChanged` → 同步行；`PendingBillsChanged` → 角标。14 / 18 / 19 / 20 号迁移分类 / 预算 / 待确认 / 导入页时**不需要**通知「我的」；若某个操作会改摘要但页面没有关闭（例如页内 Sheet 改了数量），要自己发事件或让用户刷新。
- **E2E 钩子**：`profile-*`、`sync-row` / `sync-now` 登记在 `tests/e2e/README.md`；造数 helper `LocalDb.seed_category` / `seed_channel` / `visible_category_count` / `visible_channel_count`（14 号分类 / 支付渠道页直接复用）。
- **新标记不要用 `<p>`**：MASA 的 `.m-application p { margin-bottom: 16px }` 特异性高于单类名选择器，外边距清不掉（见发现第 1 条）。

**实现要点 / 发现**

1. **MASA 的 `.m-application p { margin-bottom: 16px }` 特异性高于单类名选择器**（E2E 的间距断言发现）：资料卡里的手机号 / 注册日期最初用 `<p>`，`.ft-profile__phone { margin: 0 }` 输给它，两行被撑开 32px（`.ft-profile__who` 高 78 而不是 46）。改用 `div`；全局性的修复（`EmptyState` 的 `<p>`、`.ft-group__footer` 等）归 23 号（**23 号已处理**：`ui.css` 开头 `.m-application p { margin-bottom: 0 }` 全局归零）。
2. **「已退出登录」Toast 会被布局切换丢掉**：确认退出后立刻 `Replace("/login")`，`MainLayout`（页面栈 + Tab 栏）换成 `AuthLayout`，排队中的 Toast 随旧布局销毁——旧「我的」页就是这样，不是这次引入的。E2E 用 `MutationObserver` 断言「Toast 已入队」；要不要在登录页做一次性提示留给 22 号。
3. **假云端没有同步接口**：「立即同步」的成功路径（待同步数量清零、同步后摘要刷新）无法自动化，E2E 验证的是云端不可用时的失败提示、按钮恢复、数量不变、不登出；成功路径转人工验收。
4. **依赖旧「我的」页的 E2E 断言**：① `tab_shell_test.py` 的「我的 → 账单列表」入口断言删除，改测首页「最近账单 → 全部」（返回键回到首页，没有多出一层账单页）；新「我的」只比一屏多一点（滚动范围约 136px），滚动保活 / 底部留白 / 回顶改在压矮到 560 高的视口里做，不再依赖页面碰巧有多高；② `tab_slider_test.py` 的滚动收缩与页面保活改在「账单」Tab 上做——先造 30 笔账单，因为「账单」Tab 常驻 DOM、早先已读过一次（那时还没有账单），要自己下拉刷新重读（原为点它的刷新按钮，按钮撤掉后改用 `pull_refresh`）；③ `immersive_safe_area_test.py` 删掉旧 `.container` 根页面的内边距断言（四个 Tab 根页面都已迁移，各页自己的 E2E 覆盖「让出状态栏 / 底部留白」），保留 Tab 栏在刘海 + 手势条下的几何，旧二级页的兼容层检查改指向「统计 → 自定义报表」（21 号迁移它时再改）；④ `statistics_trend_annual_test.py` 删除「应用内压栈旧地址」一段：「我的」里的入口移除后应用内没有调用方，而 PageStack 只响应自己的导航，`Blazor.navigateTo` 压不进去，没法再自动化。
5. **`StatisticsRedirect` / `StatisticsSegmentRequest` 现在只剩兜底作用**（MAUI 里没有 Web.Server 的 HTTP 302，外部深链只有它接得住）；是否在 24 号清理时删除记为判断项。**（24 号决定保留）**：删掉之后这些旧地址在 MAUI 里会落到「页面未找到」，保留的成本只是一个薄页面 + 一个有单元测试的一次性请求服务；跳转页的转圈已换成设计系统的图标 + 令牌色，见 ADR 0007 §14 / §27。
6. **E2E 造数要注意用户可见性**：分类 / 支付渠道个数 = 预设 + 自己未删除的，所以断言用 `visible_*_count` 读库的实时结果（预设个数会随版本变化，不写死 15 / 9）；他人的、已删除的自定义项要造出来当反例。
