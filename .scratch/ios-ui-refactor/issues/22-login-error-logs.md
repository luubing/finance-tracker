**判断记录（均已评估，评审阶段会再向用户确认）**

1. **登录面板底部没有「登录即代表同意《用户协议》和《隐私政策》」那一行**：设计稿 12 画了它，但应用里没有协议与隐私文本，spec 与 ticket 也没要求。面板底部的留白（含手势条）按它的位置留着，将来补文案只需加一行。**待用户确认**：要不要补（需要提供文案与链接）。
2. **手机号输入沿用旧规则的两处缺口，没有改**：① `PhoneValidator` 只看「11 位且以 1 开头」，不检查是不是全是数字（登录与邀请成员共用，spec 约定不改规则）；② `maxlength=11` 会把粘贴进来的带空格 / 连字符的号码（「138 0013 8000」）截成前 11 个字符（旧页面一样；想「先去格式再截断」就得在输入事件里改写输入框的值，与「不受控输入」的做法冲突）。**待用户确认**：要不要修（①改共用规则；②去掉 `maxlength`、提交时整理）。
3. **退出登录后，登录页不显示一次性的「已退出登录」提示**：Toast 会随布局切换（主布局 → 登录布局）一起被丢掉，这是 13 号 ticket 起记录的既有限制；本 ticket 没有为它在登录页里加一次性提示（spec 不要求）。**待用户确认**：是否需要。
4. **刷新收进了「⋯」菜单，错误日志页没有下拉刷新**：旧页面右上角有独立的刷新图标；二级页面右上角只放一个「⋯」，刷新是旧功能不能丢，所以与 筛选 / 导出 / 清除 一起收进菜单。spec 只要求首页与账单页下拉刷新，所以日志页没有做。**待用户确认**：刷新要不要在页面上露出一个独立入口。
5. **日志时间按机器本地时区显示，没有走 `AppTimeZone`**：日志文件里的时间戳（带时区标记的 ISO 时间）由 `LogViewerService` 用 `DateTime.TryParse` 解析成机器本地时间，再按本机时间显示与分组，这是旧实现的口径，本 ticket 没动。日志不是账单，没有「应用时区」的业务含义；改成 `AppTimeZone` 会让「今天 / 昨天」与手机系统时间对不上。**待用户确认**：保持现状。
6. **级别筛选的「Critical」改成 `Fatal`，并且只列真实出现过的级别**：Serilog 写的最高级别叫 `Fatal`，旧页面的「Critical」在日志文件里根本不存在（选了永远没结果）；`Information` / `Debug` 同理——应用只写 Error 及以上（`MinimumLevel.Error()`），这两个固定选项永远为空。现在 Fatal、Error 一定有，其它级别只在日志里出现过（或已选中）时才列出。
7. **概览的三个数字改成中性色**：旧页面总数品牌色、今日日志「有日志橙色 / 没有绿色」、本周蓝色。整个重构里金额与计数不靠颜色传达含义（已确认的「金额中性色」取舍同理），今日有 / 没有日志本来就由数字与列表说明。
8. **分页由页码改成「加载更多」**：每次再取 20 条，没有页码也不能跳页；日志按时间倒序、通常只看最新几条，翻到很后面的需求很少。备选：保留页码分页（与旧版一致，但与账单列表的交互不统一）。
9. **清除成功后复位搜索与筛选**：旧页面保留条件并重新加载，结果是「条件 + 一个空列表」，看不到「暂无错误日志」的好消息；现在清除后回到空状态。
10. **导出仍只按日期范围，文件仍落在应用缓存目录**：服务接口没有级别 / 关键字参数（改接口属新功能），导出的文件在手机上用户是否够得着、需不需要原生保存 / 分享通道，只有真机上才知道。**待用户确认**（真机验收后）。
11. **搜索提交的停顿从 300 ms 改为 350 ms**：改用与账单搜索同一件共享的 `SearchField`（不受控、系统「搜索」键、清除按钮），停顿取它的统一值；体感无差别。
12. **详情由行内展开改为半屏 Sheet**：ticket 明确要求（设计稿 05 的二级页面与弹层规范）；多出「异常类型」一项（旧页面把它放在行里的 chip）。
13. **登录页的输入框是不受控的**（不回写 `value`）：受控输入在 Blazor Server 下，快速输入时 `@oninput` 往返会用旧值覆盖用户刚敲的字（E2E 实测丢字，见发现 1）；提交时用事件里捕获的值。
14. **日志级别默认值保持「Error」**：解析时日志行没有 `@l`（`CompactJsonFormatter` 只在非 Information 时写）默认当 Error；应用只写 Error 及以上，所以无影响。若以后放开最低级别，这个默认值要改成 Information（沿用旧实现，没动）。

- **不受控的文本输入**：凡是用 `@oninput` 取值的文本框都不要把 `value` 绑回去（登录页、`SearchField` 已经是这样）；提交时用事件里捕获的值。受控写法在 Blazor Server 下快速输入会丢字。
- **`p.ft-xxx` 选择器**：MASA 的 `.m-application p { margin-bottom: 16px }`（特异性 0,1,1）会盖掉单类名的样式；登录页里的 `<p>` 一律写成 `p.ft-login__xxx`。全局修复归 23 号（**23 号已处理**：`.m-application p { margin-bottom: 0 }` 全局归零；`p.ft-xxx` 的写法留着无害，24 号清理时可收回）。**（24 号评估后不收回）**：这些选择器无害，改动要碰多处已验收的样式规则，没有用户可见的收益，见 ADR 0007 §27。
- **E2E 基座**：`login()` 按 `login-phone` / `login-submit` 取元素（不再依赖按钮文案）；`log_directory()` / `LogFiles`（`write` / `files` / `clear`）/ `log_entry()` 按应用真实的日志文件格式造数据，日志页 E2E 只读专用目录（`server.ps1` 设置 `E2E__LogDirectory`，`GET /__e2e/log-directory` 返回它），**绝不碰开发机上真实的日志**；日志 / 列表类断言用 `wait_titles` 等「内容」，不要只等「条数」（连续两次结果条数相同会读到上一次的列表）。
- **BottomSheet 的高度由内容决定**（最高到状态栏下方留 12 的缝）：详情 Sheet 里异常堆栈很长时会接近全屏，不要断言「半屏」，断言「底边贴底、顶边不进状态栏、没有横向溢出」。
- **Playwright 在 Windows 上的两个坑**：`fill()` 受 `maxlength` 约束（超长的测试数据会被截断，不会报错）；剪贴板读出的换行是 CRLF。

**与 ticket / 设计稿的差异（均已评估）**

- **设计稿没有错误日志的专属画面**（screens 的 13 张里没有）：视觉按二级页面模板 + 设置式分组列表 + 与账单筛选同一套的筛选 Sheet 自行落地，验收阶段只能对照「模板与令牌」而不是某一张画面。
- **登录面板底部没有「用户协议」一行**（判断 1）；其余登录页元素（渐变与三个装饰圆球、玻璃 Logo、「记账本」与标语、白色圆角面板、「+86」输入条、品牌色主按钮）按设计稿 12 落地。
- **概览数字中性色**（判断 7）、**级别筛选「Critical」→「Fatal」**（判断 6）、**「加载更多」取代页码**（判断 8）、**清除后复位条件**（判断 9）、**刷新收进「⋯」**（判断 4）：均为有意的差异，理由见判断记录。
- **ticket 之外多做的**：日志数据层的四处既有缺陷（实现要点 3）；日志页 E2E 专用目录与 `/__e2e/log-directory`（让日志类测试可重复、不碰开发机真实日志）。

**实现要点 / 发现**

1. **受控的手机号输入框在 Blazor Server 下会丢字（E2E 发现）**：最初用 `@bind:event="oninput"` 并回写 `value`，快速输入时每次 `oninput` 的往返会把输入框改回旧值、吞掉刚敲的字。改成不受控：输入框不绑 `value`，`@oninput` 只记下当前值并清掉旧的校验提示，提交时用事件里捕获的值。`SearchField` 早就是这个写法，现在成为通用规则（见契约）。
2. **Playwright 的 `fill()` 受 `maxlength` 约束**：第一版测试想「填 12 位看会不会放行」，实际被截成 11 位——是测试数据的问题，不是页面放行了。改为只断言「按键输入最多 11 位」。
3. **日志数据层的四处既有缺陷（顺带修复，ticket 没点名）**：
   - ① 消息读的是 `@m`，而应用写日志用的 `CompactJsonFormatter` 没有这个字段（只有 `@mt` 模板 + 属性）→ 页面上每一行的消息都是空的。现在由新增的 `LogMessageTemplate` 把 `@mt` 与属性渲染成消息（`@m` 存在时仍优先）。
   - ② 级别筛选用「Critical」，Serilog 实际写的是 `Fatal` → 选了永远没有结果（判断 6）。
   - ③ 读目录用 `#if ANDROID || IOS` 取 `FileSystem`，但服务所在的 `FinanceTracker.Web` 只编译 `net10.0`，这段是死代码 → 真机上读的目录与 Serilog 写的目录对不上。现在构造函数接收日志目录，MAUI 宿主把 Serilog 写日志的目录（`FileSystem.AppDataDirectory/Logs`）同时传给它。
   - ④ 导出时缓存目录不存在会失败 → 导出先建目录。

   这四处都由 `LogViewerServiceTests` 用真实日志文件格式锁定；**第 ③ 处只有真机能验证**（见待人工验收）。
4. **BottomSheet 的高度由内容决定**：详情 Sheet 里异常堆栈很长时会接近全屏（最高到状态栏下方留 12 的缝）。E2E 的「半屏」断言因此改成：底边贴屏幕底、顶边不进状态栏、没有横向溢出；只对内容少的那一行断言高度 ≤ 屏幕的 60%。
5. **连续两次搜索结果条数相同时会读到上一次的列表（E2E 竞态）**：旧写法先 `wait_list(1)` 再读行标题——上一次搜索也是 1 条时，「等 1 条」立刻成立，读到的是旧列表。改为 `wait_titles` 等「内容」。
6. **`PopoverMenu` 定位时右缘比锚点右缘内缩 12**（`data-placement=below`）：设计如此，E2E 按这个口径断言。
7. **Windows 上的剪贴板**：读出的换行是 CRLF，且需要给上下文授予 `clipboard-read` / `clipboard-write`；已写进 README 的已知限制。
8. **`logs-failed`（加载失败占位）在 E2E 里到不了**：页面的失败分支只在服务抛异常时才出现。审查（第 1 轮）发现 `LogViewerService.GetLogsAsync` / `GetStatisticsAsync` 原先自己吞掉全部异常并返回空，这个分支在真实运行里**永远到不了**、「读失败」会被当成「没有日志」。已修：「有日志文件、但所有文件都读不出来」时抛 `IOException`（个别文件读不出来仍跳过并记 Warning），并补两条单元测试（`LogViewerServiceTests`「读取失败」一节）；页面这一支在浏览器 E2E 里仍造不出（要制造文件读取失败），列入人工验收。
9. **页面的读取放在 `OnAfterRenderAsync(firstRender)`，并用 `_loadVersion` 丢弃过期结果**：Blazor Server 预渲染与交互阶段会各读一遍日志；连续改条件时多次读取在途，只让最后一次的结果生效。
10. **登录 E2E 的「登录中」状态用 `MutationObserver` 抓取**：登录调用在本机几乎瞬间完成，轮询看不到 `aria-busy` 的那一帧；点按钮之前挂上观察者，登录完成后读它记下的状态。
11. **玻璃层预算**：登录整页只有 1 个玻璃层（Logo，`.ft-glass-dark`）；错误日志页自己的表面（概览、列表、条件条）是不带 `backdrop-filter` 的白卡，只有 Sheet、菜单与导航按钮用玻璃，每屏 ≤ 3 层（单元测试 + E2E 双重锁定）。
12. **全量回归里的偶发失败（`addbill_sheet_test.py`，与本 ticket 无关）**：账单 Tab 在数据到达后会把列表重新渲染一次（行节点被整个换掉），「行可见」之后紧接着**单次**读文字，撞上换节点的瞬间就读到空串。修法是新增 `bill_row_text`：反复读到包含全部期望片段为止，超时返回最后读到的文字让断言带着它失败。以后凡是「等到可见 → 读内容」的写法，都应该等「内容」而不是等「可见」（与发现 5 同一类）。

### 待人工验收（设备 / 模拟器）

以下只能在真机 / 模拟器上确认，**不能由 Web.Server 下的 E2E 代替**，所以验收清单的那一格保持未勾选：

- [ ] **状态栏**：登录页渐变真的铺到屏幕最上沿、状态栏图标是白色；登录后进首页（深色 Hero）仍是白色，进二级页面（浅色导航栏）变深色。
- [ ] **软键盘（最重要）**：Android（沉浸式下的 `WindowInsets` / `adjustResize`）与 iOS（WKWebView 是否缩小视口）上，点手机号输入框后，面板与「登录 / 注册」按钮是否仍在可视区、没被键盘盖住；若平台不缩小视口（`100vh` 不变），登录页要改用 `visualViewport` 调整高度。
- [ ] **号码键盘与自动填充**：弹出的是数字键盘；键盘上的「前往」键能提交；系统的手机号自动填充（`autocomplete=tel-national`）能填入且不被 11 位限制误伤。
- [ ] **错误日志在真机上读得到日志**（第 ③ 处目录修正的首次真机验证）：先制造一次 Error 级日志，再打开「我的 → 错误日志」，页面不能永远是空的；清除后文件确实被删。
- [ ] **复制**：MAUI WebView 里 `navigator.clipboard.writeText` 是否可用（Android WebView 要求用户手势与安全上下文）；不可用的话需要原生剪贴板接口（新增原生能力，另行评估）。
- [ ] **导出**：文件真实落点（应用缓存目录）用户够不够得着、需不需要原生保存 / 分享通道（判断 10）。
- [ ] **手感**：「⋯」菜单、筛选 Sheet、详情 Sheet 的弹出与收起、Sheet 内滚动；几百行的长异常堆栈在详情里的滚动、选择与横向滚动。
- [ ] **窄屏与大字号**：320pt 宽、系统大字号下，登录页、日志页没有溢出 / 重叠。
- [ ] **加载失败占位与骨架屏**（E2E 到不了，实现要点 8）：目测一次。
- [ ] **判断项 1–10 的确认**（尤其 1、2、3、4、8、10）。
