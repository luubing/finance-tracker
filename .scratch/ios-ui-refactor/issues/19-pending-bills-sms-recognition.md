## 开工前清单：两个旧页面的全部功能点（迁移后逐项对照，见文末「逐项对照」）

**待确认账单页（旧 `PendingBills.razor`，路由 `/pending-bills`）**

- P1 权限引导：通知使用权未开启 → 提示「开启“通知使用权”后，微信/支付宝的支付通知会自动填入待确认账单」+「去开启」（`OpenSettingsAsync`）；短信权限未授予 → 提示「授予短信权限后，银行扣款短信会自动填入待确认账单」+「去授权」（`RequestPermissionAsync`，成功提示「短信权限已授予」）。
- P2 空状态：「暂无待确认账单」+「支付后，微信/支付宝通知与银行扣款短信会自动出现在这里」。
- P3 「全部忽略」（`ClearAsync`，旧页面没有确认；本 ticket 要求改成 Alert 确认）。
- P4 列表项：收支图标、「支出/收入 ¥金额」、「渠道 | MM-dd HH:mm」、数据来源（通知栏 / 短信）、备注（最多 40 字 + 「…」）。
- P5 「确认」：账本必选——一个账本都没有就不打开对话框，提示「账单必须归属一个账本，请先创建账本」并跳到账本管理；对话框可修正金额（数字输入）、类型（收入开关）、支付渠道（该用户的渠道下拉）、账本（只列自己的账本）。
- P6 校验：金额必须大于 0（「请输入有效的金额」）；账本必选（「请选择账本」）。
- P7 入账：分类 = 该类型下名称含「其他」的第一个，否则该类型第一个；支付渠道 = 名称精确匹配，否则名称包含；任一为空提示「无法匹配分类或支付渠道」；账单字段：金额 / 类型 / 分类 / 支付渠道 / 账本 / 交易时间沿用待确认项的时间 / 备注沿用待确认项的内容 / 数据来源沿用识别来源（通知栏 / 短信识别）/ 同步状态待同步，经 `BillService.CreateBillAsync` 写入（服务层统一校验账本必填）。
- P8 入账后移出待确认列表（`RemoveAsync`，独立 DbContext，与账单保存不在同一事务）：账单已保存后若移除失败，不能再报「创建账单失败」（否则用户重试会产生重复账单）——当前页立刻去掉这一项并提示「账单已创建，但从待确认列表移除失败……请点「忽略」，不要重复确认」；成功提示「账单创建成功」。
- P9 入账失败提示「创建账单失败: …」。
- P10 「忽略」单条（`RemoveAsync`，提示「已忽略」）。
- P11 订阅 `PendingBillsChanged`：后台捕获新支付时列表实时刷新；电路已关闭时忽略刷新失败；页面销毁时取消订阅。
- P12 账本只列自己的（共享账本不能被通知 / 短信自动记入）；加载失败不能当作「没有账本」（提示「加载账本失败: …」）；创建账本回来后（`OnPageActivatedAsync`）刷新。
- P13 确认对话框是 Persistent（点外面不收起，避免误丢）。
- P14 入口：首页横幅（07）、「我的」入口 + 红色角标（13），路由 `/pending-bills` 不变。

**短信识别页（旧 `SmsRecognition.razor`，路由 `/sms-recognition`）**

- S1 权限：未授权提示「需要短信读取权限才能使用此功能」+「授权」（`RequestPermissionAsync`，成功提示「权限已授予」）；已授权才显示读取区。
- S2 读取范围：开始日期（默认 30 天前）；「读取短信」按钮（读取中有 loading，防重复点击）→ `ReadPaymentSmsAsync(开始日期)`。
- S3 账单归属账本（必选，只列自己的账本，加载失败提示「加载账本失败: …」，创建账本回来后刷新）。
- S4 结果列表：「识别到 N 条支付短信」，每条显示短信正文、「来自: 号码 | 时间: yyyy-MM-dd HH:mm」、「创建账单」。
- S5 读取状态：读取中转圈；读完没有结果「未找到支付类短信」（提示条 + 提示）；读取失败「读取短信失败: …」。
- S6 创建账单：账本必选放最前（「请先选择账单归属的账本」），解析用 `PaymentContentParser`（与短信广播、通知监听共用），解析不出金额 → 手动补全对话框（金额 / 收入开关 / 支付渠道文字输入；校验「请输入有效的金额」），数据来源 = 短信识别，交易时间 = 短信时间，备注 = 短信正文。
- S7 入账：分类（旧代码按名称「其他支出」取，收入账单也会取到它——与账单类型不符，见判断记录）、支付渠道（名称包含，否则名称为「其他」）；匹配不到提示「无法匹配分类或渠道，请手动选择」；成功后从结果里移除该条并提示「账单创建成功」；失败「创建账单失败: …」。
- S8 入口：「我的」页的「短信识别」行（摘要值 = 短信读取权限已授予 / 未开启，13）。

**实现要点 / 发现**

1. **待确认项的时间是设备本地墙上时间，不是 UTC**：通知 / 短信捕获时取的是 `DateTimeOffset.FromUnixTimeMilliseconds(...).LocalDateTime` / `DateTime.Now`，所以页面按原样显示、不换算；入账时由 `BillService` 经 `AppTimeZone.ToUtc` 变成账单的 UTC。E2E 造数 `seed_pending_bill` 因此按墙上时间写（`to_wall_time`），不能套用账单的 `to_db_time`（UTC）。
