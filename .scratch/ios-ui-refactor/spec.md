# iOS 风格 UI 重构 —— 液态玻璃、沉浸式状态栏与 Tab 滑块切换

**Status:** ready-for-agent

**设计稿：** `docs/design/ios-ui-refactor/`（7 张主图板 + `screens/` 下 13 张单屏，v1，已获用户确认）。视觉以设计稿为准，行为以本 spec 为准；两者冲突处见文末「Further Notes」。

**用户已确认的取舍：** 品牌主色保留 #4318FF；本轮只做浅色；趋势分析、年度报告并入「统计」分段；「记一笔」使用自定义数字键盘；Android 与 iOS 共用同一套视觉；账单列表金额支出用常规文字色、收入用绿色；首页 Hero 主指标为「本月支出」；账单搜索纳入范围；下拉刷新只刷新本页数据（不触发同步）；测试以手机视口 E2E 为主 seam。

## Problem Statement

站在记账用户的角度，现在的「记账本」有这些问题：

- **不像一个 iOS 应用**：整体是 Material 风格——纯紫色实心顶栏、3 个 Tab 的 Material 底部导航、卡片阴影。放在 iPhone 上显得突兀，在 Android 上也缺少精致感。
- **状态栏不沉浸**：Android 的状态栏被写死成品牌色（Android 15 起系统强制全屏显示，这条色带还会错位）；iOS 顶部会露出一条与页面不一致的色带；网页端完全没有安全区适配。内容没有真正铺满屏幕。
- **切换 Tab 没有反馈**：底部 Tab 点一下就硬切页面，没有选中态过渡、没有触感，缺少 App Store 那种"玻璃滑块"的质感。
- **信息架构拥挤，常用入口难找**：账单列表是最常用的页面，却藏在「我的」里；「我的」堆了 12 个入口（含账单列表、趋势分析、年度报告、自定义报表）；月度、趋势、年度统计分散在三个页面里来回跳。
- **记一笔步骤多**：整页表单加系统键盘切换，金额、分类、账本、支付渠道散落在滚动页面中，不能一屏完成。
- **页面样式不统一**：18 个路由页面各自用 Material 组件和内联样式拼装（顶栏、容器高度、对话框表单、图标按钮），没有统一的设计语言，也很难整体调整。
- **账单页缺少搜索与全量汇总**：账单越记越多，只能靠日期、账本、分类、支付渠道筛选，没有关键字搜索；页面上的合计也只是"已加载那几页"的合计。

## Solution

站在用户角度，整个 App 改为 iOS 26「液态玻璃」风格（品牌色 #4318FF 保留，仅浅色）：

- **悬浮玻璃 Tab 栏**：首页 / 账单 / 统计 / 我的 四个 Tab，右侧是独立的圆形「记一笔」按钮；Tab 栏只在四个一级页面出现。
- **沉浸式状态栏**：内容铺满到屏幕最顶端，状态栏透明，图标颜色随顶部背景（深色渐变 Hero / 浅色页面）自动切换；刘海、灵动岛、手势条都不遮挡内容；Android 与 iOS 行为一致，网页端不受影响。
- **App Store 式 Tab 切换**：选中项是一颗会滑动的玻璃高光——按下"抬起"，沿水平方向被拉长地滑到目标 Tab，越过后轻微回弹；图标由线框变实心并染品牌色；页面内容交叉淡入；带触感；系统「减弱动态效果」时降级为简单淡入。
- **一级页面按设计稿重做**：首页（渐变 Hero，突出「本月支出」）、账单（大标题 + 搜索 + 分段 + 按日分组 + 左滑操作）、统计（月度 / 趋势 / 年度分段）、我的（资料卡 + 同步行 + 精简的分组入口）。
- **记一笔变成全高 Sheet**：金额大字、自定义数字键盘与高大的「保存」键、5 列分类网格、分组的账本 / 支付渠道 / 时间 / 备注行；账本必选；语音记账只预填表单。
- **二级页面统一模板**：账本、账本成员、预算、待确认账单、短信识别、分类、支付渠道、导入、自定义报表、错误日志、登录，统一使用玻璃导航栏 + 分组列表 + 底部 Sheet + 玻璃 Toast / Alert。
- **无障碍与降级**：减弱动态效果、减弱透明度、大字体、对比度与点击区域，以及低端 Android 上玻璃效果的降级。
- **功能与数据不变**：账本必填、共享账本权限、同步、预算、导入、语音、软删除、时区口径等全部保持原样。新增的只有「账单搜索」「账单汇总按当前筛选做全量统计」和预算页的「日均可用」提示。

## User Stories

**整体导航与结构**

1. 作为记账用户，我希望整个 App 采用统一的 iOS 26 液态玻璃视觉（半透明玻璃、分组圆角卡片、大标题），以便在 iOS 和 Android 上都获得精致、一致的体验。
2. 作为记账用户，我希望底部是悬浮的玻璃 Tab 栏（首页 / 账单 / 统计 / 我的），以便单手就能在四个主要区域之间切换。
3. 作为记账用户，我希望「记一笔」是 Tab 栏右侧独立的圆形按钮，以便在任何一级页面一键开始记账，又不占用 Tab 位置。
4. 作为记账用户，我希望「账单」成为独立的 Tab，以便不必再进「我的」里找最常用的账单列表。
5. 作为记账用户，我希望趋势分析和年度报告并入「统计」页的分段控件，以便在同一处切换月度、趋势、年度，而不是在多个页面之间跳转。
6. 作为记账用户，我希望「我的」只保留资料、同步行和精简分组后的管理入口，以便不再被十几个入口淹没。
7. 作为记账用户，我希望 Tab 栏只在四个一级页面显示，进入二级页面后隐藏并由玻璃返回按钮接管，以便二级页面有更大空间、返回路径清晰。
8. 作为记账用户，我希望再次点按当前所在的 Tab 时回到该页顶部（若处于其二级页面则先回到根页面），以便快速回到起点。
9. 作为记账用户，我希望切走再切回 Tab 时页面保持原来的滚动位置与筛选状态，以便不丢失上下文。
10. 作为记账用户，我希望原来的「趋势分析」「年度报告」入口地址仍然可用并落到统计页对应的分段，以便旧入口、书签或通知跳转不失效。
11. 作为记账用户，我希望未登录时看到的是不带 Tab 栏的登录界面，以便登录前不会误入需要账号的页面。

**沉浸式状态栏与安全区**

12. 作为 Android 用户，我希望状态栏透明、页面内容铺满到屏幕顶端，以便不再看到写死的紫色色带。
13. 作为 iOS 用户，我希望顶部不再露出一条白色空白条，Hero 或页面背景延伸到状态栏之下，以便界面像原生应用。
14. 作为记账用户，我希望状态栏的时间 / 电量图标颜色随页面顶部背景自动切换（深色渐变用浅色图标，浅色页面用深色图标），以便任何页面都清晰可读。
15. 作为记账用户，我希望滚动页面、Hero 滚出屏幕后，状态栏图标颜色平滑过渡切换，以便不会出现图标与背景同色的瞬间。
16. 作为记账用户，我希望内容不被刘海、灵动岛、状态栏或底部手势条遮挡，以便所有按钮都点得到。
17. 作为 Android 15 及以上系统的用户（系统强制全屏显示），我希望布局与旧版本系统表现一致，以便升级系统后界面不错位。
18. 作为记账用户，我希望弹出系统键盘或屏幕尺寸、方向变化导致安全区变化时，页面边距随之更新，以便底部栏和输入框不被遮挡。
19. 作为在浏览器里使用网页端的用户，我希望没有原生安全区时布局依然正常（边距为 0），以便网页端不受影响。

**Tab 切换效果**

20. 作为记账用户，我希望按下 Tab 时选中项的玻璃高光"抬起"（略放大、投影加深），以便获得即时的触感反馈。
21. 作为记账用户，我希望玻璃高光像 App Store 那样沿水平方向滑向目标 Tab，移动时被拉长、越过目标后轻微回弹，以便切换有物理质感。
22. 作为记账用户，我希望被选中的 Tab 图标由线框变成实心并染上品牌色，以便一眼看出当前位置。
23. 作为记账用户，我希望切换时页面内容短暂交叉淡入，而不是硬切，以便过渡自然又不拖慢操作。
24. 作为 iOS / Android 用户，我希望切换 Tab 时有轻微的触感反馈，以便确认点按已生效。
25. 作为开启系统「减弱动态效果」的用户，我希望切换只有简短淡入、没有拉伸与弹簧动画，以便不引起不适。
26. 作为记账用户，我希望快速连续点按多个 Tab 时，高光与页面最终停在最后点按的 Tab 上，不卡住也不错位，以便快速操作依然可靠。
27. 作为记账用户，我希望向下滚动列表时 Tab 栏收缩成当前页胶囊、向上滚动或点按时展开，「记一笔」按钮始终可见，以便给内容让出空间又不影响记账。

**首页**

28. 作为记账用户，我希望首页顶部是渐变 Hero，把「本月支出」作为最大的数字，收入和结余是两个小卡，以便一眼看到本月财务概况。
29. 作为记账用户，我希望 Hero 右上角有带角标的通知入口通向待确认账单，以便不错过自动识别到的账单。
30. 作为记账用户，我希望存在待确认账单时首页出现一条横幅（笔数与来源提示），点按进入待确认账单，没有时不占位，以便及时处理。
31. 作为记账用户，我希望首页「本月预算」展示总预算和重点分类预算的进度条，用正常 / 接近上限（≥80%）/ 超支三种状态色，以便知道哪里快超支。
32. 作为记账用户，我希望首页「最近账单」展示最近几笔账单（分类图标、备注、支付渠道 · 账本、金额、时间），并可点「全部」进入账单 Tab，以便快速回看。
33. 作为记账用户，我希望首页不再有「快捷操作」宫格，因为 Tab 栏和记一笔已覆盖其入口，以便页面更清爽。
34. 作为记账用户，我希望四个一级 Tab（首页 / 账单 / 统计 / 我的）都支持下拉刷新（只刷新本页数据），以便数据变化后更新；云端同步仍只在「我的」里手动触发。**（验收后修订：原文写的是「首页和账单页……并保留手动刷新能力」，实现时曾在四个 Tab 的导航栏各放一枚刷新按钮作为手势的等价入口——设计稿本来没有画；用户拍板撤掉，下拉是唯一的刷新入口，导航栏不放刷新按钮。代价：桌面浏览器 / 辅助技术没有应用内的按钮入口，可用浏览器自带的刷新。）**
35. 作为刚注册、还没有账本或账单的新用户，我希望首页和账单页给出清晰的空状态与引导（先创建账本，再记第一笔），以便知道下一步做什么。

**账单 Tab**

36. 作为记账用户，我希望账单页有大标题，滚动后折叠成居中的小标题，以便获得 iOS 式导航体验。
37. 作为记账用户，我希望账单按日分组，每组头显示日期、星期以及当日的收支合计，以便按天对账。
38. 作为记账用户，我希望顶部汇总卡显示当前筛选条件下全部账单的支出、收入与笔数（不只是已加载的那几页），以便数字可信。
39. 作为记账用户，我希望用「全部 / 支出 / 收入」分段控件快速切换，以便快速聚焦。
40. 作为记账用户，我希望有搜索框可按备注、分类名称或金额搜索账单，以便快速找到某一笔账单。
41. 作为记账用户，我希望当前生效的筛选条件以芯片形式展示在列表上方（账本、月份、分类等），点按可调整，以便随时清楚自己在看什么。
42. 作为记账用户，我希望在筛选面板里按时间（今天 / 本周 / 本月 / 本年 / 自定义）、账本（含「未归属账本」）、分类、支付渠道筛选，可一键重置，确认按钮显示符合条件的账单笔数，以便精确查找。
43. 作为记账用户，我希望左滑账单行出现「编辑 / 删除」，点按行进入编辑，以便比小图标按钮更顺手。
44. 作为记账用户，我希望删除账单前有玻璃确认提示，删除为软删除并随同步传播，以便避免误删。
45. 作为记账用户，我希望有批量选择模式，可把所选账单批量「归属账本」，以便补齐历史上没有账本的账单。
46. 作为共享账本的只读成员，我希望没有写权限的账单不提供编辑 / 删除入口，或给出明确的无权操作提示，以便清楚自己的权限（沿用现有权限规则）。
47. 作为记账用户，我希望历史上没有账本的账单继续正常展示并标注「未归属账本」，以便知道它们还需要补账本。
48. 作为记账用户，我希望账单很多时仍可「加载更多」且滚动流畅，以便大量账单也能顺畅使用。

**统计 Tab**

49. 作为记账用户，我希望统计页顶部有「月度 / 趋势 / 年度」分段，一键切换，切换时保持当前账本筛选，以便在不同维度间比较。
50. 作为记账用户，我希望月份用胶囊切换器（上一月 / 下一月）并可选择账本，以便快速换月、换账本。
51. 作为记账用户，我希望用一张 KPI 卡同时展示支出、收入、结余，以便少占空间又一目了然。
52. 作为记账用户，我希望支出构成用圆环加分类图例与占比展示，并可切换看支出或收入，以便了解钱花在哪里。
53. 作为记账用户，我希望分类排行、支出日历、累计曲线等既有图表沿用原有数据口径，只统一成玻璃卡片外观，以便数字不变、观感一致。
54. 作为记账用户，我希望「自定义报表」入口放在统计页右上角，以便需要时一步进入。
55. 作为记账用户，我希望统计里「未归属账本」的账单仍被单独归类，以便口径与以前一致。
56. 作为记账用户，我希望趋势与年度分段保留原有能力（例如趋势的时间维度、年度的同比），以便合并后不丢失功能。

**我的 Tab**

57. 作为记账用户，我希望顶部资料卡显示脱敏手机号和注册时间，以便确认当前登录的账号。
58. 作为记账用户，我希望「云端同步」行显示同步状态（待同步条数等）并带「立即同步」按钮，以便随时手动同步。
59. 作为记账用户，我希望入口按「记账管理 / 自动记账 / 其他」分组展示（账本、预算、分类、支付渠道；待确认账单（带角标）、短信识别、数据导入；错误日志等），以便找得到。
60. 作为记账用户，我希望列表行右侧显示摘要值（例如账本个数、预算项数、短信识别开关状态），以便不进入页面也能看到概况。
61. 作为记账用户，我希望退出登录依然在「我的」里，并有确认提示，以便不会误触退出。

**记一笔**

62. 作为记账用户，我希望点「记一笔」圆钮后从底部升起一个全高 Sheet、背景页面轻微缩小，以便不离开当前页面上下文。
63. 作为记账用户，我希望金额以超大字号显示并自带光标，打开即可直接输入，以便最快记一笔。
64. 作为记账用户，我希望用自定义数字键盘输入金额（0–9、小数点、00、退格），最多两位小数，上限 99,999,999.99，长按退格清空，以便不唤起系统键盘、一屏完成。
65. 作为记账用户，我希望键盘右侧有高大的「保存」键，没选账本时置灰，以便一键保存且不会漏填。
66. 作为记账用户，我希望用「支出 / 收入」分段切换账单类型，切换后分类网格与金额颜色同步变化，以便不会选错类型。
67. 作为记账用户，我希望分类以 5 列网格展示（支出 10 个 / 收入 5 个，外加「新建分类」），超过两行可左右翻页并有分页点，以便一眼选择。
68. 作为记账用户，我希望点网格里的「新建分类」直接弹出新建分类面板，保存后自动选中新分类，以便不用离开记一笔。
69. 作为记账用户，我希望账本是必选项：未选时「保存」置灰并提示，点按置灰的「保存」会让账本行抖动并弹出账本菜单，以便遵守账本必填规则。
70. 作为记账用户，我希望账本菜单列出我自己的账本与我可以记账的共享账本（标注「共享」），并提供「新建账本…」，以便不离开记一笔就能处理账本。
71. 作为记账用户，我希望支付渠道、时间、备注以分组行呈现，点按弹出选择菜单、时间选择器或输入框，以便操作集中。
72. 作为记账用户，我希望时间按应用时区显示与输入、与账单列表口径一致，以便不会出现跨天错位。
73. 作为记账用户，我希望默认选中的分类、支付渠道、账本沿用我设置的「默认」项（没有则取第一项），以便常用场景一键保存。
74. 作为记账用户，我希望保存成功后 Sheet 收起并出现「已保存到〈账本名〉」的玻璃 Toast，首页、账单、统计随之刷新，以便确认结果。

## Implementation Decisions

**架构与范围**

- 本次重构只改展示层与宿主平台壳：不改变实体、数据库迁移、REST 接口、同步策略、权限语义、时区口径、预算规则与导入解析。数据层唯一新增是两项只读查询：账单关键字搜索，以及按当前筛选条件做全量统计的账单汇总。
- 保留 MASA Blazor 作为基础组件库（主题、表单、图表容器等）与 PageStack 的路由 / Tab 保活机制；在其上新增一层「设计令牌 + 复用组件」，放在 Web 共享库内，同时被 MAUI App 与 Web.Server 使用。
- **与 ADR 0001 冲突（风格部分）**：ADR 0001 写的是「UI 库：MASA Blazor（Material Design 风格）」。库选型不变，视觉语言改为 iOS 液态玻璃。需要新增 ADR 0007 记录方向与取舍，并在 ADR 0001 中标注"风格描述被 ADR 0007 取代"，不得悄悄改写。
- 迁移策略采用"先并存、再逐页替换、最后清理"（expand–contract）：新组件与旧样式在迁移期共存，页面逐个迁移，全部迁完后统一移除旧的紫色实心顶栏、旧底部导航与遗留内联样式。每个 ticket 完成时 App 必须可构建、可运行，既有 E2E 与单元测试全部通过。
- Android 与 iOS 共用同一套 Web 视觉层，不做分平台样式分支；平台差异只通过原生能力抽象（安全区、状态栏样式、触感）表达。

**设计令牌**

- 以 CSS 自定义属性提供（颜色、字体、字号层级、圆角、间距、材质、动效参数），Web.Server 与 MAUI 两个宿主页面加载同一份；MASA 主题的 primary 与令牌的品牌色保持同步。数值以设计稿「06 设计规范」为准，关键值如下：
  - 品牌色 #4318FF，品牌渐变 #7A45FF → #4318FF；页面底色 #F2F2F7；卡片白色。
  - 玻璃材质：浅色玻璃 = 白色约 58% 不透明 + 背景模糊 22px + 饱和度 200% + 内描边 / 高光；Hero 之上的深色玻璃 = 白色约 17% + 模糊 20px。每屏同时叠加的玻璃层不超过 3 层。
  - 圆角：分组卡 26、Sheet 顶部 40、Hero 底部 40、输入框 18、图标块 11–13；悬浮 Tab 栏高 62、左右边距 16、下沿离屏幕底边 21（iPhone 上压住 Home 指示条所在的安全区，不再叠加安全区——量设计稿 01 成品图得出，见 ADR 0007 §29；键盘 / 三键导航栏等实心占用才再整个避开）；玻璃圆形导航按钮 44。
  - 字体：iOS 用系统字体（SF / 苹方），Android 用 Roboto / Noto Sans SC；金额与数字使用等宽数字（tabular-nums）；大标题 34 / 41 粗体；金额大字 56。
- 语义色：收入绿、支出红（仅用于汇总卡片、超支状态与危险操作）、预算状态（正常 / ≥80% 橙 / 超支红）。
- 金额颜色规则：账单列表（含首页「最近账单」）里，支出用常规文字色并带负号，收入用绿色并带正号。

**复用组件（放在 Web 共享库）**

- 玻璃按钮（圆形 / 胶囊 / 文字）、悬浮玻璃 Tab 栏（含高光滑块、记一笔圆钮、收缩胶囊态）、大标题页（大标题折叠为居中小标题 + 右侧玻璃按钮）、玻璃导航栏（二级页：返回 + 内联标题 + 右侧操作）、分组圆角列表与单元格（图标块、标题 / 副标题、右值、箭头、徽标、左滑操作）、分段控件、筛选芯片、底部 Sheet（半屏 / 全高；背景缩放）、玻璃 Toast / Alert / 操作菜单、金额展示（整数大字 + 小数小字）、自定义数字键盘、三色进度条与环形进度、账单行、空状态。
- 每个组件在第一个用到它的 ticket 里创建（tracer 方式），后续 ticket 复用；组件只暴露内容插槽与事件，不内嵌业务逻辑。
- 提示反馈：Toast 通过全局样式覆盖统一外观（现有 PopupService 的调用方式不变）；Alert / 操作菜单为新组件，随页面迁移替换原有的 MDialog 确认框与表单对话框。

**壳与导航**

- 四个 Tab 根页面：首页 `/`、账单 `/bills`、统计 `/statistics`、我的 `/profile`；「账单」需要加入 PageStack 的 Tab 规则以便保活。
- Tab 栏仅在这四个根页面显示（由当前路由匹配 Tab 规则决定）；进入二级页面时隐藏，页面自带玻璃导航栏提供返回，沿用 PageStack 的 Push / Pop；登录页（独立布局）不显示 Tab 栏。
- 「记一笔」圆钮在四个 Tab 根页面可见；点按后以 Sheet 呈现。`/add-bill` 与 `/add-bill/{BillId}` 地址继续可用（可直接访问，也可从账单行进入编辑）；关闭或保存后回到来源页，来源页状态不丢失。具体实现（样式化的路由页面或覆盖层组件）由 ticket 决定。
- 旧地址 `/trend`、`/annual-report` 保留并落到 `/statistics` 的对应分段；`/custom-report` 保持独立二级页；其余路由不变。
- 再次点按当前 Tab：滚动到顶部；若处于该 Tab 的二级页面，先回到根页面。
- 网页端宽屏（桌面浏览器）：应用壳限制最大宽度并居中，保持手机比例，Tab 栏与 Sheet 不拉伸错位；不为桌面另做布局。
- 图标继续使用 MDI（成对的线框 / 实心图标）；分类与支付渠道在数据库中保存的是 mdi 图标名，新增图标必须存在于 MDI 7.2.96。

**沉浸式状态栏与安全区**

- 两个宿主统一为"内容铺满全屏"：Android 采用 edge-to-edge（系统栏透明，移除写死的状态栏颜色），MAUI 页面不再由系统自动留出安全区；iOS 页面启用 `viewport-fit=cover` 语义并让 Web 视图铺满屏幕；Web.Server 没有原生安全区（边距为 0）。
- 安全区数值（上 / 下 / 左 / 右）由原生宿主经 Web 共享库中的接口提供；Web 层把它们写成文档根上的 CSS 变量，供所有铺满型表面（Hero、导航栏、Tab 栏、Sheet、登录页）使用。Android WebView 的 `env(safe-area-inset-*)` 不可靠，以原生注入为准；iOS 以 `env()` 作后备；Web.Server 默认全 0。数值需在尺寸、方向、键盘变化时更新。
- 状态栏图标颜色：每个页面（或页面顶部区域）声明自己顶部背景是"深色（需浅色图标）"还是"浅色（需深色图标）"，滚动时可更新（例如首页 Hero 滚出后改为深色图标，过渡约 200ms）。该状态以文档根上的一个可观察属性对外暴露：原生宿主据此切换系统状态栏图标颜色，E2E 据此断言。
- 底部：Tab 栏与需要贴底的 Sheet 使用下安全区；Android 手势导航条区域保持透明。

**Tab 切换效果**

- 高光滑块位置由弹簧动力学驱动（响应约 0.42s、阻尼比约 0.62）；水平拉伸倍数随速度增加，最大约 1.7×，垂直方向压缩不超过 7%；按下时高光放大约 1.08 并加深投影、图标缩至约 0.9（约 120ms）；图标线框 → 实心约 160ms；页面交叉淡入约 180ms（目标页由约 0.985 轻微放大到 1）；点按触感（iOS 轻触反馈、Android 时钟刻度反馈）。
- 「减弱动态效果」：不做弹簧与拉伸，仅约 100ms 淡入；页面保活行为不变。
- 向下滚动超过约 24pt 时 Tab 栏收缩为"当前页胶囊"，向上滚动或点按展开；按下「记一笔」缩放约 0.92，松手后 Sheet 升起。
- 连续点按多个 Tab 时以最后一次为准：动画可被打断，状态不残留。

**一级页面内容决策（沿用设计稿 01 / 02）**

- **首页**：Hero（标题「记账本」、应用时区的日期与星期、带待确认角标的通知入口、「本月支出」大数字、收入 / 结余两个小卡）；待确认横幅（有待确认账单时才出现）；本月预算（总预算 + 重点分类预算，三色状态）；最近账单 +「全部」；无快捷操作宫格；下拉刷新只刷新本页数据。"本月"边界按应用时区，统计区间左闭右开。
- **账单**：大标题 + 右上角筛选 / 批量按钮；搜索框 + 分段（全部 / 支出 / 收入）+ 筛选芯片；汇总卡（支出 / 收入 / 笔数，口径＝当前筛选与搜索下的全部账单）；按日分组，日分组头的合计沿用现有口径（基于已加载账单）；行内左滑「编辑 / 删除」；批量选择与批量「归属账本」、「加载更多」分页、「未归属账本」标注全部沿用；下拉刷新只刷新本页数据。
- **统计**：分段「月度 / 趋势 / 年度」；月度含月份胶囊、账本选择、KPI 卡、支出构成圆环、分类排行、支出日历、累计曲线（沿用现有图表与数据口径，统一为玻璃卡片）；趋势与年度保留现有全部能力；「自定义报表」入口在右上角。
- **我的**：资料卡（脱敏手机号 + 注册时间）、云端同步行（沿用「同步状态」组件的能力，视觉并入顶部）、分组入口（记账管理：账本 / 预算 / 分类 / 支付渠道；自动记账：待确认账单（角标）/ 短信识别 / 数据导入；其他：错误日志）；账单列表、趋势分析、年度报告、自定义报表入口迁出；退出登录保留并带确认。

**记一笔 Sheet**

- 结构：顶部抓手 + ✕ + 标题（新建为「记一笔」，编辑为「编辑账单」）+ 语音麦克风；支出 / 收入分段；金额大字 + 光标；分类网格（5 列；支出 10 项、收入 5 项，外加「新建分类」；超过两行分页）；分组行（账本、支付渠道、时间、备注）；自定义数字键盘（含高大的「保存」键）。
- 金额规则：最多两位小数、上限 99,999,999.99、不允许多个小数点；长按退格清空；零值 / 空值不可保存（沿用现有校验）。金额输入不唤起系统键盘；备注使用系统键盘，聚焦备注时自定义键盘让位且布局不被遮挡。
- 账本必选：账本未选（新建时尚无账本、编辑没有账本的历史账单）时「保存」置灰；点按置灰的保存键 → 账本行抖动并弹出账本菜单。账本菜单 = 自己的账本 + 有写权限的共享账本（标注「共享」），末项「新建账本…」（打开与账本管理共用的新建面板，创建后自动选中）。保存前的写权限与账本必填校验仍由现有服务层统一负责，界面只做前置拦截与提示。
- 默认值：沿用现有"用户默认值"（设为默认的分类 / 支付渠道 / 账本；没有则取第一项）；不引入"最近使用"记忆。
- 时间：显示与输入按应用时区；界面层不得直接调用 `ToUniversalTime()` / `ToLocalTime()`，一律经 `AppTimeZone` 换算；默认当前时间。
- 新建分类：网格末尾「新建分类」打开与分类管理共用的新建分类面板，保存后自动选中。
- 保存流程：沿用现有保存逻辑（含超支提醒检查、账单变更事件通知）；成功后收起 Sheet，Toast「已保存到〈账本名〉」，各页数据刷新。
- 关闭：已输入内容（金额或备注非空）时二次确认。
- 语音：沿用现有语音输入服务（按住说话、实时转写、解析为草稿）；只预填表单、不自动保存，数据来源标记为语音识别（BillSource.Voice）；无语音能力时降级。覆盖层样式见设计稿 04（实时转写高亮、波形、上滑取消）。
- 编辑模式：同一 Sheet，标题「编辑账单」，含「删除」操作（软删除，带确认）；无写权限则不可编辑。

**二级页面模板**

- 玻璃导航栏（返回 + 内联标题 + 右侧操作）+ 分组列表 + 底部 Sheet（新建 / 编辑表单）+ Alert（危险操作确认）+ Toast（结果反馈）；左滑只是快捷方式，每个操作必须有等价的非滑动入口。
- 各页面保留现有全部功能：迁移前先列出该页现有的功能点并写入 ticket 的实现说明，迁移后逐项对照。涉及页面：账本（新建 / 编辑 / 删除 / 设为默认 / 邀请的接受与拒绝 / 成员入口）、账本成员、预算（总预算与分类预算、按账本、新建 / 编辑 / 删除）、待确认账单（权限状态、确认前可修正金额 / 类型 / 支付渠道且账本必选、忽略、全部忽略）、短信识别、分类（自定义新增 / 编辑 / 删除 / 设默认）、支付渠道、导入（微信 / 支付宝 CSV、解析预览、导入到账本（必填）、完成后自动同步一次）、自定义报表、错误日志、登录。
- 预算页新增只读提示「日均可用」＝ 总预算剩余额度 ÷ 本月剩余天数（含今天，按应用时区）；没有总预算或已超支时不显示。
- 待确认账单卡片上的账本芯片用于快速选择账本；「确认入账」必须保留现有确认流程的能力（金额 / 类型 / 支付渠道可修正，账本必选）。是否保留独立的确认面板由 ticket 在满足这些能力的前提下决定。

**平台能力抽象**

- 安全区、状态栏样式、触感三项能力在共享库中定义接口，MAUI 宿主按平台实现；做法与现有的语音、短信、通知读取一致（Android / iOS 条件编译注册，其余平台与 Web.Server 使用空实现）。Web 层只通过这些接口与文档根上的可观察状态交互，不直接依赖原生。

**无障碍与降级**

- 系统「减弱动态效果」：去掉弹簧与拉伸，只保留短淡入。「减弱透明度」：所有玻璃表面（Tab 栏、导航按钮、Sheet 背板）回退为不透明纯色。提供根节点级的单一开关，使原生宿主在判定设备性能不足时也能触发同样的回退。
- 文字与背景对比度 ≥ 4.5:1（玻璃之上的文字需在最不利背景下满足）；可点击区域 ≥ 44×44；正文字号随系统缩放（至少 130%）且布局不溢出；重要状态除颜色外有文字。

**账单搜索与全量汇总（唯一的数据层改动）**

- 账单查询新增可选关键字条件：备注与分类名称做不区分大小写的包含匹配；关键字能解析为数字时，同时匹配金额等于该数值的账单（数值相等，不是文本包含）。与现有筛选条件（时间、账本、分类、支付渠道、类型）取交集；仍遵守软删除与账本可见性（含共享账本）等现有规则；关键字为空时行为与现状完全一致；暂不暴露到 REST 接口。
- 账单汇总查询：给定与列表相同的筛选条件（含关键字），返回支出合计、收入合计与笔数；列表与汇总必须使用同一套条件，汇总不受分页影响。

**文档**

- 新增 ADR 0007（iOS 风格视觉体系，取代 ADR 0001 的风格描述）；最终清理时更新 CLAUDE.md 中与 UI 相关的说明、README 以及 E2E 说明文档。

## Testing Decisions

以下 seam 已与用户确认。

- **什么是好测试**：只验证外部可观察行为——用户在手机视口里能看到、点到、得到什么（导航结果、可见文案、可点性、元素的几何位置关系、持久化后的数据），不断言实现细节（CSS 类名、组件内部状态、DOM 层级）。需要断言没有可见文案的状态（当前激活的 Tab、状态栏图标样式、安全区变量）时，使用文档化的、专供测试的可观察属性，并在实现 ticket 里把它们当作对外契约写明。
- **主 seam（沿用现有）：Playwright E2E**。对 Web.Server 的 `http` 启动配置运行，使用手机尺寸视口（约 390×844）、触摸与高 DPR 模拟。新增共享基座（设备模拟、登录、造账本 / 造账单、控制台与页面错误采集、可选的截图输出供人工对照设计稿），既有三个脚本迁移到基座。覆盖范围：
  - Tab 栏导航与激活态、二级页隐藏 Tab 栏、再次点按回顶、未登录无 Tab 栏；
  - 沉浸式布局（Hero 顶到视口顶端；安全区变量变化时内容与 Tab 栏位移；状态栏样式属性随滚动切换）；
  - Tab 滑块（到达目标位置；移动中出现拉伸；减弱动态效果下无拉伸）；
  - 记一笔完整流程（键盘输入规则、账本必选与置灰保存、保存后在账单页出现、编辑与删除）；
  - 账单页（分组、全量汇总、筛选、搜索、批量归属账本）、统计分段与旧地址兼容；
  - 各二级页的可达性与关键写操作；减弱动态效果 / 减弱透明度模拟。
- **次 seam（沿用现有）：xUnit**，仅用于非界面逻辑：账单关键字搜索语义、汇总查询口径（与列表条件一致、不受分页影响）。先例：账本统计、预算概览、保存账单回归（使用真实 SQLite 迁移）、预算预警、语音解析等测试。
- **不自动化，人工验收**：状态栏图标颜色与沉浸式在真机 / 模拟器上的表现、Android 15 与旧版本对比、iOS 安全区与灵动岛、触感、玻璃模糊的真机性能、iOS 构建（仅 CI 的 macOS 环境能构建）。每个 ticket 的验收标准单列"人工验收"项并对照设计稿；最后的收尾 ticket 做一次全量回归。
- **不新增 seam**：不引入 bUnit，不做像素级视觉回归。
- **既有测试保持绿色**：每个 ticket 完成时，既有 E2E 与 `dotnet test` 必须全部通过，`dotnet build` 零错误。依赖旧文案的断言（首页「本月概览」、按钮「登录/注册」「记一笔」、记账页「选择分类」等）由改动该文案的 ticket 同步更新。
- **E2E 数据不隔离**（Web.Server 共用本机 SQLite）：用例使用带时间戳的唯一名称，只断言自己创建的数据；不用固定 sleep，以状态等待为准。
- 现有 E2E 说明记载 MASA 的下拉选择在无头浏览器里难以自动化；新的自定义选择器（菜单、行、Sheet）必须能被 E2E 稳定操作，从而首次能自动化覆盖"完整保存一笔账单"。

## Out of Scope

- 暗色模式（本轮只做浅色；令牌与状态栏机制要为将来加暗色留出余地，但不实现）。
- 横屏、iPad、折叠屏、桌面宽屏的专属布局（网页端宽屏只保证居中限宽、不错位）；Windows / MacCatalyst 目标；应用图标与启动页。
- 新业务能力：除「账单搜索」「汇总按筛选全量统计」和预算页「日均可用」提示外，不新增功能；不改实体、数据库迁移、REST 接口、同步策略、权限语义、时区口径、预算规则、导入解析。
- 联网后自动同步；下拉刷新触发同步；"最近使用"默认值记忆。
- 图标字体与图表库的离线本地化（MDI 与 ECharts 目前走 CDN，属既有问题）。
- 多语言 / 英文文案；完整的读屏（VoiceOver / TalkBack）适配审计。
- 像素级视觉回归自动化；bUnit 组件测试。
- 把账单搜索暴露到 REST 接口。
- 设计稿里的示例数据与示例文案仅为示意，不要求照搬。

## Further Notes

- **ADR 冲突**：与 ADR 0001 的"Material Design 风格"描述冲突，处理方式见 Implementation Decisions（新增 ADR 0007，ADR 0001 标注被取代）。其余 ADR（0004 共享账本权限、0005 时区口径、0006 同步身份与时间戳）不受影响，实现时必须继续遵守。
- **设计稿与本 spec 不一致处，以本 spec 为准**：(a) 设计稿 04 写"默认选中最近使用"，实际沿用现有的用户默认值；(b) 设计稿 07 写"下拉刷新触发同步"，实际只刷新本页数据；(c) 设计稿 05 的待确认卡片是"一步确认入账"的示意，实际必须保留确认前修正金额 / 类型 / 支付渠道的能力；(d) 设计稿四个 Tab 的导航栏都没有刷新按钮，spec 原要求"保留手动刷新能力"、实现时按 spec 放了刷新按钮，验收后用户拍板以设计稿为准撤掉（用户故事 34 已修订）。
- **工作区冲突风险**：工作区里还有未提交的「账本必填」改动，涉及的页面（记一笔、账单、导入、待确认账单、首页、月度统计等）正是本次重构要改的页面。开工前应先把那批改动提交或合并，否则会产生冲突。
- **主要风险**：(1) 玻璃模糊在低端 Android WebView 上的性能；(2) PageStack 与 Sheet 呈现方式的兼容；(3) Android WebView 的安全区不可靠，必须靠原生注入；(4) MDI 图标与 ECharts 走 CDN，离线启动时图标缺失，重构后 Tab 栏更依赖图标，这个既有问题会更明显，建议另开需求处理；(5) iOS 构建只能在 CI 的 macOS 环境验证，iOS 人工验收需通过 CI 产物在真机或模拟器上确认。
- **迁移期**：新旧样式并存，每个 ticket 都应可独立合并与演示；全部页面迁完后由收尾 ticket 清理旧样式、更新文档并做全量回归（对照设计稿 07 的逐页清单）。
- **术语**：界面文案与代码沿用 CONTEXT.md 的领域词汇（账单、分类、支付渠道、账本、数据来源、同步状态、软删除、预算、账本成员、共享账本），避免使用其「Avoid」列表里的同义词。
- 设计稿中的单屏 PNG 为 2x 透明底，适合直接对照；主图板里的编号圆点与图例说明了每一处设计意图。
