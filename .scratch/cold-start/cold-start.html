01 · 冷启动：同一张画布的接力

系统启动画面 → 品牌加载页 → 首页 / 登录页。全程同一底色，内容一层层长出来；已登录路径里 Logo 的位置始终不动。取代现在的「紫色 .NET 图 → 白屏小字 → 页面一闪」。

iOS 26 · Liquid Glassv1 草案

已登录用户 每天打开记账的路径：四帧接力

首次安装 / 未登录 从加载页分叉：登录页的背景本来就是整屏渐变，渐变层原地交还；Logo 组上浮、白色面板升起

怎么决定去哪

加载页不关心去哪，只负责「盖住」直到最终页面就绪；去向由首屏自己说了算。

  • 现状的那一闪：首页总是先渲染、再判断是否登录，未登录用户会先看到首页骨架，再被 Replace 到 /login。加载页一直盖到最终页面就绪，这一闪发生在它下面，用户看不到。
  • 交接时机：首屏就绪，或到 1.5 s 上限，先到者为准（建议值）。到上限仍未就绪就带着骨架交出，不让人为了看动画多等。

动效编排

只有两种动效语言——幕布（高度 + 圆角）与 Logo 位移。时长与缓动全部取自现有令牌：400 ms = --ft-dur-sheet，180 ms = --ft-dur-page / --ft-dur-fade。

什么时候会看到

只有「进程重新创建」才走完整接力，普通的切回前台不打扰用户。

  • 冷启动（划掉后台、或被系统回收后再打开）：系统启动画面 → 加载页 → 首页，即上面第一行。
  • 热启动（从后台切回）：不显示——应用还在内存里，直接回到离开时的页面。
  • 首次安装 / 已退出登录：同样的接力，只是在第三步分叉到登录页。

同一张画布

启动全程同一底色，每一步只多长出一层内容，而不是换一张图。

只做状态变化

渐变淡入、幕布收拢、面板升起；数据出现不做动画（沿用设计规范 06 的原则）。

全部来自令牌

只新增 1 个令牌 --ft-splash-bg；渐变、玻璃、字号、时长、缓动都沿用 tokens.css。

可降级

减弱动态效果：只做 100 ms 淡入；降低透明度：Logo 方块改为实色。
