落地会改到哪里

设计层面的预估；确认方向后再逐项核对。

  1. 原生资源Resources/Splash/splash.svg 换成新 Logo；FinanceTracker.App.csproj 的 Color / BaseSize 改值
  2. MAUI 宿主页wwwroot/index.html：加载页标记与关键样式内联，放在 #app 之外；MDI 字体 CSS 与 ECharts 改成不阻塞首次绘制（defer / 本地化）
  3. 原生与 WebView 之间MainPage.xaml 的底色由 White 改为启动底色，WebView 出来前不再闪白
  4. 令牌与共享脚本tokens.css 新增 --ft-splash-bg；一小段启动脚本放进 FinanceTracker.Web（两个宿主共用）：首屏就绪信号 → 交接动画 → 移除加载页，以及 12 s 兜底
  5. 页面Index.razor / LoginPage.razor 在首屏就绪时发信号；加载页盖住那一闪，不改变登录判定逻辑
  6. 测试与文档E2E 手机视口加启动与交接断言；Web.Server 宿主同样放加载页；ADR 0007 追加「启动」一节

需要你定的事

下面几项没有标准答案，取决于你想要的观感。

  1. 已登录交接用什么？本稿：幕布收拢，约 400 ms，有一点仪式感。另一种：朴素的 180 ms 交叉淡入——更快更稳，也是「减弱动态效果」下的行为。
  2. 应用图标要不要一起换？现在是蓝色笔记本。不换的话，点开图标 → 紫色启动画面会有一次变色。这不在冷启动范围内，但直接影响观感。
  3. 要不要做「启动失败」兜底？它需要看门狗与「重新加载」的能力，行为要在真机验证。不做的话，卡住时仍只有转圈。
  4. 快启动是否保留渐变淡入？首屏若不到 400 ms 就绪，淡入会被截断。可以接受，也可以走快路径：直接从底色切到渐变。

只有真机能确认的事

这份设计稿是用真实样式表在浏览器里还原的，下面这些它验证不了。

  1. 原生 → WebView 之间会不会闪白iOS、Android 12+、Android ≤ 11 各看一遍；只改 MainPage 底色是否足够。
  2. Android 12+ 的启动图标缩放96 dp 方块在圆形遮罩里实际多大，是否需要调整 BaseSize。
  3. 加载页首帧距点击图标多久CDN 资源不再阻塞后量一次；0.6 s / 1.5 s / 12 s 三个门槛都要按这个分布重定。
  4. 「重新加载」在 BlazorWebView 里的效果重载页面能否让 Blazor 重新启动，还是需要原生层配合。
  5. 中低端 Android 上的帧率幕布的高度 + 圆角动画若掉帧，就退化为交叉淡入（即第 1 项的另一种选择）。

令牌与时长取自 src/FinanceTracker.Web/wwwroot/css/tokens.css；0.6 s / 1.5 s / 12 s 是建议值，不是实测数据；Android 12+ 的图标缩放以真机为准。落地清单是设计层面的预估，确认方向后再逐项核对代码。
