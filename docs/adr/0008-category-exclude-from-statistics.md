# 分类的「不计入统计」开关

## 背景

「存款」这类账单：钱确实从账户里出去了，要记在**支出**里（余额才对得上、账单列表里也得看得到），但它不是"花销"，
不想让它抬高统计里的支出、也不想让它占用预算。需要一种办法让**一部分账单留在账单列表里、却不参与统计**。

备选方案：

| 方案 | 结论 |
|------|------|
| 账单上加一个「不计入统计」标记（每笔单独设） | 否决：记一笔时多一步、容易忘；历史账单要逐笔补；统计口径取决于每笔账单，难以解释 |
| 新增账单类型（转账 / 存款，既不是收入也不是支出） | 否决：动账单类型枚举，牵动导入解析、同步、预算、全部统计与既有数据；「存款」之外还有「还信用卡」「借入」等，类型永远不够用 |
| 统计页上临时"隐藏某个分类"的筛选 | 否决：只影响当前这一页的显示，首页本月概览与预算仍然包含它；每次都得重新选 |
| **分类上加一个「不计入统计」开关** | **采用**：一次设置，处处一致；新建分类时就能顺手打开；符合用户对"存款是一类账"的理解 |

## 决策

`Category` 增加布尔字段 **`ExcludeFromStatistics`**（界面叫「不计入统计」，默认 false = 计入）。
开着开关的分类下的账单**不参与统计、首页本月概览与预算已用金额**；账单列表里仍然照常显示。

术语：界面、代码里统一叫「不计入统计」（`ExcludeFromStatistics`），不要换成「忽略」「屏蔽」「隐藏」。
唯一的例外是统计页底部的提示文案「已忽略 N 笔「不计入统计」的账单…」——沿用用户提出需求时的说法，句子里仍带着正式叫法。

### 范围

| 位置 | 是否受影响 | 说明 |
|------|-----------|------|
| 统计 Tab：月度（合计、分类构成与排行、账本构成、预算执行、支出日历、累计收支）、趋势、年度、自定义报表（含环比 / 同比） | 是 | 都经 `StatisticsService` / `BudgetService` |
| 首页「本月概览」与预算概览 | 是 | 直接调用 `StatisticsService.GetMonthlyStatisticsAsync` / `BudgetService`，与统计页同口径 |
| 预算：总预算、账本预算、分类预算的已用金额，超支提醒 | 是 | `BudgetService`；三种预算一视同仁 |
| 账单 Tab：汇总卡、列表、当日合计 | **否** | 列表就是账单的真实流水，汇总卡与列表对得上；被排除的账单在列表里带「不计入统计」标记 |
| 自定义报表的导出 CSV / 分享摘要 | 随报表 | 用的是同一份统计结果，所以同样不含被排除的账单；导出格式与分享文案本身未改，也不附「已忽略」说明 |

### 口径

规则只写在 `FinanceTracker.Core.Services.StatisticsScope` 一处：账单所属分类是**当前用户自己的**自建分类，且开着开关 → 不计入。

1. **查询时按分类当前的开关判定，不是入库时的快照。** 改开关会让该分类的全部历史账单一并重新计入 / 不再计入——
   用户的意图是"这类账单不算花销"，而不是"从今天起的这类账单"。
2. **只认当前用户自己的分类。** 这是个人偏好：别人的开关不能影响我的统计；预设分类（`UserId = null`）是全局共享数据，不放个人开关（也没有界面入口）。
   统计本来就只算自己记的账单，所以共享账本里其他成员用他们自己的分类记的账单，对我来说不存在"被排除"。
3. **已软删除的自建分类仍按它删除前的开关判定。** 否则"删掉分类"会让它名下残留的账单（比如另一台设备删除后同步过来的）悄悄重新计入统计。
4. **预算一视同仁**：被排除分类的账单不占总预算 / 账本预算；给被排除分类设的分类预算已用恒为 0。
   `GetBudgetAlertAsync` 对被排除分类的账单返回 `null`（它没占用任何预算，没什么可提醒的，否则月初存一笔钱会因为别的支出接近上限而弹出一条无关的超支提醒）。
   新建分类预算时选不到被排除的分类（设了也累计不到）；编辑一笔已存在的、分类后来被开了开关的预算时，选项里仍保留它，并提示「账单不会累计到这笔预算里」。

## 实现要点

- **`StatisticsScope` 是唯一的口径出口**（`ExcludedCategoryIdsAsync` / `ExcludedCategoriesAsync` / `WithoutExcluded` / `IsExcludedAsync`）。
  `StatisticsService` 的每个公开方法、`BudgetService` 的已用金额与提醒都经它取要计入的账单；两处各写一份，迟早有一处漏改，首页与统计页的本月支出就对不上了。
- **陷阱：不能把"被排除的分类"作为子查询拼进账单查询。** 上面第 3 条要对分类表 `IgnoreQueryFilters()`，而 EF Core 的
  `IgnoreQueryFilters()` 是**整条查询**级的开关——拼进去，账单自己的软删除过滤器也跟着失效，已删除的账单会重新算进统计 / 预算
  （既有用例 `LedgerStatisticsTests.已删除的账单不计入统计` 当场抓到过）。做法：先单独查出被排除的分类 Id（只涉及分类表的小查询，得到 `List<Guid>`），
  再 `WithoutExcluded(ids)` 交给账单查询。回归用例见 `StatisticsSoftDeleteTests`。
- **提示数据**：`IStatisticsService.GetExcludedStatisticsAsync(userId, startLocal, endLocalExclusive, ledgerId)` 返回区间内被排除的分类汇总
  （名称、图标、类型、金额、笔数，按金额从大到小）。区间同其他统计一样**左闭右开**；趋势视图的窗口终点含端点，换算时 `end.AddTicks(1)`。
- **REST**：分类接口（`CategoriesController`）收发 `excludeFromStatistics`（创建缺省 false；更新时请求里没带 = 保持原值，不能让老调用方悄悄把开关改回去）；
  `GET /api/statistics/excluded` 对应上面的服务方法（日期含当天，终点取次日零点）。
- **数据库**：`Categories.ExcludeFromStatistics`（`NOT NULL`，默认 false，老数据一律"计入统计"）。PostgreSQL（`FinanceTracker.Infrastructure`）与
  SQLite（`FinanceTracker.Infrastructure.Sqlite`）两套迁移历史各一份 `AddCategoryExcludeFromStatistics`，`ModelSnapshotTests` 守住快照与模型一致。

## 同步

`CategorySyncDto` 携带该字段（`FromEntity` / `ToEntity` / `ApplyTo` / `ContentEquals` 都带上）。分类仍是整条记录后写入优先（见 ADR 0002 / 0006），
没有为这个字段单独做合并。**取舍：** 还没升级的旧客户端推上来的分类 JSON 里没有这个字段，反序列化成 false——如果它在新客户端设了开关之后又编辑了同一个分类
（`UpdatedAt` 更新），开关会被这次后写入覆盖成"计入统计"。这是"整条记录后写入优先"的直接后果，影响面小（只是开关需要重新打开），不值得为它引入字段级合并。
升级后的客户端之间没有这个问题。预设分类不同步、也没有开关，不受影响。

## 界面

- **开关**在新建 / 编辑分类的 Sheet 里（`CategoryFormSheet`，分类管理页与「记一笔」里内联的「新建分类」共用），一行 `ToggleSwitch`，脚注点明范围并举例
  （支出：「存款」「还信用卡」；收入：「借入」「退款」）。点「保存」才落库，不保存关掉不生效；只改名不会改动开关。
- **标记**：分类管理页里开着开关的自定义分类名称下多一行副标题「不计入统计」（`data-excluded="true"`）；账单行（首页最近账单、账单 Tab）在副标题前多一枚小标签
  「不计入统计」，读屏名称以「，不计入统计」结尾。标记只给**分类所有者自己看自己的账单**（预设分类、别人在共享账本里用他自己的分类记的账单不标）。
- **提示**：统计的月度 / 趋势 / 年度 / 自定义报表页面底部各有一行说明（`ExcludedNote`，`role="note"`，区间内没有被排除的账单时整行不存在）：
  「已忽略 3 笔「不计入统计」的账单：存款 -¥1,200.00」；只有一个分类时不重复笔数，多个分类每项带「（N 笔）」，按金额从大到小，最多点名 3 个、更多时补「等 N 个分类」；支出带 `-`、收入带 `+`。
  文案与展示规则都在 `ExcludedFromStatisticsPresentation`（纯函数，单元测试覆盖）。
- **刷新**：统计 / 账单 / 首页都是常驻的 Tab 根页面，在分类页拨开关后它们随二级页面关闭（`NavController.PageClosed`）自动重新读取；记账后随 `BillChanged` 重新读取——不需要新的事件，也不需要下拉刷新。

## 已知限制 / 不做的事

- 没有"单笔账单"级别的例外：想让某一笔不计入，换到一个开着开关的分类下。
- 没有批量操作：开关在分类上，一次设置覆盖该分类下所有账单，不需要批量。
- 预算页对已存在的、分类后来被开了开关的预算不加行内提示（这类预算已用恒为 0，剩余额度不变）；只在编辑那笔预算的表单里说明。
  服务层也不拦「给开着开关的分类新建分类预算」：界面的分类选项里没有这类分类，但 REST 调用方仍能建出来，它的已用同样恒为 0——这是无害的死预算，不值得为它在 `BudgetService` 里加一道会连累「编辑已有预算」的校验。
- 账单 Tab 的汇总卡不排除（见上"范围"）；因此同一个月里首页的「本月支出」与账单 Tab 的「支出」在有被排除账单时会不同——这是刻意的，账单行上的标记就是解释。
