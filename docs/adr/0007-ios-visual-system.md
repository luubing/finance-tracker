# iOS 风格视觉体系

## 背景

ADR 0001 把 UI 描述为「MASA Blazor（Material Design 风格）」。这次 UI 重构要把整体视觉改成 iOS 风格（液态玻璃），
并增加沉浸式状态栏、Tab 滑块切换等 iOS 式交互。**组件库选型不变，视觉语言变了**，所以单独记一条决策，
并在 ADR 0001 里标注「风格描述被本 ADR 取代」。

重构按 24 个 ticket 分批落地，**已全部完成**（收尾清理见 §27）。自动化只覆盖网页层；真机 / 模拟器的人工验收项逐条记在「已知限制」里，没有一项被当作已通过。

## 决策

### 1. 视觉基线

- 整体视觉以 iOS 为参照（液态玻璃材质、大标题、分组卡片、弹簧动效）；Android 与 iOS **共用同一套 Web 视觉层**，
  不做分平台样式分支，平台差异只通过原生能力抽象表达（见第 5 点）。
- 品牌色保持 `#4318FF`；本期只做浅色，不做深色模式。
- MASA Blazor 继续作为基础组件库（主题、表单、图表容器等），`PageStack`（`Masa.Blazor.MobileComponents`）继续负责
  二级页面压栈与 Tab 根页面保活。视觉由下面的「令牌 + 复用组件」覆盖，不再追求 Material 外观。

### 2. 设计令牌是样式的唯一来源

- 颜色、字号、圆角、间距、玻璃材质、动效参数全部以 CSS 自定义属性（`--ft-*`）定义在
  `src/FinanceTracker.Web/wwwroot/css/tokens.css`，**两个宿主（MAUI `index.html`、Web.Server `_Layout.cshtml`）加载同一份**，
  加载顺序固定为 MASA 样式 → `tokens.css` → `app.css` → `ui.css`。
- 页面与组件只引用令牌，不再硬编码颜色、圆角、字号，也不写静态内联样式；迁移期遗留的内联样式与兼容层已在 24 号清理（§27），
  `VisualSystemGuardTests` 扫描源码守住这条。
- 品牌色在三处出现，必须一致：`--ft-brand`、C# `DesignTokens.BrandColor`、MASA 主题 primary
  （`UseFinanceTrackerDesign()` 统一设置）。`DesignTokensTests` 守住这一致性，也守住两个宿主页面的加载顺序。
- 数值以设计稿 06 为准；改动令牌即改动设计规范，需同步更新设计文档。

### 3. 材质：玻璃只来自令牌

- 玻璃表面一律使用 `--ft-glass-*`（浅色玻璃）/ `--ft-glass-dark-*`（Hero 之上的深色玻璃）令牌，不在组件里手写
  `backdrop-filter` / 半透明背景。这样「降低透明度」的回退只需要在令牌层改一处。
- **每屏同时叠加的玻璃层不超过 3 层**：`backdrop-filter` 在低端 Android WebView 上是性能热点。
- 内容区背景是纯色（`--ft-bg`），玻璃只用于 Tab 栏、浮层顶栏、Sheet 等「悬浮」元素。

### 4. 应用壳：四个 Tab + 独立「记一笔」圆钮

- 一级页面四个 Tab：首页 `/`、账单 `/bills`、统计 `/statistics`、我的 `/profile`；右侧是独立的圆形「记一笔」按钮。
  Tab 与路径的对应关系集中在 `FinanceTracker.Web.Shell.TabNavigation`，Tab 栏（`GlassTabBar`）与页面栈规则都取自它。
- Tab 栏几何：高 62、左右边距 16、距底 `21 + 底部安全区`，与「记一笔」圆钮（62）间距 10；宽屏（≥ 521px）应用壳限制
  最大宽度 480 并居中。
- **Tab 栏只在四个一级页面显示**；二级页面（压栈的页面）与登录页不显示。登录页不渲染 Tab 栏，二级页面只隐藏
  （`visibility: hidden` + `inert`），保留 DOM 以便返回时滑回。
- **切换 Tab 只用 `NavigationManager.NavigateTo(根路径)`，不得 `Push` 一个 Tab 根路径**：压栈会把一个常驻的根页面
  重复挂成二级页面，造成状态分裂。`TabNavigationTests` 会扫描 Razor 页面守住这条约定；需要「回到某 Tab 的根」
  时用 `PageStackNavController.GoBackToTab(根路径)`。
- Tab 根页面由页面栈常驻（切走只隐藏不销毁）：切走再切回保留滚动位置与筛选状态。
- 再次点按当前 Tab：已在根页面则滚动回到顶部；停在该 Tab 的二级页面则先回到根页面。
- 一级页面内容区底部预留 `--ft-tabbar-clearance`（距底 + Tab 栏高度 + 安全区 + 24），最后一项内容可以完整滚出 Tab 栏之上。
- 宽屏下应用壳加 `transform: translateZ(0)`：这让 `position: fixed` 的后代（页面栈的页面、Tab 栏、弹层）
  以壳为包含块，因此都收在壳内；并用 `overflow-x: clip` 裁掉压栈时向左错开的下层页面。

### 5. 原生能力经抽象接入

- 安全区（刘海 / 灵动岛 / 手势条 / 键盘）通过 `--ft-safe-top|right|bottom|left` 变量暴露给 Web 层；来源优先级：
  html 内联覆盖 → 原生注入（`--ft-native-safe-*`）→ `env(safe-area-inset-*)` → `0px`。页面一律读这四个变量，
  不直接用 `env()`。
- 状态栏图标明暗由 `immersive.js` 对屏幕顶部采样得出，写到 `<html data-statusbar-icons="light|dark">`；背景是渐变 / 图片时
  页面用 `data-statusbar-bg="dark|light"` 显式声明。
- 触感反馈等原生能力同样经 Web 共享库里的接口抽象，由 MAUI 宿主实现、Web.Server 宿主提供空实现，
  所以网页端与 E2E 不受影响。`IHapticFeedbackService.SelectionChanged()`：iOS 用 `UIImpactFeedbackGenerator(.light)`，
  Android 用视图级 `PerformHapticFeedback(CLOCK_TICK)`（不需要震动权限）。

### 6. Tab 滑块动效：弹簧在脚本里积分，状态不进 Blazor 的渲染树

- **弹簧由 `tabBar.js` 数值积分**（response / damping 取自令牌 `--ft-spring-*`），不用 CSS 缓动曲线近似：
  弹簧被打断时要保留当前速度继续运动，CSS transition 做不到；水平拉伸倍数 = `1 + 0.7 × 当前速度 / 本次移动的峰值速度`
  （最大 1.7×，垂直压缩 ≤ 7%），也必须读到实时速度。
- **点按乐观响应**：点按时脚本在客户端立刻开始动画，不等 Blazor Server 往返；Blazor 每次渲染后调用 `sync(index)` 告知真实序号。
  与最后一次点按一致才算确认，更早那次点按的迟到确认被忽略（否则连点时高光会折返）；2.5s 仍没确认（跳转没发生）回到真实 Tab。
- **脚本接管后，高光位置的唯一来源是内联 `translate`**（静止时保留，只清掉 `scale`）。`--ft-tab-x` 只是预渲染 / 脚本加载失败时的回退：
  代码触发的跳转是「渲染先到、`sync` 后到」，如果静止时回退到 CSS 位置，高光会先瞬移到新位置再被拉回旧位置重新滑动。
- **脚本写的状态（`data-collapsed` / `data-pressed` / `data-pressing`、高光的 `data-state` 与内联 `translate` / `scale`）一律不由 Razor 渲染**，
  Blazor 的差量更新不会冲掉它们。这些属性是文档化的可观察属性（`tests/e2e/README.md`）。
- 页面交叉淡入是纯 CSS 动画（`.p-page-container__item:not(.d-none)`，`display` 由 none 变可见时自动重播）；
  它让根页面在 180ms 内成为 `transform` 的包含块，期间放在根页面里的 `position: fixed` 元素会跟着错位——需要钉在屏幕上的元素
  放在页面栈之外或用 `sticky`。
- **减弱动态效果**（`prefers-reduced-motion`）：不做弹簧 / 拉伸 / 抬起，高光直接就位并做约 100ms 淡入，页面只做约 100ms 淡入；
  收缩 / 展开功能保留，只是没有宽度动画。
- 向下滚动超过 24（`--ft-collapse-threshold`）收缩成「当前页胶囊」，向上滚动 / 点按胶囊 / 切换 Tab / 滚回顶部展开；
  「记一笔」圆钮始终靠右。收缩态下四个 Tab 是 `inert`——脚本滚动页面后要点 Tab，必须先展开（E2E 的 `open_tab` 已内置）。

### 7. 二级页面模板、弹层与 Toast（05 号 ticket 起）

- **二级页面 = 页面栈的全屏对话框 + `SecondaryPage` 组件**：玻璃导航栏（返回 + 居中 h1 标题 + 右上角操作）挂在 `PStackPageBar` 的
  `BarContent` 里，整体替换页面栈默认的紫色顶栏；顶栏背景是页面背景色 + 底部渐隐（不是玻璃，不占玻璃层名额），高度 `44 + --ft-safe-top`。
  页面栈自带的转场与左边缘右滑返回照常工作；背景浅色，状态栏图标由 `immersive.js` 自动取深色，页面无需声明。
  顶栏之下内容区的上内边距（`.m-page-stack-item__content { padding-top: 顶栏高度 + 状态栏安全区 }`）是 `ui.css`「二级页面」一节里的正式规则——24 号把它从 `app.css` 的迁移期兼容层移了过来，兼容层随后整体删除。
- **MASA 样式的特异性**：顶栏背景由 `.m-app-bar.m-toolbar.m-sheet`（三个类）设置，覆盖它的规则至少要同样的特异性
  （`.m-app-bar.m-toolbar.m-page-stack-item__bar.ft-subbar`），仅写 `.ft-subbar` 会静默失效。
- **弹层（Sheet / Alert / 操作菜单）共用 `OverlayBase`**：显示状态由 Blazor 持有（`Visible` / `VisibleChanged`），开合动画是纯 CSS；
  关闭先播放退出动画再卸载（Sheet / 操作菜单 260ms，Alert 180ms，时长与 `ui.css` 一致），卸载后触发 `OnClosed`，页面在那里清理表单状态。
  容器是 `position: fixed` 铺满应用壳，放在二级页里时盖住整页（含顶栏）。层级固定：Tab 栏 100 < Sheet 120 < Alert / 操作菜单 130 < Toast 1100。
  打开后焦点交给弹层容器（让 Esc 可用），**不自动聚焦输入框**，避免移动端一打开就弹出键盘。
  Alert 点遮罩**不关闭**（避免误触放弃本应明确选择的决定），Esc 等同取消；Sheet 点遮罩 / 关闭按钮 / Esc / 向下拖拽把手或标题栏均可收起，
  操作菜单点遮罩 / 取消 / Esc 收起；保存中（`Dismissible=false`）Sheet 的所有收起方式都不响应。
- **手势层是文档级事件委托，不进 Blazor 渲染树**：左滑行与 Sheet 拖拽收起由 `wwwroot/js/ui.js` 统一接管，组件只渲染标记；
  全局只装一份监听（`UiRuntime` 在应用根部安装），行再多、重绘后也自动生效，没有「每行一次 JS 互操作」。
  脚本只写自己拥有的状态（`data-open` / `data-dragging` / `data-dragged`、内联 `transform`、托盘的 `inert`），Blazor 的差量更新冲不掉它们。
  松手判定看「当前位置 + 按松手速度再滑行 120ms 后的落点」；滑动结束后 350ms 内行内 click 被吞掉（防止松手误触单元格）；行已展开时点按内容只收起。
- **每个左滑操作都必须有不依赖滑动的等价入口**——这是调用方的责任，组件不替它决定（账本页：点按整行进入编辑 Sheet，里面有设为默认 / 共享 / 删除）。
- **Toast 不改调用方式**：仍是 `PopupService.EnqueueSnackbarAsync`，用全局样式把 MASA 的排队消息条改成玻璃胶囊；
  MASA 容器带内联 `bottom: 0` 与 `max-width`、颜色类带 `!important`，覆盖规则同样需要 `!important`。位置恒为 Tab 栏之上（二级页面上显得略高，但全局一致）。
- **降级**：`prefers-reduced-motion` 下 Sheet / Alert / 操作菜单入场改为淡入，左滑过渡近似瞬时；「降低透明度」「减弱动态效果」的整体回退在 23 号 ticket 统一收口，见 §26。

### 8. 迁移策略：先并存、再逐页替换、最后清理

新组件与旧样式（旧页面的紫色实心顶栏、`app.css` 里的「迁移期兼容层」）在迁移期共存，页面逐个迁移；
全部迁完后统一移除兼容层与遗留内联样式。每一步 App 都可构建、可运行，既有 E2E 与单元测试保持通过。
**迁移已完成**：兼容层、遗留的内联样式、不再有引用的组件与 E2E 里对旧页面容器的兜底都已在 24 号清理（§27）。

### 9. 一级页面通用件与首页（07 号 ticket 起）

- **Hero 上的小卡 / 圆按钮用扁平半透明：只取 `--ft-glass-dark-bg` 与 `--ft-glass-dark-shadow`，不用 `--ft-glass-dark-filter`（不叠 `backdrop-filter`）**：
  首页同屏已有 Tab 栏的玻璃层，Hero 上再叠 3 块 `backdrop-filter`（通知入口、两张小卡）会越过「每屏 ≤ 3 层」的预算；
  深紫渐变之上半透明白底与真模糊的观感差别很小。E2E 里「首页同屏玻璃层数 ≤ 3」守住这条。
- **金额统一经 `AmountDisplay`**：币种符号 + 整数（含千分位）+ 小数，格式在 `MoneyPresentation`（千分位 `,`、小数点 `.` 固定，
  不随设备区域设置变化）。读屏当作一个文本（`role="img"` + `aria-label`），`data-amount` 是两位小数的原始值（E2E 用它断言）。
- **状态不只靠颜色**：预算行有「剩余 / 仅剩 / 超支 / 已用完」文字，进度条 `role="progressbar"` + 带状态的 `aria-valuetext`；
  使用百分比**向下取整**，保证「≥ 80% 预警 / ≥ 100% 超支」与显示值严格对应（79.6% 显示 79% 仍是「正常」）。
- **文字用色另有一档加深值**：`--ft-expense` / `--ft-income` 是图形与汇总的用色（白底对比度约 4.2:1 / 3.2:1，达不到 AA），
  小号文字用 `--ft-danger-text` / `--ft-income-text` / `--ft-warning-text`（≥ 4.5:1）；`DesignTokensTests` 计算并守住对比度。
  全局对比度审计（含 `--ft-label-2`）已在 23 号 ticket 完成，见 §26。
- **下拉刷新（`PullToRefresh` + `pullRefresh.js`）与 Tab 滑块同一思路**：手势在脚本里接管、状态（`data-state`、`--ft-ptr-offset`、
  `--ft-ptr-progress`）写在 Blazor 不渲染的属性上，Blazor 重绘冲不掉；组件只通知页面「松手过了阈值」，页面决定刷新什么。
  **下拉刷新只重读本页数据，不触发云端同步**（设计稿 07 写的是「触发同步」，以 spec 为准）。
  **下拉是四个 Tab（首页 / 账单 / 统计 / 我的）唯一的刷新入口，导航栏 / Hero 里不放刷新按钮**：设计稿本来就没有画；实现时曾按 spec 原文（「保留手动刷新能力」）
  为桌面浏览器 / 辅助技术放过一枚等价的刷新按钮，验收后用户拍板撤掉（spec 用户故事 34 已修订）。代价是没有触摸的环境（桌面浏览器、辅助技术）没有应用内的按钮入口，
  可用浏览器自带的刷新；真机是触摸，不受影响。**新增依赖 `PullToRefresh` 的页面不要再补按钮入口，除非先改这条决定**；E2E 以「页面里没有按钮形式的刷新入口」守住。
  滚动容器用 `data-scroll-root` 标记（`tabBar.js` 的收缩与 E2E 的 `scroll_root_*` 也认它）。
- **首页的几块数据顺序读取**：它们共用同一个 `DbContext`（MAUI 里 Scoped 等同于单例，Blazor Server 里是同一条电路），EF Core 不允许并行查询，
  所以用 `SemaphoreSlim` 闸门串行化「下拉刷新 / 账单变更 / 二级页面关闭」几条入口。`PendingBillService` 每次调用自己新建上下文
  （`IDbContextFactory`），读它是安全的；Web.Server 因此也注册真实实现（原为空实现），横幅与角标才能被 E2E 验收。
- **页面栈的退出动画期间会吞掉新的导航**：浏览器回退后 URL 与 Tab 栏立即恢复，二级页面要约 300ms 才从 DOM 移除，这期间再点按入口
  事件到了但不跳转。只影响 E2E 的快速连点（`wait_secondary_pages_closed` 等它），真人手速碰不到。

### 10. 大标题页、分段控件与账单 Tab（08 号 ticket 起）

- **大标题页 `LargeTitlePage`**：根节点就是 Tab 根页面的滚动容器（`.ft-tabpage`，`data-scroll-root`）；导航栏 `header.ft-lnav`
  `position: sticky; top: 0`（高 = `--ft-safe-top` + 44），大标题是页面里唯一的 `h1`。折叠状态（大标题底边滚到导航栏底边之上）
  由 `ui.js` 的滚动监听写在根节点的 `data-title-collapsed`——Blazor 不渲染这个属性，重绘冲不掉。折叠后导航栏填页面背景色，
  **不是玻璃**，不占玻璃层名额；导航栏里的玻璃圆按钮各自占一层，页面最多放两个，加上 Tab 栏正好 3 层
  （账单页：Tab 栏 + 筛选 + 多选，E2E 数着 `backdrop-filter` 守住）。
  Tab 根页面切走只隐藏不销毁，Chromium 会保留隐藏元素的 `scrollTop`，所以切走再切回时折叠状态与滚动位置一致；
  WKWebView / Android WebView 是否同样保留，列入人工验收。
- **分段控件 `SegmentedControl`**：滑块位置只由 `--ft-seg-index` / `--ft-seg-count` 两个样式变量决定，位移走 CSS 过渡，选中值由调用方持有。
  `.ft-seg` 的水平内边距等于滑块的内边距，每段宽度 = 滑块宽度，文字中心与滑块中心对齐（只有垂直方向不留内边距，点击区域是整条轨道的高度 44）。
  **Razor 陷阱**：`string?` 参数写 `Value="_segment"` 是字符串字面量，必须写 `Value="@_segment"`——写错时点击照样走 `ValueChanged`，
  肉眼看不出，只有 E2E 对 `aria-pressed` / `data-value` 的断言抓得到。
- **页面读库的单车道 `PageDataGate`**：Tab 根页面常驻（页面栈保活），一次账单变更会让首页 / 账单页 / 统计页同时「重新加载本页数据」，
  而它们共用同一个 Scoped `DbContext`，EF Core 不允许并行查询。所有「查库刷新」的入口（初次加载、下拉刷新、账单变更事件、二级页面关闭……）
  都经过闸门串行执行；闸门**不可重入**（里面不能再调闸门），写操作不经过它。
- **账单查询、总数与汇总共用一份条件**：`BillFilter`（时间范围 / 分类 / 支付渠道 / 账本 / 未归属账本 / 类型；10 号会加关键字）→ `BillService` 里唯一的
  `BuildBillQueryAsync`，列表、总数、汇总都从它取「符合条件的账单」，口径一致由结构保证而不是两处各写一遍再人工对齐。汇总在库里按类型分组求和
  （至多读回两行），不受分页影响。**两种口径刻意并存**：汇总卡是全量口径，按日分组头的合计仍基于已加载账单（沿用旧口径，spec 保留的差异）。
- **左滑「删除」的等价入口是点按行进入编辑页**（里面有删除）；删除前用 `GlassAlert` 确认。Alert 关闭有 180ms 退出动画，期间遮罩仍盖着页面、
  会吞掉触摸——E2E 在确认 / 取消后要等 `alert-host` 消失再继续操作页面。没有写权限的行（共享账本里别人记的账单，`CanModify = false`）
  不渲染滑动操作，点按只给「这笔账单由账本里的其他成员记录，只有记录它的人可以修改或删除」的本地提示（不发请求、不会登出）。

### 11. 筛选 Sheet、条件条与多选操作栏（09 号 ticket 起）

- **条件条 `BillFilterChip`**：账单 Tab 在分段控件与汇总卡之间放一排横向滑动、不换行的标签，每个筛选维度（时间 / 账本 / 分类 / 支付渠道）一颗，
  始终显示四颗，已设置条件的排在前面（`OrderByDescending(Has)` 是稳定排序，各自保持原来的相对顺序）。没设置：文字是维度名 + 下拉箭头，点按 = 打开筛选 Sheet 并滚到这一组；
  已设置：品牌色浅底，文字是当前条件，点文字 = 调整，点 × = 单独移除，两个按钮各自 44 高。读屏名称是「时间：本年，点按调整」「移除时间条件：本年」（文案在 `BillListPresentation`）。
  已设置的标签是 `span[role=group]` 里的两个按钮——**不能做成「按钮里套按钮」**（无效 HTML，WebView 会重排 DOM）。
- **账单 Tab 的默认视图是「本月」，它不算筛选条件**（第 2 轮评审，用户拍板；设计稿 02 / 13 的时间标签就是「本月」）：`BillListFilter.DefaultTimePreset = Month`，页面打开时 `ResetPanel()`；
  默认的「本月」不计入角标（`PanelCount` 只算 `HasTimeCondition = HasTime && !IsDefaultTime`）、条件条上是中性的「本月 ⌄」（`data-active="false"`，读屏名称「时间：本月，点按调整」）、
  筛选 Sheet 里默认选中、「重置」回到它（`IsDefaultPanel` 时置灰）。**取消时间范围**（Sheet 里再点选中的预设，或条件条上点已设置时间标签的 ×）= 「不限时间」：标签是中性的「时间」、同样不是条件不计角标，
  但它偏离了默认，「重置」可点。「清除搜索 / 清除筛选」（`ClearConditions`）只去掉真正的条件，**不顺手把默认的「本月」取消**；空状态也据此区分：只受「本月」限制时是「本月还没有账单」+「记一笔」+「查看全部账单」（取消时间范围），
  取消后一笔都没有才是「还没有账单」。首页「查看全部」进来看到的是本月。
- **筛选 Sheet `BillFilterSheet` 编辑的是草稿**：只在 `Visible` 从 false 变 true 的那一刻把页面当前条件复制成草稿（之后页面重绘 / 后台刷新账本列表冲不掉用户正在调的条件），
  点「查看」才生效；✕ / Esc / 遮罩 / 下拉把手都是放弃，没改条件就点「查看」只是收起。时间 / 账本 / 支付渠道是单选，再点已选中的标签 = 取消；**分类可多选**（第 2 轮评审，用户拍板：满足其中任意一个即可，
  `BillFilter.CategoryIds` 走 `IN` 查询；条件条上多选时写「第一个的名字等 N 项」，一个维度一个 ×，角标只算 1 项）；账本多一个「全部」，
  「未归属账本」与具体账本互斥——它们是同一个「账本」维度的不同取值。**时间预设（今天 / 本周 / 本月 / 本年，周一为一周之始）存的是预设本身而不是日期**，
  查询时才按当时的应用时区日历日换算（`BillListFilter.ToQuery(nowLocal)`，区间含端点），页面放过夜再翻页 / 刷新，「今天」跟着变；
  自定义与预设互斥，起止日期都含当天、可以只填一端；已选预设（含默认的「本月」）时点「自定义」会把预设的起止预填进日期框。
- **底部「查看 N 笔账单」与汇总卡同一口径**：Sheet 每次改草稿都用页面传入的 `CountAsync`（`BillService.GetBillCountAsync`，与列表 / 汇总共用 `BuildBillQueryAsync`）重新估算，
  经 `PageDataGate` 排队，过期结果（又改了条件）用版本号丢弃；**笔数为 0 也照常写「查看 0 笔账单」且可点**（第 2 轮评审，用户拍板；设计稿 13 里按钮始终是「查看 N 笔账单」）——点了之后账单页给出「没有符合条件的账单」与「清除筛选」入口；
  估算失败不拦着用户（按钮退回「查看账单」，仍可点）。笔数写在 `data-count` 上，按钮外层 `aria-live="polite"`：这是用户调条件时唯一能听到的「现在有多少笔」反馈。
- **「未归属账本」是账单筛选里的一等条件**：`BillFilter.UnassignedLedger`（`LedgerId IS NULL`）；与 `LedgerId` 同时给出时按交集处理（必然为空）。
  历史无账本的账单（见 CLAUDE.md 账本约定）因此可以被筛出来、全选、批量归属——这是它们回到正轨的主入口。
- **多选操作栏 `ft-actionbar` 不是玻璃**：玻璃层预算（每屏 ≤ 3，见 §3）已被 Tab 栏与导航栏两个圆钮用完，操作栏用实色卡片 + `--ft-shadow-bar`，悬浮在 Tab 栏之上
  （`--ft-z-actionbar` 90 < Tab 栏 100 < Sheet 120 < Alert 130 < Toast 1100）；多选时页面根加 `ft-bills--selecting`，底部多留出操作栏的位置，最后一笔账单能滚到它之上。
- **批量归属 `AssignLedgerSheet`**：账本必选（不支持「移出账本」，那会制造新的未归属账单）；**只列自己的账本**（共享账本不能作为归属目标，`BillService` 同样拒绝）；
  只有一个自有账本时打开即预选，多个时让用户明确选一个（避免手滑把一批账单归错账本）；一个都没有时给「还没有自己的账本，请先到「我的 - 账本管理」新建一个」的引导。
  提交中（`Busy`）Sheet 不可被收起、按钮转圈，防止重复提交；成功后清空选择、仍停在多选模式（便于接着归属下一批），并经 `BillEventService` 通知其他页面刷新。
- **悬空条件自动移除**：条件指向的账本 / 分类 / 支付渠道已不存在（例如退出了共享账本、别处删了自建账本）时，条件条上没有名字可显示、结果也必然为空，
  加载选项时直接移除；共享账本没读成功时**不能**据此移除（那只是「没读到」，不是「不存在」）。改了条件后不在列表里的已选账单同样自动移出已选（`PruneSelection`）。
- **玻璃层预算的已知例外**：账单 Tab 打开 Sheet 时同屏是 4 层（Tab 栏 + 导航栏两个圆钮 + Sheet 的关闭按钮），比 §3 的「≤ 3」多一层。
  Sheet 打开时底下的页面不可交互，若把页面的两个玻璃圆钮临时降级，会出现「Sheet 一开按钮突然变样」，所以本 ticket 接受这一层，
  E2E 写成「Sheet 打开时 ≤ 4、收起后 ≤ 3」。**23 号 ticket 已统一决定：Sheet 升起期间被盖住的页面与 Tab 栏关掉毛玻璃**（`<html data-ft-sheet-open>`，见 §26），此后任何 Sheet 打开时整屏都 ≤ 3 层，这条例外不再存在。
- **图标字体里没有的字形**：预设支付渠道「支付宝」的图标 `mdi-alipay` 在 `@mdi/font` 7.2.96 里**不存在**（19 个预设图标逐个核对过，只有它缺），渲染出来是一块空白。
  `MdiIcons.Normalize` 用 `RetiredIcons` 把它换成 `mdi-qrcode-scan`（扫码支付的通用意象），所有经 `Normalize` 的出口（行、标签、Sheet）一次修好；
  预设数据里的图标名没改（已同步进用户库的历史数据不用迁移），单元测试守住「预设图标经 `Normalize` 后全部在字形清单里」，E2E 在字体已加载时逐个检查标签图标的 `::before` 有内容。

### 12. 账单搜索（10 号 ticket 起）

- **匹配规则**（`BillService.BuildBillQueryAsync` 里的**一个** `Where` 分支，列表 / 总数 / 汇总同时生效，规则由 `BillKeyword.Parse` 统一解析）：
  关键字去掉首尾空白，空 = 没有条件；备注或分类名称**不区分大小写地包含**关键字；关键字整体能解析成数字（`12`、`35.5`、`-3`，按 `InvariantCulture`，与系统区域无关）时，
  再并上「金额**等于**该数值」。数字匹配的是数值相等而不是文本包含：`35` 命中 35.00 的账单与备注含「35」的账单，不命中 35.50 / 135。
  只读查询：不暴露到 REST、不改实体 / 迁移 / 同步；与时间 / 账本 / 分类 / 支付渠道 / 类型取交集，软删除与账本（含共享账本）可见性照旧。
- **SQLite 的三个事实决定了写法**：① 金额列是 TEXT，`Amount == x` 依赖 EF 把两边都规范成同一种文本；**范围比较 `>= x && <= x` 会被翻译成 `ef_compare(...)` 的数值比较**，
  对库里非规范文本（别的路径写入的 `12.500`）同样成立，所以用它表达「相等」。**只有**单元测试「库里的金额文本格式不规整时也按数值比较」（用原始 SQL 写入非规范文本）守得住这一点——
  EF 自己写入时会把 12.50 规整成 `12.5`，所以普通的「12.5 与 12.50 相等」用例对 `==` 也能通过（变异检查：把条件改成 `==`，27 项里恰好这一项失败）；② `ToLower().Contains()` 翻译成
  `instr(lower(x), @p) > 0`——**按字面匹配，`%` / `_` 不是通配符**（不用 `LIKE`，免去转义）；③ SQLite 的 `lower()` **只折叠 ASCII**：中文不受影响，
  带重音的拉丁字母（É / é）不会互相匹配——可接受，记账场景几乎遇不到。
- **关键字不是筛选维度**：它在 `BillListFilter` 里是独立的 `Keyword`（赋值时规范化：去首尾空白，空白 = null），不在 `BillFilterDimension`、不进筛选 Sheet、不计入角标（`PanelCount`）、
  条件条上没有它的标签——搜索框里的文字本身就是它的展示。但它是条件：`HasAny` 含它（空状态说「没有找到相关账单」而不是「还没有账单」），`Clone` / `CopyFrom` / `SameConditionsAs` / `ToQuery` 都带它，
  所以 Sheet 的草稿不丢关键字、Sheet 底部的「查看 N 笔账单」带着关键字算、「只改了关键字」不会被当成「条件没变」。
  空状态按条件组合给三种文案（只有关键字 / 关键字 + 筛选 / 只有筛选），「清除」按钮的文案与实际清掉的内容一致（清除搜索 / 清除搜索与筛选 / 清除筛选），点它清掉全部条件。
- **提交时机：停顿提交，行为在 `ui.js` 的文档级委托里，不用 Blazor 的 `oninput`**。Blazor Server 的 `oninput` 每个按键都往返一次服务端，而且输入法组词期间（拼音还没选字）的 `input`
  事件会让结果列表来回闪。规则：输入停顿 350 ms 提交；`isComposing` 期间不提交（组词结束的 `compositionend` 再排一次停顿——Safari 的 `compositionend` 在最后一次 `input` 之前触发，所以两处都要排）；
  回车 / 软键盘「搜索」键立即提交并让输入框失焦（收起软键盘；组词期间的回车 `isComposing` / `keyCode 229` 是在确认候选字，不算）；清除按钮清空、保持焦点（软键盘不收起）、立即提交；
  失焦时浏览器自己派发 `change`。「提交」就是在输入框上派发一次 `change`，Blazor 的 `@onchange` 接手；脚本记下每个输入框最近一次提交的内容，内容没变不重复提交，
  服务端 `ApplyKeywordAsync` 在第一个 `await` 之前就更新关键字，所以同一次输入的重复事件（脚本派发的 + 浏览器的）第二个直接返回。
  **Playwright 的 `fill()` 同时派发 `input` 与 `change`，等于立即提交**；测停顿用 `press_sequentially`，测输入法用 `compositionstart` / `InputEvent({isComposing:true})` / `compositionend` 模拟。
- **搜索框是「不受控」的**：`SearchField` 的 `<input>` 不绑 `value`——内容由浏览器持有，服务端不回写。回写会让「事件往返期间用户又敲的字」被服务端旧值盖掉（经典的受控输入竞态）。
  代价是服务端要从外部清空时（空状态里的「清除…」、换账号）不能改 `value`，而是给 `<SearchField>` 换一个 `@key`（`_searchEpoch`）让整个输入框重建；
  首次进入时搜索框还是空的，不换 key（重建只会丢掉用户这时已经敲的字）。清除按钮的显隐用 CSS `:placeholder-shown` 判断（有占位文字且正显示 = 没有内容），不依赖脚本也不依赖服务端状态。
- **外观**：灰色填充（`--ft-fill`）、18px 圆角（`--ft-radius-input`）、整条 44 高、左侧放大镜、输入框字号 16px（iOS Safari 小于 16px 聚焦时会放大页面），自己不用 `backdrop-filter`；
  聚焦时 2px 品牌色外圈。位置在大标题之下、分段控件之上，跟着页面滚动（不吸顶——吸顶要多占一块玻璃 / 不透明区域，与大标题折叠的导航栏叠在一起），与其它条件一样随页面常驻、切 Tab 不丢。
  读屏：容器 `role="search"`，输入框 `type="search"` + `aria-label`「搜索账单」，旁边一个视觉隐藏的 `role="status"` 区域播报「找到 N 笔账单」/「没有找到相关账单」。

### 13. 统计 Tab：分段壳与月度（11 号 ticket 起）

- **外壳 + 三个可嵌入的视图**：`Pages/Statistics.razor` 是 Tab 根页面（`LargeTitlePage`），持有「切换分段时要保持的状态」——分段（月度 / 趋势 / 年度）、**账本筛选（三个分段共用）**、月度的年月；
  `MonthlyStatisticsView` / `TrendAnalysisView` / `AnnualReportView` 只管「按参数取数 + 摆放」，共用 `StatisticsViewBase`（读库经 `PageDataGate`、参数 `(用户, 账本, 视图自己的 LoadKey)` 变了才重新加载、
  排队等锁期间被更新的加载取代的旧加载直接放弃、订阅 `BillChanged`、失败只弹 Snackbar 并保留上一次的数据）。旧的 `/statistics` 重复页面（`MonthlyStatistics.razor`）已删除。
  趋势 / 年度两个分段在 11 号只是把原页面主体搬进来（旧地址 `/trend`、`/annual-report` 暂时保留为薄包装），视觉重做与旧地址改为跳转在 12 号（见 §14）。
- **规则：视图被父页面直接调用 `ReloadAsync` 时必须自己重绘**。视图的参数没变，框架重绘父页面时会跳过它，所以字段换成了新数据、界面还停在旧数据上——
  刷新「没反应」就是这么来的（E2E 里「造一笔账单 → 刷新 → 读 KPI」发现；当时入口还有刷新按钮，按钮撤掉后同一条断言改成真实触摸下拉，路径相同）。`ReloadAsync` 开始（标记重新加载中）与结束（换上新数据）都显式 `StateHasChanged`；
  走参数变化（`OnParametersSetAsync`）与 `BillChanged` 的路径本来就会重绘，重复调用无害。
- **刷新 = 只读本页数据**（沿用 07 / 08 的约定）：刷新只有下拉（导航栏没有刷新按钮，见 §9）——重读账本列表 + 重新加载当前视图，**不触发云端同步**（同步只在「我的」里手动触发）。二级页面关闭后同样重新加载
  （预算 / 账本 / 分类 / 导入都可能改了这里的数据；记一笔 / 编辑账单已经经 `BillChanged` 刷新，不重复）。
- **口径不变（ADR 0005）**：月份是应用时区的自然月、区间左闭右开；只统计当前用户自己记的账单（共享账本里别人记的不计）；账本选项只列用户自己的账本；
  历史无账本账单在「按账本」里归「未归属账本」；「按账本」只在「全部账本」且用户至少有一个账本时才有意义（选了具体账本只剩那一个，没有账本只剩一条「未归属账本」），否则入口不出现；
  预算执行节只在当月有预算时出现，账本口径随筛选（全部账本 = 只看全部账本的预算，具体账本 = 该账本预算 + 全部账本预算）。
  一次加载取回支出 / 收入 × 按分类 / 按账本四套数据，所以「支出 ↔ 收入」「按分类 ↔ 按账本」切换不再查库。
- **构成圆环是纯 SVG，不用 ECharts**：环很简单、不需要交互；纯 SVG 没有脚本与 CDN 依赖，手机上不卡，每一段又是独立元素，E2E 能直接数段数、读占比。几何是纯函数（`DonutGeometry`：从 12 点钟开始顺时针、
  段间留缺口、单段铺满一圈不留缺口、没有数据画灰色空环）。**环与图例的颜色来自同一个 `ColorIndex`**（金额排名 → `ft-hue--0…9` → `--ft-hue`，色板只引用设计令牌：
  品牌、橙、绿、蓝、粉、青、紫、黄、靛、灰，超出 10 项循环），所以永远一致。图例按金额降序（同额按名称），金额 ≤ 0 的不出现；占比 = 金额 / 合计（两位小数，银行家舍入，与服务层一致），
  显示文字一位小数（`<0.1%` 表示大于 0 但不足 0.05%，避免真实存在的分类显示成 0.0%）。环中心放总额（`AmountDisplay`），≥ 12 个字符的长金额缩小字号，不挤出环中心的孔。

### 14. 统计 Tab：趋势与年度重做、旧地址改为跳转（12 号 ticket 起）

- **时间控件跟随分段，外壳持有全部「切分段要保持的状态」**：月度 = 月份胶囊；趋势 = 时间范围胶囊（点按弹出 `ActionSheet`：最近 7 天 / 30 天 / 90 天 / 12 个月）；
  年度 = 年份胶囊（`PeriodSwitcher`，2000–2100）；账本胶囊三个分段共用，始终在右。时间维度（按日 / 周 / 月）是趋势独有的，放在趋势视图顶部的分段控件里，
  但取值同样由外壳持有（`@bind-Dimension`）——切分段、切 Tab 再回来范围 / 维度 / 年份都不丢。
  设计稿 07 的「需确认」（时间范围放哪）的结论：筛选行三个分段保持一致（左 = 本分段的时间控件，右 = 账本），维度是趋势内部的切换，所以放在视图里。
- **数据口径不变，只换展示**（ADR 0005）：趋势窗口 = `[现在 − N 天（或 12 个月）, 现在]`，按日 / 周（周一起）/ 月（月初）聚合、只返回有账单的日期；
  年度当年是「年初至今 vs 去年同期」（同一月日截止，左闭右开），已结束 / 未来的年份比整年，去年同期为 0 时变化率为 `null`、显示「—」+「（无对比基数）」，不显示成 0%；只统计自己记的账单。
  展示规则（范围 / 维度 / 年份的规整与文案、明细表排序、同比文案与语义色、变化率字号档位）都是 `StatisticsPresentation` 里的纯函数，单元测试覆盖，Razor 里不散落判断。
- **折线图的颜色取自设计令牌**：`StatisticsChartOptions` 用纯函数构造 ECharts 配置（支出 `DesignTokens.ExpenseColor` #E8362C、收入 `IncomeColor` #1FA544、净收支 `BrandColor`；与 KPI 小圆点、月度的累计收支图 / 支出日历同一套——最初趋势 / 年度折线用的是 iOS 系统红绿 #FF3B30 / #34C759，
  与月度两张图不一致，且系统绿在白底上只有约 2.2:1，低于线条等图形元素的 3:1，审查阶段按用户决定统一到前者），点多（> 31）时不画数据点，
  纵轴标签 `¥{value}`、重叠自动隐藏，网格右侧留 22px 免得最后一个横轴标签被卡片边缘裁掉。单元测试把配置序列化成 JSON 后按 ECharts 读它的方式检查；
  E2E 读 ECharts 实例的配置（`window.echarts.getInstanceByDom(div).getOption()`）核对横轴 / 数据 / 线色，不读画布像素（离线 CDN 不可用时只验证容器与空状态）。
- **趋势明细表**：原表是每页 10 行的翻页，手机上改为「一次 10 行 + 显示更多逐批展开」。排序三态循环（升序 → 降序 → 取消，取消回到日期升序），换列从升序重新开始，同值保持原来的日期顺序（稳定排序）；
  排序状态在 `th` 上用 `aria-sort` 表达；表头按钮铺满整个单元格（命中区域 ≥ 44 × 44），排序箭头绝对定位在文字旁、不占列宽，所以表头文字始终与下面的数字右对齐。
- **年度的同比颜色语义**：支出上涨 = 差（`--ft-danger-text`）、收入上涨 = 好（`--ft-income-text`），下降相反，无基数 / 四舍五入后为 0 = 中性；文字色用 `*-text` 令牌（≥ 4.5:1，`--ft-income` 在白底只有约 3.2:1）。
  变化率可以非常长（去年同期只有 0.01 元时是 `+99999999800.0%`），按字数分档缩小字号（≥ 9 个字符一档、≥ 12 个字符再一档），不撑破两栏。
- **年度的分类统计拆成「支出构成 / 收入构成」两个圆环**（第 2 轮评审后用户拍板；最初沿用原口径——收入与支出的分类放在一起汇总、占比占两者合计，页面用一行说明讲清楚）：
  `AnnualStatistics` 新增 `ExpenseCategoryStats` / `IncomeCategoryStats`（只含各自类型的账单、占比各自占本类合计、金额降序，与月度分段的构成口径一致），原来的混合 `CategoryStats` 保留给 REST 接口，响应形态不变；
  视图按类型各一节（节标题 / 圆环中心「全年支出」「全年收入」/ 图例 / 没有这一类账单时「当年暂无支出账单」「当年暂无收入账单」）。
- **趋势折线图的横轴补零**（第 2 轮评审后用户拍板）：统计服务只返回有账单的日 / 周 / 月，折线直接连着有数据的点画会让没有账单的时间凭空消失。`StatisticsPresentation.FillTrendBuckets` 在页面层把三张折线图的横轴补成连续的时间桶
  （从窗口起点所在的日 / 周一 / 月初走到终点所在的桶，每桶一个点，没有账单的桶是 0）。只补趋势视图的三张折线图：明细表仍只列有账单的桶、KPI 合计不变、没有任何账单时仍是空状态；月度分段的累计收支与支出日历不动。
- **旧地址只做跳转，分段不经过地址传递**：
  - 直接访问 `/trend`、`/annual-report`（书签 / 刷新）：Web.Server 在 HTTP 层回 302 到 `/statistics?segment=trend|annual`（不看旧地址的查询串）。页面栈对「初始地址就是旧地址」的情形没有干净的出路——历史里会留下一条旧地址，返回时落在空白页上。
  - 应用内（12 号完成时「我的」里的入口把旧地址压栈；13 号移除入口后应用内已没有调用方，这条路径只留作兜底，也没有 E2E——PageStack 只响应自己发起的导航，脚本里 `Blazor.navigateTo` 压不进去）：薄页面 `StatisticsRedirect` 先登记请求、再 `GoBackToTab("/statistics")`（一次完成「清栈 + 切到 Tab 根页面」；`NavigateTo(replace)` 只改地址不清栈，会在统计页上面残留一张空白全屏页）。
    页面栈的事实：**250 ms 内的第二次导航调用被静默丢弃**（`ExecuteIfTimeElapsed`），而跳转页是 Push 之后才渲染出来的，所以先等 300 ms 再调用，被丢（地址没变）就重试，最多 3 次；
    `Replace(..., clearStack: true)` 在栈里只有一页时会触发重载循环，不用。
  - **为什么不用地址里的 `?segment=` 传分段**：带参数的地址会留在历史里。用户落地后切了分段、进二级页面（比如自定义报表）再返回时，地址又回到带参数的形态，
    统计页若在地址变化时按参数切分段，就把用户切换后的分段冲掉了（E2E「落地后换分段、进自定义报表再返回」发现的真实缺陷）。所以：地址里的 `segment` **只在统计页创建时读一次**（宿主 302 的直接访问）；
    应用内跳转用一次性请求服务 `StatisticsSegmentRequest`（Scoped，登记后只能取走一次，10 秒后作废，不会在以后某次无关的进入统计页时突然生效）：统计页创建时、或地址变到统计页的那一刻认领它。
    点 Tab 栏回到统计页、从二级页面返回都没有请求，保持用户停留的分段。
  - 已接受的权衡：应用内入口跳转之后，「我的」那条历史记录被替换，系统返回键回到的是它之前的一条——返回行为合理，不会回到旧地址或空白页。
  - 「我的」里的「趋势分析」「年度报告」入口已由 13 号 ticket 移除（统计 Tab 本身就是入口，见 §15）；旧地址继续保留给书签与外部链接。
    `StatisticsRedirect` / `StatisticsSegmentRequest` 现在只剩兜底作用（MAUI 里没有 Web.Server 的 HTTP 302，旧地址若被外部深链 / 旧版本留下的导航带进来，只有它接得住）；
    **24 号决定保留**：删掉之后这些旧地址在 MAUI 里会落到「页面未找到」，而保留的成本只是一个薄页面加一个一次性请求服务（后者有单元测试）；跳转页的转圈已换成设计系统的图标 + 令牌色（§27）。以后若确认没有任何深链 / 旧版本会带旧地址进来，可以一并删除这两处和 `/trend`、`/annual-report` 两张页面。
- **实现里踩到的坑**：① Razor 里字符串类型的组件参数必须写 `@`（`Range="@_trendRange"`）——写成 `Range="_trendRange"` 传进去的是字面量，视图的范围永远不变；非字符串参数（`int`、`Guid`）才按表达式处理。
  ② 父页面直接调用子视图的 `ReloadAsync()` 时子视图自己要 `StateHasChanged`（§13）。③ 筛选行里 `.ft-pill` 自带 `margin-left: auto`，后定义的它会压过单类名选择器——覆盖时用两类名选择器。

### 15. 我的 Tab：分组设置列表 + 云端同步行（13 号 ticket 起）

- **只做展示重构**：沿用 `LargeTitlePage`（大标题「我的」滚动后折叠成居中小标题）+ `GroupedList` / `ListCell`，iOS「设置」式分组：资料卡 → 云端同步 → 记账管理（账本 / 预算 / 分类 / 支付渠道）→ 自动记账（待确认账单 / 短信识别 / 数据导入）→ 其他（错误日志）→ 退出登录。
  入口目标页与原来一致，没有新增功能；账单列表（= 账单 Tab）、趋势分析 / 年度报告（= 统计 Tab 的分段）、自定义报表（= 统计页右上角）四个入口迁出，不再保留重复入口。
  导航栏右侧没有按钮（与设计稿一致；刷新只靠下拉，见 §9）。**整页没有新增任何 `backdrop-filter` 层**（每屏只有 Tab 栏那 1 层）。
- **摘要值：每行独立读取，读失败只让这一行不显示摘要**（不显示成 0 误导用户）。口径与各自的管理页一致：账本 = 自己的账本个数（不含已删除、别人的、我加入的共享账本）；
  预算 = 本月（应用时区）「全部账本」口径的预算项数（账本专属预算不计入）；分类 / 支付渠道 = 预设 + 自己未删除的；待确认账单 = 红色计数角标（≥ 100 显示「99+」，行的读屏名称带真实笔数）；
  短信识别 = 读取权限是否已授予（「已开启 / 未开启」，权限检查不碰数据库，所以不进数据闸门）。其余读库全部经 `PageDataGate` 与其它常驻的 Tab 根页面排队（它们共用一个 `DbContext`）。
  文案 / 摘要 / 角标的判断都是 `ProfilePresentation` 里的纯函数，单元测试覆盖，Razor 里不散落判断。
- **同步行沿用原「同步状态」组件的全部能力，只换外观**（`SyncStatus` 现在渲染成一个 `ListCell`：橙色图标块 + 状态副标题 + 右侧「立即同步」胶囊，按钮本体 44 高保证点击热区）：
  待同步数量读 `GetOfflineCacheCountAsync`（待同步 + 同步失败；读失败如实显示「状态未知」，绝不显示成「已同步」）；「立即同步」始终可点；结果仍用 Toast 反馈，整体失败时给真实原因而不是「同步完成，0条失败」。
  **同步仍然只由用户点按触发**：下拉刷新、进入页面、二级页面关闭都只重读本页数据，**不联网同步**（与 pull_refresh=refresh_only 的决定一致，E2E 用假云端断言「刷新期间云端没有收到任何同步请求」）。
  同步结束经 `OnSynced` 通知「我的」重读各项摘要（一次同步可能拉下账本 / 预算 / 账单）。
- **自动更新靠事件，不靠轮询**：账单变更（记一笔 / 编辑 / 删除 / 导入，`BillChanged`）→ 刷新待同步数量；待确认账单变化（`PendingBillsChanged`）→ 刷新角标；认证状态变化 → 重读资料；
  二级页面关闭（`PageClosed`——账本 / 预算 / 分类 / 支付渠道 / 待确认账单 / 短信识别 / 导入都可能改了摘要）→ 重读全部摘要与同步行（记一笔页除外：它已经经 `BillChanged` 刷新，不重复读）。
- **退出登录**：红色文字行 → Alert 确认（取消 / Esc 留在原地）→ 清登录状态 → 回登录页。登录页是独立布局（没有 Tab 栏），换号登录后不残留上一个用户的资料与摘要。
  **已知限制**：确认后排入队列的「已退出登录」Toast 会随着布局切换（`MainLayout` → `AuthLayout`）一起被丢掉——旧的「我的」页就是这样，不是这次引入的；E2E 只能断言「Toast 已入队」。要让用户看到提示，得在登录页上做一次性提示，留给 22 号（登录页）判断。
- **实现里踩到的坑**：MASA 的 `.m-application p { margin-bottom: 16px }` 特异性（类 + 元素）高于单类名选择器，`<p>` 的外边距清不掉（`.ft-x { margin: 0 }` 输给它）——资料卡的手机号 / 注册日期因此被撑开 32px。
  新写的标记一律用 `div` / `span`，不用 `<p>`；全局性的修复已在 23 号 ticket 完成：`ui.css` 开头 `.m-application p { margin-bottom: 0 }` 把它归零（见 §26），
  之前绕开它的 `p.ft-…` 选择器与「不用 `<p>`」的约定保留无害——24 号评估后**不收回**（§27）。
- **其它 E2E 脚本里依赖旧「我的」页的断言已改**：Tab 壳的「账单入口」改测首页「最近账单 → 全部」（返回键回到首页），滚动类断言压矮视口、不再依赖「我的」页的内容高度（新页面只比一屏多一点）；
  Tab 滑块的收缩 / 页面保活改在造了 30 笔账单的「账单」Tab 上做；沉浸式脚本删掉旧 `.container` 根页面断言，旧二级页的检查改指向「统计 → 自定义报表」。

### 16. 分类管理与支付渠道：同构的「自定义 / 预设」管理页（14 号 ticket 起）

- **只做展示重构**：两页都是二级页面模板（`SecondaryPage`，右上角「＋」）+ `GroupedList` / `ListCell` / `SwipeRow` + 底部 Sheet + Alert / ActionSheet，沿用账本页（§7）的全部交互约定。
  新建 / 修改 / 删除 / 设为默认全部调用既有服务（`CategoryService` / `PaymentChannelService` / `UserDefaultService`），服务层校验与权限语义不变，页面不绕过任何校验。
- **页面结构**：分类页顶部是「支出 / 收入」分段（每个分类只属于一种账单类型）；两页都分「自定义」与「预设」两组。
  - 「自定义」组：左滑出现「编辑」「删除」，点按整行进入编辑 Sheet（编辑 Sheet 里的「设为默认」开关与「删除」是左滑操作的非滑动等价入口）；右侧是该项下的账单数「N 笔」；组末尾始终是「新建…」行（没有自定义项时它就是这一组的全部内容），脚注只在有自定义项时出现。
  - 「预设」组：**只读**——不能改名、不能删除，右侧标注「预设」，没有左滑托盘与箭头；点按弹出 ActionSheet，里面只有「设为 / 取消默认」一项。预设项不显示账单数（省掉对应的查询）。
  - 「默认」徽标在自定义与预设行上都可能出现；分类的默认支出分类与默认收入分类各有一个、互不影响（菜单与开关文案随类型变化），支付渠道只有一个默认；默认值仍存在 `UserDefaults`（记一笔默认选中它，15 号用）。
    设为 / 取消默认**立即生效**（不依赖「保存」），成功后 Toast 提示、列表徽标跟着变，编辑 Sheet 保持打开。
- **共用件（避免两页各写一份）**：`NameIconFormSheet` 是通用的「名称 + 排序 + 图标网格」表单 Sheet（名称校验、保存中状态、成功 / 失败提示、`EditingExtras` 插槽放页面自己的操作）；
  `CategoryFormSheet` 在它外面包一层「调用 `CategoryService` 落库」——**15 号「记一笔」的「新建分类」直接复用这个面板**（`OnSaved` 把保存后的分类交给调用方，调用方自动选中它），支付渠道页直接用 `NameIconFormSheet`。
  文案与规则是 `ManagedItemPresentation`（名称校验：空 / 全空格 → 「请输入{分类｜支付渠道}名称」，超过 50 个字 → 「…名称最多 50 个字」；「N 笔」）、`CategoryPresentation` / `PaymentChannelPresentation`（候选图标、默认菜单文案、配色）里的纯函数，单元测试覆盖，Razor 里不散落判断。
- **颜色不落库（判断项）**：设计稿 11 的新建面板里有颜色选择，但 `Category` / `PaymentChannel` 实体没有颜色列，加列意味着迁移 + 同步 DTO + 云端表，超出「只改展示」的边界，所以**表单里没有颜色选择**；
  色块配色由名称（预设分类用固定色）或 Id（自定义分类 / 支付渠道）稳定哈希取色（`BillPresentation.CategoryTone` 的七色盘），同一个项在账单行、统计、管理页里颜色一致。是否新增 `Color` 列留作判断项（见 review-backlog）。
- **分类类型编辑时不可改（判断项）**：`UpdateCategoryAsync` 会覆盖 `Type`，而分类下已有账单的类型是固定的，改类型会让统计口径错乱；新建时的类型 = 当前分段，编辑时原样带回。
- **删除**：Alert 确认后软删除；分类 / 支付渠道下还有账单时服务层抛 `InvalidOperationException("该…下有账单，无法删除")`——页面把它当**警告**提示（条目保留，Sheet 仍打开让用户另做处理），不是错误；
  预设项的 `ForbiddenAccessException` 同样走警告提示（正常情况下预设行不提供删除入口）。**权限类错误绝不当成 401 处理**（CLAUDE.md 第 7 条：本页没有任何 401 / 登出路径）。
- **图标**：分类 42 个（7 行 × 6）、支付渠道 24 个（4 行 × 6）候选，全部存在于应用引用的 MDI 7.2.96——脚本核对类名（`.scratch/check_mdi.py` 读官方 CSS）+ E2E 在应用实际加载的字体里逐个检查 `::before` 字形（图标缺字形会渲染成空白）。
  已退役的 `mdi-alipay` 由 `MdiIcons.Normalize` 回退为 `mdi-qrcode-scan`；历史数据里不合法的图标类名列表回退默认图标（`mdi-tag` / `mdi-credit-card`），编辑保存时规范化。
- **数据读取**：经 `PageDataGate` 与常驻的 Tab 根页面排队（共用一个 `DbContext`）；依赖 localStorage 的用户 Id 在 `OnAfterRenderAsync(firstRender)` 取。
  二级页面关闭（`PageClosed`）会让首页 / 账单 / 统计 / 我的重读，所以分类 / 支付渠道的增删改不需要发 `BillChanged`。读失败：已有数据时保留旧数据并 Toast，第一次就失败才整页显示错误状态与「重试」。
- **已知取舍**：① 每个自定义行单独查一次账单数（N+1，数量级是用户自己建的几个到几十个，且都在闸门内顺序执行）；批量统计需要给服务加新接口，不属于展示重构。
  ② 分类 Sheet 的 42 个图标让它高到视口顶部下 12px（`.ft-sheet` 的 `max-height`），遮罩区只剩顶上一条；真机上用左上角关闭 / 拖拽把手收起更自然，是否收窄图标网格的高度留待人工验收判断。
  ③ 页面里没有用 `<p>`（MASA 的 `.m-application p` 外边距泄漏，见 §15）；`GroupedList` 脚注本身是 `<p>`，已由 23 号 ticket 的全局归零（`.m-application p { margin-bottom: 0 }`）一并修好（§26）。

### 17. 记一笔 Sheet（15 号 ticket 起）

- **布局级覆盖层，不是路由页**：`AddBillSheet` 常驻挂在 `MainLayout` 里、`PPageStack` 之前，由 Scoped 服务 `AddBillSheetService`（`Open()` / `Close()` / `IsOpen` / `Changed`）开关——
  Tab 栏「记一笔」圆钮与首页 / 账单 Tab 空状态里的「记第一笔」都只调 `Open()`。**不压栈**：地址不变、来源页（滚动位置、筛选、Tab）原封不动，关掉就在原处，也不与页面栈的转场 / 左边缘右滑返回打架。
  旧地址 `/add-bill` 由 Web.Server 302 到 `/?add-bill=1`，首页在首次渲染之后（预渲染没有 JS / 登录态）读到参数升起 Sheet；MAUI 宿主没有 HTTP 层，入口都是服务调用，用不到这条路径。
  `/add-bill/{BillId}`（编辑）在 16 号并入同一个 Sheet，见 §18。
- **背景缩放只靠同级选择器**：`.ft-sheet-host--scale ~ .m-page-stack`——Sheet 宿主与页面栈是应用壳里的兄弟节点，不需要脚本也不需要在页面栈上挂状态类。缩放 0.94、圆角 28、`transform-origin: 50% 0`；
  关闭时宿主带 `--closing`，页面栈随退出动画同步复位，卸载后不留残余变换。Tab 栏（`.ft-tabwrap`）与页面栈同级，不被缩放，只是被 Sheet 与遮罩盖住（Tab 栏 100 < Sheet 120）。
  减弱动态效果下不缩放（背景保持原样，Sheet 淡入）。
- **玻璃层预算（每屏 ≤ 3）**：Sheet 升起后屏幕上本来有 Tab 栏 + 标题栏的两个玻璃圆钮 + 底下页面自己的玻璃钮（账单页导航栏两个、统计页一个），最多 5 层；
  `.ft-sheet-host--scale:not(.ft-sheet-host--closing) ~ .m-page-stack .ft-glass`（以及 `~ .ft-tabwrap .ft-glass`）把这些被遮罩盖住的层的 `backdrop-filter` 关掉，屏幕上只剩标题栏的两个圆钮；
  一开始收起（`--closing`）就立刻恢复。E2E 在四个 Tab 上各量一次（升起时只有两层，收起后与升起前一致）。Toast 是短暂的玻璃胶囊，不算「常驻层」。
- **金额不是输入框**：展示区是 `div`（大字 + 闪烁光标，不唤起系统键盘），输入全部走自定义键盘 `AmountKeypad`；规则集中在纯函数 `AmountInput`（最多 2 位小数、整数 ≤ 8 位且 ≤ 99,999,999.99、不出现前导零、
  `00` 键补两个 0、第三位小数 / 第二个小数点被忽略、长按退格清空），单元测试逐条覆盖。金额随位数缩小字号（`data-size`），99,999,999.99 也不溢出。
  备注是普通输入框（16px，免 iOS 聚焦放大）：聚焦时 `ui.js` 在 `.ft-sheet` 上写 `data-typing="true"`，键盘区隐藏、Sheet 内容不被系统键盘遮挡，回车 / 失焦恢复——脚本自有属性，Blazor 重绘冲不掉。
- **保存键置灰用 `aria-disabled`，不用 `disabled`**：被禁用的按钮收不到点击，做不了「点按置灰的保存键 → 账本行抖动并弹出账本菜单」的引导；`aria-disabled="true"` 同样让读屏读作「不可用」，样式据它置灰（浅灰底 + 加深的灰字，达到大号文字的对比度）。
  自动化里要点它必须 `click(force=True)`（Playwright 把 `aria-disabled` 当成不可点）。引导顺序由 `AddBillPresentation.CheckSave` 决定：金额 → 分类 → 支付渠道 → 账本；缺账本抖账本行并弹账本菜单，其余缺项抖对应区域并给一句提示。
- **账本必选，界面只做前置拦截**：默认账本 = 用户设为默认的自己的账本，否则第一个自己的账本（沿用旧记账页），所以「缺账本」只发生在**一个自己的账本都没有**的用户身上；账本菜单 = 自己的账本 + 有写权限（Owner / Editor）的共享账本（带「共享」徽标），
  末项「新建账本…」复用 05 号的 `LedgerFormSheet`，保存后自动选中。账本必填、写权限、UTC 换算仍由 `BillService` / `LedgerMemberService` 统一负责，`ForbiddenAccessException` 只弹警告 Toast（**不登出**，CLAUDE.md 第 7 条）。
- **弹出菜单 `PopoverMenu` 是实色白底，不是玻璃**（玻璃层预算，§3）：层级 `--ft-z-popover` 125，介于 Sheet 120 与 Alert 130 之间；定位由 `ui.js` 的 `positionPopover` 完成——优先放在触发行下方、右缘对齐，放不下放上方，
  两边都不够选空间大的一侧并限高、内部滚动；脚本写好位置前 `visibility: hidden`，写完置 `data-positioned`（避免在原点闪一下），脚本失败回退成底部列表（`data-fallback`）。
  点菜单外面只收起菜单、**不穿透**到下面的行，Esc 收起。账本菜单（`LedgerMenu`）是后续待确认账单 / 导入账单复用的共用件。
- **分类网格 `CategoryGrid`**：5 列、每页两行（10 格）、末尾虚线圆的「新建分类」；超过一页横向滚动 + `scroll-snap`，页码由 `ui.js` 的滚动监听写在容器的 `data-page` 上，分页点高亮靠 CSS 兄弟选择器，翻页不经 Blazor 往返。
  选中项变化后（新建分类、语音识别选中了第二页的分类、切换账单类型）组件调 `scrollPagerTo` 滚到选中项所在页（同类型内平滑，切换类型直接就位）；选中项不在列表里时不翻页（新建分类时「选中」先于「列表刷新」到达，按找不到处理会误翻回第一页）。
  **顺序沿用 `CategoryService`（类型 → 排序数字）**：自建分类的排序数字默认 0，所以排在预设前面，与旧记账页一致，用户用「排序」数字控制位置。新建分类复用 14 号的 `CategoryFormSheet`，保存后自动选中。
- **读取分两段、每次打开是一次新的「记账会话」**：先读本地（分类 / 支付渠道 / 账本 / 默认值，经 `PageDataGate`）让表单立刻可用；再读共享账本——先联网刷新成员关系，读路径只给 `CloudAvailability` 的短期限（ADR 0006），云端慢 / 不可用时只是菜单里少了共享账本。
  会话编号取自 `AddBillSheetService.OpenCount`：后台任务回来时编号对不上（用户已关掉又重开）就丢弃，上一次的迟到结果不会污染新的草稿。
- **保存流程沿用旧逻辑**：写入与随后的预算检查在同一个 `PageDataGate` 里（共用同一个 `DbContext`）：`EnsureCanWriteAsync` → `BillService.CreateBillAsync` → 预算预警；闸门之外再发 `BillEvents.NotifyBillChanged()`，各 Tab 页据此重读。
  成功后 Sheet 收起，Toast「已保存到「账本名」」，随后沿用「预算超支提醒 / 预算预警」Toast；数据来源 = 语音预填 ? `Voice` : `Manual`。时间界面显示 / 输入的是应用时区墙上时间，经 `BillService` 用 `AppTimeZone` 换成 UTC 入库，界面层不调用 `ToUniversalTime` / `ToLocalTime`（ADR 0005）。
- **有输入时关闭需确认**：金额或备注非空时，✕ / 遮罩 / 下拉把手 / Esc 先弹 `GlassAlert`「放弃本次记账？」（继续编辑 / 放弃）；保存成功后先清草稿再关，不会再弹。
- **E2E 基座**：`create_bill(..., page=…)` 经新界面保存（键盘输入 → 选分类 / 账本 → 保存）；不传 `page` 仍直接写库，留给历史无账本账单、待确认账单、非手动来源与精确时间这类界面造不出的数据。新的选择器全是普通按钮 / 行，  不再有「MASA 下拉无法自动化」的限制。

### 18. 编辑账单与删除（16 号 ticket 起）

- **编辑是同一个 Sheet 的另一种模式，不是另一个页面**：`AddBillSheetService.OpenEdit(billId)` 升起同一个 `AddBillSheet`（`Open()` 仍是新建），`EditingBillId` 标明编辑的是哪一笔，`OpenCount` 仍是记账会话编号（迟到的上一次结果按编号丢弃）。
  入口——账单 Tab 点按行与左滑「编辑」、首页最近账单、深链——都只调 `OpenEdit`；旧的编辑页 `Pages/AddBill.razor` 整页删除，应用里再没有任何地方压栈到 `/add-bill/{BillId}`，各 Tab 页里「路由前缀 `/add-bill` 的二级页关闭后重读」的判断也一并删掉（Sheet 保存后发 `BillChanged`，各页据事件重读）。
- **深链 `/add-bill/{BillId}`**：Web.Server 把 GUID 形式的旧地址 302 到 `/?add-bill={BillId}`；`AddBillSheet` 在首次渲染之后（预渲染没有 JS / 登录态）用 `AddBillSheetService.ReadOpenRequest(uri)` 读出请求——参数缺值 / `1` / `true` 是新建，非空 GUID 是编辑，其余忽略。
  非 GUID 写法（`/add-bill/abc`）不属于旧地址，不做 302，落到应用的「未找到」页。MAUI 宿主没有 HTTP 层，入口都是服务调用。
- **标题栏与删除入口**：编辑时标题是「编辑账单」，右上角**留空**（语音只用来预填新建，编辑里没有麦克风、没有语音状态行，也不会误触发）；「删除账单」是**内容最底部的红字行**（`ListCell Destructive`，`--ft-danger-text`，自成一组，在四行设置的下面）——
  破坏性操作不放在紧挨关闭钮的位置（早先版本是右上角垃圾桶，第 2 轮评审改）。点它先弹 `GlassAlert`（红色确认键）：「分类 · 备注，金额。删除后不再显示，并会随同步传播到其他设备。」，确认才软删除（`DeleteBillAsync`，同步状态变回待同步，删除随同步传播）；
  成功后收起 Sheet、Toast「账单已删除」、发 `BillChanged`（列表、汇总、统计重读）；账单已被别处删掉时 `DeleteBillAsync` 返回 false，Toast「账单不存在或已删除」，列表照样刷新。保存 / 删除进行中删除行置灰、关闭不可操作；
  **保存与删除互斥**（第 3 轮审查）：删除进行中点保存、保存进行中确认删除都直接忽略，不会对同一笔账单并行写库。
  账单读出来之前、以及它在「我是只读成员」的共享账本里时没有这一行（见下条）。
- **打开时只问清「这笔账单在不在、是不是自己记的」，写权限到保存时才查**：读账单在 `PageDataGate` 里完成。账单不存在 / 已软删除 → Toast「账单不存在或已删除」；不是自己记的（共享账本里其他成员记的）→ 与账单列表同一句只读提示；两种情况 Sheet 都收起，不留一个打不开的空壳。
  **没有写权限（例如被改成只读成员）的账单照常打开**，保存时才被拒绝（与旧编辑页一致）：保存先在本地校验目标账本的写权限（`EnsureCanWriteAsync`，读离线缓存），再交给 `BillService.UpdateBillAsync`——服务层认的是**原账本**，只读成员不能改只读账本里的账单（包括把它挪去自己的账本）。
  两处都抛 `ForbiddenAccessException`，界面 Toast「无权限编辑这笔账单：…」（带上服务层给的原因），Sheet 留着，**这是 403 语义，绝不登出**（CLAUDE.md 第 7 条）。
- **只读成员不能删除 / 批量归属只读共享账本里的账单**：规则只有一条——「生效的 Viewer 成员行 + 账本未删除 + 账本不是我的」才算只读（`LedgerMemberQueries.GetReadOnlyLedgerIdsAsync`，客户端与服务端同一份查询；被移出 / 退出 / 待确认的成员、账本已删除、历史无账本的账单都不算，它们仍可管理）。
  `BillService.DeleteBillAsync` / `AssignBillsToLedgerAsync`（整批拒绝）/ `UpdateBillAsync` 命中就抛 `ForbiddenAccessException`，REST 的 `PUT` / `DELETE /api/bills/{id}` 返回 403；界面据 `ILedgerMemberService.GetReadOnlyLedgerIdsAsync` 不给入口：账单 Tab 里这类账单没有左滑「删除」、不能多选，编辑 Sheet 没有「删除账单」行。
  为什么服务层也拦：删除 / 修改要随同步推到云端，云端对只读成员的推送一律拒绝，放行只会留下「本地已删 / 已改、云端还是原样」永远对不上的账单。
- **预填与「有没有改过」**：金额走 `AmountInput.FromDecimal`（整数不带小数点，有小数补满两位：88.5 → `88.50`；超上限夹到上限，多余小数四舍五入）、类型、分类、支付渠道、账本、时间（库里 UTC → `AppTimeZone.ToLocal` 的墙上时间）、备注。预填完记下快照 `BillDraft`
  （金额规整到 2 位小数、时间精确到分钟、备注 Trim 且空白算空、账本 `Guid.Empty` 算无），之后与当前表单的 `BillDraft` 比较——`NeedsConfirmClose`：改了才拦截关闭（「放弃修改？」/ 本次的修改不会保存。/ 继续编辑 / 放弃），改了又改回原样视为没改。
- **没改动也照常写库**：保存就是「按现在的内容再存一次」（与旧编辑页一致，第 2 轮评审用户拍板）——同步状态变回待同步、修改时间更新，Toast 同样是「账单已更新」。早先版本是「与快照相同直接收起 + Toast「没有修改」」，为的是不无谓地变回待同步、不刷新 `UpdatedAt`（「后写入优先」下可能盖掉别的设备上的真实修改）；
  取舍后选了行为简单、与旧页一致，代价是「没改也点保存」会多一次待同步。`BillDraft` 快照只留给「关闭确认」判断有没有改过。
- **保存沿用旧逻辑**：`EnsureCanWriteAsync` → `BillService.UpdateBillAsync`（不动数据来源、同步状态变回待同步）→ 预算预警（支出）→ 闸门之外 `BillEvents.NotifyBillChanged()`；Toast「账单已更新」（旧页是「账单更新成功」）。
  账本必填同新建：历史无账本账单、账本已被删除的账单（本地读不到它，当作没有账本）账本行显示「请选择账本」、保存键置灰、点按置灰的保存键抖动账本行并弹出账本菜单，补选账本后才能保存。
- **切换账单类型记住各自选中的分类**（新建与编辑都是）：每种类型各记一个当前分类，来回切不丢；没选过的类型取用户默认分类 / 第一项。
- **刻意没做的**：账单的分类 / 支付渠道已被软删除时不强制重选——EF 的全局过滤加上 `Bill→Category` 必填导航，让这种账单根本读不出来，而分类被未删除账单使用时服务层又拒绝删除，这个场景不可达，写了也测不到。

### 19. 语音记账覆盖层（17 号 ticket 起）

- **覆盖层只管展示，识别逻辑与状态仍在 Sheet 里**：`VoiceOverlay` 是 `AddBillSheet` 的子组件（`position: fixed` 盖满屏幕），参数是展示快照（是否按住形态、是否已说完、是否最终结果、是否在取消区、转写文本、高亮片段、芯片），
  对外只有 `OnFinish` / `OnCancel` 两个事件；一切识别流程（`VoicePhase`：`Idle → Listening → Parsing`）在 `AddBillSheet.Voice.cs`。展示规则（标题 / 提示 / 说明文案、转写按命中片段切段、芯片、上滑取消阈值、波形参数）是纯函数 `VoicePresentation`，单元测试覆盖。
  层级 `--ft-z-voice` 127：Sheet 120 < 弹出菜单 125 < **语音 127** < Alert 130 < Toast 1100（识别失败的 Toast 要看得见；`DesignTokensTests` 校验这条链）。隐藏时不立刻卸载：保留 `LeaveMs`（= `--ft-dur-fade` 180ms，单元测试校验同值）的淡出，期间保持最后一帧、不再响应、读屏忽略。
- **两种形态，沿用原来的两种识别方式**：**按住**（MAUI 原生流式识别，`SupportsHoldToTalk`）——手指一直按在标题栏的麦克风上，覆盖层只是反馈（`pointer-events: none`，手势仍由那颗按钮接收）；上滑 ≥ 56px 或朝任意方向滑开 ≥ 120px 进入「取消区」（覆盖层泛红、提示变「松开手指，取消本次语音」），
  滑回阈值内退出取消区，**松手时按所在区域决定取消还是预填**；原来的「滑出按钮即取消」（`pointerleave` / `pointercancel`）保留为兜底（有的 WebView 不给被捕获的指针发 move）。**点按**（浏览器 Web Speech，没有「按住」这个动作）——大麦克风是「说完了」按钮（点一下结束并出最终结果），底部多一个「取消」，Esc 同样取消。
- **实时转写与高亮是「预览」，预填只发生在最终结果之后**：浏览器识别器改为 `interimResults = true`，部分结果经 `OnPartialText` 回到 .NET（原生本来就有 `PartialResultReceived`）；每来一段部分结果就用**同一个** `BillVoiceParser` 解析一次，认出的金额 / 分类 / 支付渠道 / 时间在转写里用淡紫色 + 下划线高亮并列成芯片
  （`VoicePresentation.Live`：高亮只保留「有芯片的字段」，分类不属于识别出的账单类型时既无芯片也不高亮——高亮的就是会被预填的）。解析是异步的，用序号丢弃慢回来的旧结果；预览失败不打断识别。
- **高亮靠解析器新增的 `Matches`，解析规则一字未改**：`ParsedBillDraft` 加了只增不改的 `Matches`（`VoiceMatchSpan(Start, Length, Kind)`），由 `BillVoiceParser.LocateMatches` 用解析器**自己的词表与正则**把已解析出的字段回溯到原文里的位置（金额取最早出现的写法、时间取命中的相对日期说法、分类 / 渠道取全名或最长的同义词）；
  `Amount / Type / TransactionTime / CategoryId / PaymentChannelId` 的取值逻辑与既有单元测试保持不变，`BillVoiceMatchSpanTests` 另外覆盖定位。
- **取消的语义**：取消 = 丢弃，不预填、不提示。浏览器端 `cancelRecognition()` 先置 `cancelled` 再 `abort()`，识别器迟到的任何结果 / 错误都被静默丢弃；.NET 端阶段已回到 `Idle`，迟到的 `OnVoiceTextReceived` 同样直接返回。**最终结果一旦到手（表单已预填、覆盖层在做收尾停留）就不能再取消**。
  识别超时（点按 15s、按住 60s）、Sheet 被收起 / 卸载时也走同一条取消路径，不会留下一直收音的识别器。
  **迟到的最终结果不串会话**（第 3 轮审查）：最终结果的处理（解析 → 预填 → 停留 450 ms → 收起覆盖层）跨几个 `await`，开始时记下 `_voiceGeneration`，每个 `await` 之后比较；新会话开始 / 会话结束 / 销毁都会推进它，所以 Sheet 收起又重开之后，迟到的这一份既不会写进新会话的表单，也不会把新会话的覆盖层收掉。
- **布局不跳动**：转写区固定 3 行高（114px，`--ft-voice-transcript-height`），文字在其中垂直居中；说得更长时 `VoicePresentation.Segments` 只留末尾 30 个字（最窄 320px 屏每行也放得下 10 个字，单元测试校验）、前面补「…」，完整文本照常进备注（`RawText`）。
  芯片区预留两行高（86px），识别到一项出现一枚（`@key` 保持元素身份，只有新增的才播放弹入）。E2E 校验空状态与有内容时各区域的位置完全一致。
- **玻璃层预算**：覆盖层是整屏唯一的新玻璃层（`blur(28px) saturate(140%)`），Sheet 打开时标题栏已有 2 个圆钮，加上它恰好 3 层；芯片只是半透明填充 + 描边，大麦克风是实色渐变，都不模糊。单元测试（`.ft-voice*` 里只有 `.ft-voice` 带 `backdrop-filter`）与 E2E（整屏恰好 3 层）双重守住。
- **贴近设计稿的浅磨砂，用「大号文字」补对比度（第 2 轮评审，用户拍板）**：设计稿 06 的底是偏白的灰紫磨砂（对设计图取样约 RGB (128–141, 124–139, 131–163)），白字在上面只有约 3.3–3.9:1、淡紫高亮只有约 2.4–2.8:1。
  交付时先落地的是深靛紫 78%（白字 ≥ 4.5:1，但比设计稿暗、饱和得多），评审时用户选了「贴近设计稿的浅磨砂，小字加大加粗来补对比」，现在是靛紫 60%（`--ft-voice-bg`，叠在纯白上约 RGB (128, 124, 162)，与设计稿取样一致）；
  取消区的泛红底同步变浅（`rgba(110, 24, 32, .62)`）。代价与补法：**透上来的页面纯白（最不利）时白字约 4.0:1、淡紫高亮 `#EAE6FF` 约 3.3:1**，到不了正文的 4.5:1，所以——
  ① 直接压在覆盖层上的小字（状态「正在聆听…」、转写占位、手势提示、底部说明、「取消」）一律放大加粗成**大号文字**（`--ft-type-voice-status` / `--ft-type-voice-note` = 700 19px，≥ 18.66px 且 ≥ 700，WCAG 对大号文字只要求 3:1），转写本来就是 800 28px；
  ② 已识别芯片（仍是 15px）换成**深色半透明底**（`--ft-voice-chip-bg` = 靛紫 34%，设计稿里芯片本来就比四周更深），白字约 5.8:1，仍按正文的 4.5:1 要求；③ 提示色 `--ft-voice-text-2` 的不透明度从 .88 提到 .92；淡紫高亮从 `#DCD6FF` 提亮到 `#EAE6FF`（再深在浅磨砂上就低于 3:1，也就和白字更接近，**颜色之外的下划线 / `data-kind` 才是主要线索**）。
  底部说明变大之后「识别结果将预填到表单，确认后才会保存」一行放不下，用 `text-wrap: balance` 两行均分（不支持的 WebView 退回普通折行，只是可能多出一行短尾巴）。
  `DesignTokensTests` 逐项锁定：白字 / 提示色 / 高亮在纯白叠加后的底上 ≥ 3:1；三档语音字体令牌必须是大号文字，且 `.ft-voice__status / __placeholder / __text / __hint / __foot / __cancel` 的规则确实用这三档令牌（防止某处另写一个小字号绕过去）；芯片白字 ≥ 4.5:1。E2E 的 a11y 扫描（`a11y_degradation_test.py`）再用截图像素复核。
  **「降低透明度」下的降级分支保持深色不透明底**（`--ft-voice-bg-solid` #3A3178、取消区 #6B1C26，关掉模糊，白字 ≥ 4.5:1、不依赖大号文字），令牌在 `@media (prefers-reduced-transparency: reduce)` 里一处切换——降级路径本来就该选最稳妥的可读性，不追求设计稿的观感。
- **减弱动态效果**：红点呼吸、波形起伏、光圈外扩都换成静态（波形保持钟形静态高度），覆盖层只做 100ms 淡入淡出，芯片不弹入。识别中（已说完）红点与波形暂停，大麦克风置灰（`aria-disabled`，不用 `disabled`——同保存键）、手势提示撤掉。
- **E2E 注入假的 `SpeechRecognition`**：无头 Chromium 里没有麦克风，用 `context.add_init_script` 在页面脚本之前装一个模拟 Chrome 行为的假识别器（`stop()` 之后把已听到的内容作为最终结果交出、`abort()` 触发 `aborted`、最终结果之后结束），
  真实的 `billVoiceInput.js` → `BillVoiceInputService` → Sheet → 覆盖层全链路照常运行，测试用 `window.__speech.say / fail` 代替「说话 / 识别器出错」。按住形态（原生）在 Blazor Server 宿主里没有，只能用单元测试（阈值与文案）+ 样式分支（用脚本改标记）+ 真机验收覆盖。

### 20. 预算页（18 号 ticket 起）

- **只换展示，预算规则与服务层一字未改**：总预算 + 分类预算、可按账本独立设置、同年月 / 同账本范围 / 同分类唯一（应用层校验）、超支 / 预警通知全部沿用 `IBudgetService`。页面只调既有的 `GetBudgetStatusAsync`（不再额外读 `GetBudgetsAsync`——编辑要用的字段状态里都有）与 `Create / Update / DeleteBudgetAsync`。
  指定账本时的口径沿用服务层：显示该账本的预算 + 全部账本的预算；不指定账本只显示全部账本的预算（账本级预算在对应的账本视图里才出现）。月份「按应用时区」：起始月取 `AppTimeZone.ToLocal(DateTime.UtcNow)`（旧页面用设备的 `DateTime.Now`），月份范围 2000–2100、允许未来月份（预算本来就有「提前给下个月定额度」的用法）；统计 Tab 与它不同：往后只到当月（`ShiftMonthUpTo`，未来没有账单，「下一月」在当月置灰——审查阶段按用户决定）。
- **展示规则是纯函数，组件只排版**：`BudgetPagePresentation`（总览取哪个总预算、「日均可用」、行名称 / 灰色小字 / 读屏名称、排序、整页模型）、`BudgetFormPresentation`（分段、文案、校验）、`BudgetPresentation`（07 号起：状态判定与行文字）、`RingGeometry`（环的几何），单元测试覆盖。
  - **总览取哪个总预算**：指定账本时优先用该账本自己的总预算，没有再用全部账本的；其余总预算进「其他总预算」分组（全部账本的在前）。只有分类预算、没有总预算时不画总览，出现「设置总预算」引导行——有了总预算才有环与「日均可用」。
  - **「日均可用」**＝总预算剩余额度 ÷ 本月剩余天数（含今天），四舍五入（远离零）到分；「今天是几号」按应用时区；只在查看**当前月份**、有总预算、剩余额度 > 0（没超支也没用完）时显示。是 spec 里允许新增的唯一预算相关提示，只读，不改任何预算规则。
  - **状态与「显示的百分比」同口径**：显示向下取整的整数百分比（79.6% 显示 79%、仍是「正常」，99.6% 显示 99%、还没「超支」），≥ 80% 接近上限、≥ 100% 超支；分类行按已用金额从多到少排（相同按分类名、账本名，顺序稳定）。
- **进度环 `ProgressRing`**：纯 SVG（没有脚本 / CDN 依赖，E2E 能直接读出进度），viewBox 100、半径 44、环宽 12（外径 ≈ 120pt 时 ≈ 14pt，孔直径 76%，环中心文字左右各留 12%）；12 点钟方向起、顺时针、圆角端点；弧长用 `stroke-dasharray`（写在样式里才有 500ms 过渡，「减少动态效果」下没有过渡）。
  环尺寸 `--ft-ring-size: min(120px, 33vw)`；窄屏（< 360px）总览卡改成上下排、筛选行折行，八位数的金额也放得下（金额 ≥ 12 个字符缩小一档，极端长的金额折到下一行右对齐，不冲出卡片）。根节点 `role="progressbar"` + `aria-valuenow`（整数）+ `aria-valuetext`（带状态文字）；状态不只靠颜色——环中心写「已使用 / 已用完 / 已超支」、「剩余」标签超支时变「超支」、行右上角写「剩余 / 仅剩 / 超支 / 已用完 + 金额」。
- **SVG 的过渡事件要在最外层拦下**：MASA Blazor 的 Transition 脚本在祖先元素上监听 `transitionend` / `transitioncancel`，并读 `e.target.className.split(' ')`；SVG 元素的 `className` 是 `SVGAnimatedString` 而不是字符串，所以进度环的弧每变一次就抛一次 `TypeError`（功能无影响，但是页面错误、污染控制台，E2E 的错误采集会失败）。
  `ui.js` 的 `UiRuntime` 在文档捕获阶段对 SVG 元素自己的过渡事件 `stopPropagation()`，MASA 的脚本读不到它；这是全局行为（以后任何带过渡的 SVG 元素都受益）。
- **整行可点，进度条不被嵌进按钮**：`BudgetRow` 给了 `OnClick`（预算页）时名称是一个按钮（读屏名称「编辑预算：名称，状态文字」），它的伪元素（`position: absolute; inset: 0; z-index: 1`——进度条也是定位元素，没有 `z-index` 会被后出现的进度条盖住）铺满整行：整行都能点、按下底色均匀铺满，而 `role="progressbar"` 的进度条不会成为按钮的子节点（按钮的子节点对读屏是「纯展示」，会吞掉进度信息）。
  总览卡本身不可点（环是 `progressbar`，同理），右上角显式的「编辑」按钮点击区域 44 × 44（负外边距把多出来的热区让回去，不撑高标题行）。每个左滑操作都有非滑动等价入口：点整行 / 总览「编辑」→ 编辑 Sheet；Sheet 里的「删除预算」→ 与左滑「删除」同一个确认 Alert。
- **新建 / 编辑是同一个底部 Sheet（`BudgetFormSheet`）**：顶部分段「总预算 | 分类预算」→ 金额（与「记一笔」同一套自定义数字键盘与 `AmountInput` 规则，不唤起系统键盘；保存键是键盘右侧高大的那一格，缺项时置灰是 `aria-disabled` 而非 `disabled`，仍可点——点了告诉用户缺什么）→ 月份（`PeriodSwitcher`）→ 账本（芯片，不选 = 全部账本；用户没有账本时整栏不出现）→ 分类（只有分类预算，支出分类芯片）→ （编辑）「删除预算」。
  **默认分段由入口决定**：右上角「＋」与空状态的「新建预算」——已有总预算默认「分类预算」、否则默认「总预算」；「设置总预算」引导行固定总预算；「新建分类预算」行固定分类预算。年月与账本沿用页面当前筛选（旧页面也是如此），表单里可改。表单只在 Sheet「由隐藏变为显示」的那一刻按目标初始化，之后页面重绘（比如列表在后台刷新）不会冲掉正在输入的内容。
- **校验提示分两类**：用户能立刻改的——缺金额「请输入预算金额」、缺分类「请选择分类」、重复预算、金额 / 年月不合法（服务层抛的 `InvalidOperationException` / `ArgumentException`，文案本身面向用户，重复预算沿用「该月份已存在相同的预算，请直接编辑」）——留在表单里（`role="alert"`），Sheet 保持打开，改一下再保存；意外错误（读写库失败）才 Toast「操作失败: …」。
- **保存成功后页面跳到刚保存的预算所在的月份**（账本级预算还切到该账本）再重读：表单里可以改年月与账本，不跳过去用户可能保存完却看不到它；全部账本的预算在任何账本视图里都可见，所以账本筛选保持不变。
- **写库也排进 `PageDataGate`**：Tab 根页面常驻、可能正在刷新，它们与本页共用同一个 scoped `DbContext`，不允许并行操作；`PageDataGate` 是单车道信号量（不可重入），所以保存与删除也走同一条车道，而不是只给读排队。
- **删除用 `GlassAlert` 确认**（红色确认键）：标题带名称「删除预算「购物消费」？」，说明「删除后这条预算不再统计，也不再提醒超支。已记的账单不受影响。」，确认才软删除（`DeleteBudgetAsync`）；从 Sheet 里删时 Alert（z 130）盖在 Sheet（z 120）之上，确认后 Sheet 一并收起。旧页面点垃圾桶就直接删，没有确认。
- **加载与失败**：骨架（总览卡 + 3 行）→ 内容 / 空状态 / 失败态（第一次就失败：整页「预算加载失败」+ 重试；已有数据时刷新失败保留旧数据、只给 Toast）；`_loadVersion` 让连续切换月份 / 账本时只采用最后一次的结果；`budgets-content` 的 `data-year` / `data-month` / `data-ledger` 是**已加载完成**的筛选，E2E 据此等待。
- **「日均可用」的提示条一度用独立的文字色令牌 `--ft-callout-warning-text`（#9A5000）**，没有复用 `--ft-warning-text`（当时是 #A15500）：16% 橙叠在页面背景上，#A15500 只有 4.39:1 < 4.5（`DesignTokensTests` 抓到），#9A5000 约 4.75:1。
  **23 号已把两个令牌统一**：`--ft-warning-text` 直接加深为 #9A5000（白底、徽标的 16% 橙浅底、叠在页面底色上的 16% 橙浅底上都 ≥ 4.5:1），独立令牌删除；首页 / 我的页里钉死 `rgb(161, 85, 0)` 的 E2E 同步改为 `rgb(154, 80, 0)`。
- **玻璃层预算**：预算页没有新增任何玻璃层——总览卡 / 行 / 提示条 / 环都是不透明或半透明填充，没有 `backdrop-filter`（`DesignTokensTests` 校验预算相关选择器都不带），整屏只剩导航栏的两颗圆钮。

- **只换展示，识别与入库规则一字未改**（唯一的行为变更见下面「短信识别页」一条：第 2 轮评审改成读取结果先进待确认账单）：通知栏 / 短信的捕获、`PaymentContentParser` 的解析、`PendingBillService`（独立的 `DbContext`、`PendingBillsChanged` 事件）、`BillService.CreateBillAsync`（账本必填、时间经 `AppTimeZone.ToUtc`）都没动；
  页面把「怎样把待确认项变成正式账单」收进纯函数 `PendingBillConversion`（分类 / 支付渠道的匹配、账单字段），展示规则收进 `PendingBillPresentation` / `SmsRecognitionPresentation`，单元测试覆盖，组件只排版。
- **「一键确认入账」与「修改后入账」并存**：设计稿 05 画的是一步入账；ticket 与 spec 要求确认前仍能修正金额 / 类型 / 支付渠道、账本必填。所以卡片上是「忽略 | 确认入账」两个按钮 + 账本芯片——「确认入账」用识别结果直接入账（分类取该类型下的「其他…」，支付渠道按名称匹配，账本取卡片上的账本芯片）；
  要修正就点卡片主行，升起「确认账单」Sheet（金额用与「记一笔」同一套自定义数字键盘，不唤起系统键盘）。短信识别页读到的短信也是先进待确认账单、再从这里确认（原来短信页自己的「手动补全」Sheet 已取消）。
- **不猜**：支付渠道没匹配到时，点「确认入账」不入账、也不报旧页面那句「无法匹配分类或支付渠道」，而是打开 Sheet，顶部提示「没能匹配到支付渠道，请选择一个再入账」、渠道行标红；置灰的「入账」键仍可点，点了引导（缺金额 → 金额抖动；缺渠道 / 账本 → 对应行抖动并直接弹出菜单）。
  分类不在 Sheet 里选——识别结果里本来没有分类，入账取「其他支出 / 其他收入」（卡片上显示的就是入账时会用的分类，看到什么入账后就是什么）；要改分类，入账后在账单里编辑。
  `PickCategory` 现在**优先取预设的「其他支出 / 其他收入」**，其次名称含「其他」，再次该类型第一个（旧页面是「名称含『其他』的第一个」，用户自建的「其他杂项」排在预设前面时会取到它）。
- **账本必填的三层拦截**：卡片上的账本芯片（默认账本，点它换；没有账本时是红色的「选择账本」）→ 没有账本时点「确认入账」弹出账本菜单（`LedgerMenu`，里面有「新建账本…」，行内建好后自动选中，不用离开页面）→ Sheet 里账本行同理；最后服务层 `BillService` 仍校验一次。只列用户**自己的**账本——通知 / 短信捕获的账单不自动记入别人共享的账本。
- **待确认项的时间是设备本地的墙上时间，不是 UTC**：通知 / 短信捕获时取的是 `LocalDateTime` / `DateTime.Now`，所以 `PendingBill.TransactionTime` 页面按原样显示（今天 / 昨天 HH:mm、同年「11月23日 09:05」、跨年带年份），**不再换算**；入账时由 `BillService` 经 `AppTimeZone.ToUtc` 变成账单的 UTC。
  这与 `Bills.TransactionTime`（一律 UTC）正好相反，E2E 的 `seed_pending_bill` 因此改用 `to_wall_time` 原样写入（原先按 UTC 写，卡片时间会差一个时区偏移）。
- **入账与移除不在一个事务里，失败要分开说**：账单已保存、但从待确认列表移除失败时，不能报「创建账单失败」（用户重试会重复入账）——当前页立刻去掉这张卡片，并提示「账单已创建，但从待确认列表移除失败……请点「忽略」，不要重复确认」。
  入账期间整张卡片的按钮禁用（`_busy`），连点只产生一笔账单；Sheet 保存期间不可下滑收起、不可重复提交。
- **自动识别状态：绿色细状态条 ↔ 权限卡片**：两项都开启是一条 15% 绿浅底的细状态条（「通知栏识别、短信识别均已开启」+ 右侧「设置」，`role="status"`）；有一项没开是分组卡片，两行权限行各带「去开启」，已开启的那行是对勾 + 「已开启」徽标；权限状态还没读出来之前什么都不渲染，免得先闪「未开启」再变「已开启」。
  通知使用权只能在系统设置里开：「去开启」跳到系统设置页并提示「开启后回到这里」（沿用 `OpenSettingsAsync`），短信权限则弹系统授权框。「设置」菜单（`ActionSheet`）通向通知使用权的系统设置与短信识别页。两种权限行与短信识别页的权限分组共用同一个 `CapturePermissionRow`。
- **短信识别页：设置式分组 + 固定在底部的主按钮**：权限分组 → 读取范围分组（开始日期默认 30 天前）→ 读取结果（「读取结果」摘要 + 每条短信一张卡片）；「读取短信」固定在页面底部（`.ft-pagefoot`，高度 `--ft-pagefoot-height`，内容据此留出底部空间）。
  开始日期看到的是「2026年10月26日」，真正的输入是盖在整行上的透明 `<input type="date">`（点按即唤起系统日期选择器，`max` = 今天），读取范围按**应用时区的日期零点**传给平台服务。
- **短信读取结果先进待确认账单（第 2 轮评审，用户拍板；这是 19 号唯一的行为变更）**：旧页面是点「创建账单」直接创建正式账单、根本不进待确认列表（ticket 文字「读取结果进入待确认列表」与现状不符，交付时按现状保留并请用户确认），现在改成与实时短信监听走同一条路——
  **读取失败（读短信抛异常 / 加入待确认时出了意料之外的错）退回读取前的引导状态**（第 3 轮审查）：Toast 说明原因，内容区不显示「未找到支付类短信」——「没读成」与「读了但没有」不是一回事。
  规则收进纯函数 `SmsCapture`（Web/Models，单元测试覆盖）：`PaymentContentParser` 解析出金额的才加入（识别不出金额的跳过，验证码 / 营销短信不会混进待确认列表；原「手动补全」Sheet 随之取消），经同一个 `IPendingBillService.AddAsync`
  加入（数据来源 = 短信识别、备注 = 短信原文、交易时间 = 短信时间——设备本地墙上时间，同上一条，不换算）。**去重**交给服务（来源 + 金额 + 交易时间 ±1 分钟），所以重复读取同一批短信、或读到实时监听刚捕获过的同一笔，都只会记为「已在待确认列表」。
  **容量**：待确认账单上限 `IPendingBillService.MaxCount`（200，满了服务会丢弃最早的一条）——批量读取先按剩余容量算「预算」，由新到旧加入、用完后剩下的计「列表已满，未加入」，重复的与写入出错的不占预算，**不会顶掉用户还没处理的待确认账单**；
  预算用完后不再调 `AddAsync`（它会丢弃最早的一条），但**已经在列表里的短信仍如实记为「已在待确认列表」**（第 3 轮回归发现：列表满了再读同一批，读过的那条会被误记成「列表已满」）——去重规则收进 Core 的 `PendingBillDeduplication`（一个表达式，`AddAsync` 交给数据库查询，短信页在列表已满时 `Compile()` 后在内存里判断，两边是同一个表达式，有单元测试锁住一致性）。注意库里的金额是文本（Microsoft.Data.Sqlite 把 decimal 存成 `0.0###…` 写法，`7.00` → `"7.0"`）：数据库侧按文本相等、内存侧按数值相等，只有库里写法与应用不一致（比如 E2E 直接往表里塞 `"7"`）时两边才会分歧，影响仅限「列表已满」时标签是「已在待确认列表」还是「列表已满」，不影响落库；
  捕获时间取短信时间（待确认列表按捕获时间倒序，仍按付款先后排；列表满了需要腾位置时，最早的付款最先让位）。单条写入出错记为「加入失败」并继续处理下一条，读不到现有条数时整批有金额的短信记为失败、不写入。
  页面上：「读取结果」摘要分组（新加入 / 已在待确认列表里 / 没识别出金额 / 待确认账单已满未加入 / 加入失败，各类有数才显示，脚注只写最需要用户知道的那一件事；「新加入待确认账单」一行点按去待确认账单页确认入账）+ 每张短信卡片右下角的去向标签（`ft-badge`，成功 / 中性 / 警告 / 危险四色）+ 读取后按结果分级的 Toast。
  **账本不在短信页选了**（账本行、账本菜单、行内新建账本、手动补全 Sheet 都已删除）——账本在待确认账单里确认入账时再选，账本必填在那里拦截。**已知取舍**：去重只对着待确认列表，**已确认入账的短信重新读取时会再次出现在待确认列表里**（不去查正式账单：那要新增「按金额 + 时间查账单」的能力并处理 UTC / 应用时区换算，超出本次重构范围；页面脚注只承诺「已经在待确认列表里的不会重复加入」）。
- **并发与读写**：待确认项走自己独立的 `DbContext`（`IDbContextFactory`，不占共享 `DbContext` 的队列）；账本 / 分类 / 支付渠道的读取与账单写入都排进 `PageDataGate`（与常驻 Tab 页共用同一个 scoped `DbContext`）。创建成功后经 `BillEventService.NotifyBillChanged()` 通知首页 / 账单 / 统计刷新；
  后台捕获到新支付（`PendingBillsChanged`）时列表实时刷新，页面销毁时取消订阅。
- **玻璃层预算**：这两个页面没有新增玻璃层——权限卡 / 状态条 / 待确认卡片 / 短信卡片都是不透明或半透明填充；整屏只有导航栏的返回钮与「全部忽略」，「确认账单」Sheet 升起时再加它自己的关闭钮，恰好 3 层（E2E 校验）。
- **对比度**：状态条文字用 `--ft-capture-ready-text`（#0F6B2E）——`--ft-ink-green` 叠在 15% 绿底上只有约 3:1；账本芯片没选账本时的浅红底 `--ft-pcard-missing-bg`（10%）配 `--ft-danger-text`（12% 的底上只有 4.46:1）。两者都由 `DesignTokensTests` 逐项计算。
- **窄屏（320pt）**：卡片里账本芯片独占一行、「忽略」「确认入账」平分下一行；金额文字 ≥ 11 个字符缩一档（八位数的金额也放得进一行）；导航栏居中的标题再宽就会被右侧「全部忽略」压到，所以窄屏下导航栏右侧的文字胶囊（`.ft-nav__side--end` 里非圆形的按钮）内边距由 20 收到 12。
- **E2E 的原生能力假实现**：浏览器里没有通知使用权、读不到短信，Web.Server 在开发环境（Development）下配置 `E2E:FakeCapture=true`（仅 `tests/e2e/server.ps1` 打开；`/__e2e/*` 端点没有认证，所以生产环境即便误带了环境变量也不注册）时把 `ISmsService` / `INotificationListenerPermissionService` 换成进程内的假实现（`E2ECapture.cs`），E2E 经 `POST /__e2e/capture` 设置权限与「读到的短信」、经 `GET` 核对平台服务被调用的次数；
  不打开这个开关时端点不存在、行为与改造前完全一致（空实现），MAUI 应用不引用它。

### 22. 导入账单（20 号 ticket 起）

- **只换展示，解析与导入规则一字未改**：微信 / 支付宝 CSV 仍由**云端**解析（`CsvParserService`），页面只调既有的 `api/import/{wechat|alipay}/preview` 与 `api/import/{wechat|alipay}`。
  时间口径沿用 ADR 0005：CSV 里的交易时间是不带时区的用户本地时间，导入请求上报 `UtcOffsetMinutes`（`AppTimeZone.GetUtcOffsetMinutes()`）、由服务端换算成 UTC 入库；**页面预览原样显示 CSV 里的时间，不换算**（预览不是库里的时间）。
  请求里唯一新增的字段是 `LedgerId`——接口早就要求账本必填，旧页面却从未带它（账本必填之后，旧页面其实已经导入不了）。
- **一个页面、四步 + 结果**：来源（微信 | 支付宝，`SegmentedControl`）→ 文件（一行 `ListCell`）→ 解析预览 → 导入到账本；后面的步骤在前面完成后才出现。阶段是 `ImportStage`（`Idle｜Reading｜Ready｜Parsing｜Failed｜Preview｜Importing｜Done`），经根节点 `data-stage` 暴露给 E2E。
  文案 / 汇总 / 预览行 / 失败映射 / 主按钮可用性都是纯函数（`ImportPresentation`），编码检测在 `CsvFileDecoder`，单元测试覆盖，组件只排版。
- **显式的「解析预览」按钮**（第 2 轮评审后用户拍板恢复；最初的实现是选完文件自动解析）：选好文件只读入、停在「已选文件」（`Ready`），**不自动向云端解析**；解析预览放在底部固定的主按钮上，同一个位置按步骤换动作——「解析预览」（没选文件置灰）→「解析中」→「导入 N 条账单」→「继续导入」，`data-action` = `parse｜import｜again`。已选了文件时换来源：已读入的文件保留（选错来源不必重新选文件），但原来的预览作废、回到「已选文件」，由用户再点「解析预览」按新来源解析。解析失败提示条里的「重试」保留，与底部「解析预览」是同一个动作（`ImportPresentation.CanParse` 同一条规则，连点两下只发一次请求）。读取 / 解析 / 导入进行中来源与文件输入禁用。
  文件太大（> 10 MB，读之前按大小拦）、文件不是账单、解析不出任何账单、云端不可用都停在第 2 步给出 `role="alert"` 提示，页面始终可操作（重试 / 换文件 / 换来源）；「重试」只在已经读出文件内容时出现。
  **`ParseAsync` 本身不判断「忙」，由入口（换来源、「重试」）各自挡住**：选文件走到解析时阶段已经是 `Parsing`（读取也算解析阶段，好让文件名先显示出来），里面再判断「忙」就会把自己挡在门外、永远停在「解析中」——这个缺陷单元测试与读代码都看不出来，是 E2E 第一次真实运行时才暴露的。
- **文件选择：透明的 `InputFile` 盖在整行上**（与短信识别页的日期行是同一套 `.ft-addbill__picker` 手法）：用户看到的是文件名 + 大小 + 右值「重新选择」，点按整行就是点文件输入，唤起系统文件选择器。`accept=".csv"` 只是选择器的过滤提示、不是校验，文件是否真的是账单以云端的解析结果为准。
  读完内容就 `@key++` 换一个新的文件输入（旧输入还留着上一次的值，同一个文件再选一次不会触发 change）。**编码检测规则与旧页面一致**（带 BOM 的 UTF-8 / UTF-16 LE / BE；无 BOM 且文本含「交易时间 / 交易类型」按 UTF-8；否则 GB18030；兜底 UTF-8），搬进 `CsvFileDecoder` 并补上单元测试；预览与导入提交的是同一份已解码的文本，导入不再重新读文件。
- **预览**：汇总用 `KpiCard`（支出 / 收入 / 结余，中性色，**针对全部账单**）+ 说明行（「共 N 笔账单 · 起 至 止」，日期取 CSV 里的原样；微信才有「另有 N 条中性交易 / 无效交易已跳过」，支付宝接口不返回跳过数）+ 明细（**最多 100 行**，页面写明「仅显示前 100 条，其余 N 条会在导入时一并导入」，账单很多时避免渲染几千行）。
- **账本必选，界面与接口各拦一道**：没选账本主按钮置灰（置灰就点不动），账本一行红字「选择账本」；账本菜单复用 15 号的 `LedgerMenu`，里面有「新建账本…」，就地建好后自动选中。只列用户**自己的**账本（`LedgerModel.LoadOwnAsync`，与待确认账单 / 短信识别同口径：不在用户没选的情况下往别人的共享账本里导入）；
  默认选用户设置的默认账本，否则第一个自己的账本，所以界面上「没选账本」只发生在用户一个账本都没有时。
- **导入前先尽力同步一次账本**：导入写入的是云端数据库，刚在本机建好的账本云端还不认得（会 400「账本不存在」）。导入前调一次 `SyncService.SyncLedgersAsync`，**失败不拦截**——账本已在云端时照常导入，确实缺失时由服务端明确报错。这是既有行为的补救，不改同步规则。
- **失败留在预览阶段，且区分「一定没写入」与「不知道有没有写入」**：预览与账本选择都保留，页面里出一张提示卡（`role="alert"`）+ Toast。云端**明确拒绝**（401 / 400 / 403 / 404 / 409 / 422）只给原因；其它（5xx、超时、连不上——请求可能已经到了云端）追加「云端可能已经收下了部分账单，请先到账单列表确认，再决定要不要重新导入」。
  导入不做去重，盲目重试会重复入账，所以这句提示是必要的。面向用户的文案经 `ImportPresentation.DescribeFailure` 生成，不泄露内部异常信息（5xx 一律「云端服务暂时不可用，请稍后重试」）。
- **结果页与导入后的同步**：导入成功后页面换成结果——状态图标 + 标题（「导入完成」｜「部分账单导入失败」｜「没有账单导入成功」）、账本 / 总计 / 成功 / 失败的分组列表、失败详情（云端最多回 10 条）、「同步到本机」一行。
  成功笔数 > 0 时自动同步一次（`SyncService.SyncBillsAsync`，保持「同步由用户手动触发 + 导入后自动一次」的现状）并 `BillEventService.NotifyBillChanged()`，账单 / 首页 / 统计随之刷新；同步失败不影响导入结果，只在那一行与 Toast 里说明，用户可稍后在「我的」页点「立即同步」补拉。底部主按钮变成「继续导入」，回到第 1 步（来源与账本沿用，文件与预览清空）。
- **读写与过渡**：账本读取经 `PageDataGate`（常驻 Tab 页与二级页共用同一个 scoped `DbContext`）；读取结束之前账本一行显示「加载中…」，不会先闪「加载失败」或红色的「选择账本」；账本读取失败不能当作「还没有账本」。
  导出说明默认收起（点开才展开，路径与格式提示随来源切换），箭头转向用 `--ft-dur-press` 过渡，减弱动态效果下没有过渡；「同步到本机」行进行中图标转圈（减弱动态效果下放慢，仍是「正在同步」的唯一视觉反馈）。
- **玻璃层预算**：导入页没有新增玻璃层——整屏只有导航栏的返回钮与底部固定的主按钮栏（`.ft-pagefoot`，不带 `backdrop-filter`），E2E 校验每个状态都 ≤ 3；提示卡用白底红字（`--ft-danger-text` 在白底上 ≥ 4.5:1，`DesignTokensTests` 锁定），不用红色浅底（约 4.1:1，达不到）。
- **窄屏（320pt）**：「重试」折到提示文字下面，预览行 / 账本行 / 汇总三栏 / 结果行都不冲出屏幕，导航标题与返回钮不重叠，主按钮高度 ≥ 44（E2E J 节逐元素核对）。

### 23. 自定义报表（21 号 ticket 起）

- **只换展示，统计口径一字未改**：数据仍是 `IStatisticsService.GetCustomStatisticsAsync`（KPI / 分类排行 / 收入与支出分类汇总）+ `GetCategoryComparisonAsync`（分类环比），入参仍是「应用时区自然日的起止日期 + 账本（null = 全部账本，含历史无账本账单）」，统计服务把区间当作含两端日、换成 UTC 的左闭右开区间去查库（ADR 0005），页面不做任何时区换算。
  唯一的口径修正是「今天」：旧页面用 `DateTime.Now`，运行环境时区与应用时区不一致时会差一天，现在取 `AppTimeZone.ToLocal(DateTime.UtcNow).Date`。
  报表里没有「按账本」的汇总（旧页面也没有），所以不存在「未归属账本」这一行；历史无账本账单只是包含在「全部账本」里（选了具体账本则不含）。
- **一个页面、自上而下**：快捷区间（芯片）→ 报表范围分组（开始日期、结束日期、账本，三行 `ListCell`）→ 校验提示 → 结果 → 底部固定的主按钮「生成报表」（`.ft-pagefoot`，生成中置灰并转圈）。页面是二级页面模板（Tab 栏隐藏），统计 Tab 右上角压栈 `/custom-report`，返回回到统计 Tab 停留的分段。
  展示规则（快捷区间、校验与文案、说明行、环比各行、CSV、分享文字）全是纯函数（`CustomReportPresentation`），单元测试覆盖，组件只排版。
- **日期用系统日期选择器**：与短信识别页同一套手法——用户看到的是「2026年11月1日」，真正的输入是盖在整行上的透明 `input[type=date]`（`.ft-addbill__picker`），点按整行唤起系统选择器；日期的解析 / 文案在两处共用的 `DateInputPresentation` 里。
  `min` / `max` 取 2000-01-01 ～ 2100-12-31（与统计 Tab 的年份范围一致），统计服务回推「上一等长周期」时才不会下溢出 `DateTime.MinValue`。浏览器允许清空日期：清空 = 没选，行右值显示红字「请选择」，**不悄悄沿用旧值**（否则行上写的日期与输入控件里的不一致）。
- **输入不合法在页面里说明，不等点击后弹 Snackbar**：没选开始 / 结束日期、超出可选范围、结束早于开始，分组下面用红字（`.ft-form-error`，`role="alert"`）写明原因，主按钮同时置灰，强行触发也不会生成；已有的结果不会被清掉，改对之后立即恢复。
- **快捷区间点一下只填日期、不立刻生成**（与旧页面一致）；它「亮起」不是记下点过谁，而是**每次按当前起止日期重新判断**是否正好等于某个快捷区间——所以手动把日期改成与「本月」一样时它也亮，改成别的就都不亮，不会出现「亮着本月、日期却是别的」。
  算法沿用旧页面：本月 = 1 日 → 今天；上月 = 上月 1 日 → 上月最后一天；近 30 / 90 天 = 今天往前 30 / 90 天 → 今天（含两端，所以实际是 31 / 91 个自然日，与统计 Tab 趋势的「最近 30 天」同一算法）。
- **结果是生成那一刻的快照**：参数（含账本名）在生成时取一次，之后改日期 / 账本不会动已有结果，说明行（「区间 · 账本 · 共 N 笔账单」）写明了它的范围，用户改了参数还没重新生成时也看得出眼前是哪一份。再次生成失败时保留旧结果、只弹 Snackbar；从来没成功过才显示「报表生成失败」占位。
  **生成前 `await Task.Yield()`**：本地 SQLite 的异步查询常常同步完成，不让出的话「生成中」这一帧永远渲染不出来（按钮没反应、也没有骨架），用户会觉得没点上——这是 E2E 用 `MutationObserver` 抓「生成中」那一帧时才暴露的。
  根节点的 `data-generation`（已结束的生成次数，成功 / 失败各算一次）让测试等「这一次生成结束」，不靠固定延时。
- **结果卡片沿用统计的组件**：KPI 单卡（`KpiItem.Summary`，与统计 Tab 同一张；栏标题是「支出 / 收入 / 结余」，旧页面的「总支出 / 总收入 / 净收支」随之统一，**导出与分享文字里的「净收支」保持原样**）、分类环比（`GroupedList`，每行图标块 + 名称 + 「¥500.00（上期 ¥400.00）」 + 右侧变化块）、分类排行（`CategoryRankChart` Top 8）、
  支出构成与收入构成各一张圆环 + 图例（`DonutChart` + `LegendList`，取代旧的双环组件 `ExpenseIncomeDonutChart`，信息不丢；旧的 `ChartCard` / `ExpenseIncomeDonutChart` 随旧页一并删除）、「导出与分享」分组两行。
- **环比的规则与颜色**：沿用统计模型给的变化率；上期没有这个分类的支出 = 「新增」（按「涨」画向上箭头）；否则显示带符号的一位小数（`+50.0%` / `-50.0%`；本期归零 = `-100.0%`），箭头与语义色按「支出变多是坏事（红）、变少是好事（绿）」，按显示的一位小数判断，所以 `0.0%` 永远是持平。
  行顺序沿用统计服务（变化金额绝对值从大到小，同值稳定）。**顺带修了统计服务的一个缺陷**：只在上一周期出现的分类（本期归零）原先被命名为「未知分类」，现在取上一周期里它自己的名称与图标。
- **导出 CSV**：内容仍是「区间 / 总支出 / 总收入 / 净收支 / 账单数量」+「分类, 金额, 笔数, 占比(%)」的支出分类汇总，文件名仍是 `custom_report.csv`；选了具体账本时多一行「账本」。三处改正——
  ① 金额一律是不带千分位的两位小数（旧版 `:N2` 的 `1,234.50` 里的逗号会把一个金额劈成两列）；② 含逗号 / 引号 / 换行的文字（用户自建的分类名可以是任何字符）按 RFC 4180 加引号转义；③ 换行固定 CRLF，不随运行平台变化。
  下载走 `ui.js` 的 `downloadText`（Blob + 隐藏的 `a[download]`，文件开头加 UTF-8 BOM 让 Excel 打开中文不乱码），取代旧版的 `eval` + data URI（没有长度上限与转义问题，也不依赖 `eval`）。
- **分享摘要**：文字格式沿用旧页面（【记账报表】区间 → 总览 → 支出 Top3 → 环比增长最多 / 减少最多），选了具体账本时标题行加「 · 账本：xxx」，金额统一用 `MoneyPresentation`（千分位、两位小数，负数是「-¥…」而不是「¥-…」）。
  分享走 `ui.js` 的 `shareText`，返回 `shared｜copied｜cancelled｜unsupported` 交给页面决定提示：**用户主动关掉系统分享面板不是失败，也不退到剪贴板**（旧版会落到复制分支，在用户不想要的时候改掉他的剪贴板）；没有系统分享才复制并提示「已复制」；两条路都不通才提示不支持。
- **玻璃层预算**：没有新增玻璃层——整屏只有导航栏的返回钮与底部固定的主按钮栏（`.ft-pagefoot` 不带 `backdrop-filter`），E2E 校验各状态 ≤ 3；内容底部留出主按钮栏的高度，滚到底最后一节不被它盖住。
- **窄屏（320pt）与共享件的修正**：320 宽时 KPI 卡每栏只有约 96pt，14 个字符的金额（`¥98,765,432.10`）在原有的 14px 下比栏还宽。新增令牌 `--ft-type-amount-summary-xlong`（12px）与 `@media (max-width: 359px)` 规则，
  只作用于「金额位数很多」的 `.ft-amount--long` KPI 金额——`KpiCard` 是统计 Tab / 导入 / 报表共用的，三处一起受益。E2E 的 G 节逐元素核对三种状态（空闲 / 不合法 / 有结果）不溢出、不重叠，长账本名与长分类名换行。

### 24. 登录页与错误日志（22 号 ticket 起）

- **登录页只换外观，认证一字未改**：手机号手动输入、无验证码、首次使用自动注册、会话存本机、云端令牌与手机号绑定的规则都没动——页面仍是 `AuthService.RegisterOrLoginAsync` → `AuthStateService.SaveUserInfoAsync` → 回首页（`replace`），失败仍走错误 Toast「登录失败: …」。
  唯一新增：提交前去掉手机号首尾空格（与账本成员页邀请手机号同一做法）。页面上的文案与「手机号怎样才算合法」集中在 `LoginPresentation`（纯函数，单元测试覆盖），规则仍是登录与邀请成员共用的 `PhoneValidator`。
- **布局**：用 `AuthLayout`（没有页面栈、没有 Tab 栏）；根节点占满整屏高度、自己纵向滚动；渐变背景铺到屏幕最顶端（含状态栏之下），根节点声明 `data-statusbar-bg="dark"`（02 号的约定：状态栏用白色图标）。
  上方是品牌区（玻璃 Logo + 应用名 + 标语），下方是贴底的白色圆角面板（手机号输入、校验提示、「登录 / 注册」主按钮），面板底部让出手势条安全区。
  **软键盘弹出、可视高度变小时，品牌区先被压缩（超出的部分被裁掉），面板与按钮始终在可视范围内**；极矮（横屏 + 键盘）面板放不下时整页滚动。这是网页层的结构保证，**真机软键盘的实际表现**（WebView 是否缩小视口、是否把聚焦的输入框滚进可视区）归人工验收。
- **校验提示预留一行高度**：输入框失焦（先于点按钮发生）时提示才出现，位置一动，随后的点击就落空了。校验在提交时进行（空 / 位数 / 格式，文案沿用旧规则），不边输入边报错；用户继续输入，旧提示立刻消失。
  提示 `role="alert"`（出现时读屏立刻播报），输入框带 `aria-invalid` / `aria-describedby`，出错时输入条红描边（`--ft-danger-text`），校验失败后把焦点还给输入框。
- **手机号输入框是「不受控」的**：不把 `_phone` 回写成 `value`（与搜索框同一做法）。Blazor Server 下 `@oninput` + 回写 `value` 在敲得快时会用往返之前的旧值盖掉用户在往返期间继续敲的字（字符丢失 / 闪烁）——
  这个缺陷读代码看不出来，是 E2E 第一次真实运行时暴露的（「按键输入最多 11 位」读到空值）。`type=tel` + `inputmode=numeric` + `enterkeyhint=go` + `autocomplete=tel-national`；字号 18px（≥ 16px，iOS 聚焦不放大页面）；`maxlength=11` 沿用旧页面。
- **玻璃层预算**：整页只有 1 个玻璃层（Logo，`.ft-glass-dark`）；背景的三个圆球是纯渐变（不模糊、不占预算）。面板是不透明白色。
- **错误日志页按二级页面模板重做，功能不减**：右上角「⋯」（`PopoverMenu`）收起 筛选 / 刷新 / 导出日志 / 清除日志——清除是红色（`PopoverMenuItem.Danger`），点后用 `GlassAlert`（破坏性）确认；没有日志时导出 / 清除置灰。
  页面自上而下：概览三栏（总日志数 / 今日 / 本周，口径是全部日志、不受搜索与筛选影响）→ 级别分布 → 时间范围 → 搜索框（`SearchField`，匹配消息 / 异常类型 / 来源 / 完整信息，不区分大小写，停顿 350 ms 提交）→ 条件条（`ConditionChip`：点文字 = 打开筛选 Sheet 调整，点 × = 单独移除，「清除条件」保留搜索关键字）→
  按天分组的设置式列表（行 = 级别图标块 + 标题 + 「时间 · 级别 · 来源」+ 箭头）→「加载更多」（每页 20 条，跨页的同一天合并成一组）。**点一行弹出半屏详情 Sheet**（时间含毫秒 / 来源 / 异常类型 / 消息 / 完整异常信息 / 上下文 / 复制），取代旧页面的「行内展开」；Sheet 的高度由内容决定（`BottomSheet` 的通用规则，最高到状态栏下方留 12 的缝），内容少时是半屏。
  筛选是一个 Sheet（级别多选 + 起止日期，编辑草稿、点「查看日志」才生效；放弃改动 = ✕ / 遮罩 / Esc）；结束日期早于开始日期时在下方给提示并置灰「查看日志」（旧页面不校验，结果是一片空白却不说为什么）。
- **展示规则全是纯函数**（`LogViewerPresentation` / `LogMessageTemplate`，单元测试覆盖）：分组与组头、行标题 / 副标题 / 读屏名称、级别样式、条件标签、空状态文案（「没有日志」是好消息、「没有符合条件的日志」要另说）、复制文本、导出提示；组件只排版。
  **服务接口（`ILogViewerService`）没变**，页面只多读一次概览；级别只列日志里出现过的 + Fatal / Error（旧页面的「Critical」对不上 Serilog 写的 `Fatal`，过滤永远选不中）。
- **数据层顺带修了四处既有缺陷**（都是只有造出真实日志文件才暴露的）：① 应用用 `CompactJsonFormatter` 写日志，只有模板 `@mt` 与分列的属性、没有渲染好的 `@m`，旧解析读 `@m`，**每条日志的「消息」都是空的**——现在自己把属性代入模板（`LogMessageTemplate.Render`：识别 `{名字}` / `{@名字}` / `{$名字}` / `{名字,对齐:格式}`——只代入属性值、不套对齐与格式——与 `{{` `}}` 转义；找不到的属性原样保留 `{名字}`，与 Serilog 自己渲染缺失属性一致）；
  ② 日志级别与过滤器不一致（见上一条）；③ 导出到还不存在的目录必然失败——先建目录；④ **真机上日志页读的目录与 Serilog 写的不是同一个**：取目录用的 `#if ANDROID || IOS` 写在不引用 MAUI 的类库里，永远不会编译，日志页在真机上读的是桌面默认目录、永远是空的——
  现在 `LogViewerService` 接收目录参数，MAUI 宿主（`MauiProgram`）传 Serilog 写日志用的 `FileSystem.AppDataDirectory/Logs`，Web.Server 不传（桌面默认目录）。④ 无法在 E2E 里验证，归真机人工验收。
- **导出仍只按日期范围**（服务接口没有级别 / 关键字参数，与改造前一致；页面不改接口），写到本机缓存目录并在 Toast 里写出路径；这个路径在真机上是否用户可达、是否需要原生的保存 / 分享通道，与 21 号的 CSV 下载同属待判断。
- **时间口径**：日志时间戳是 Serilog 写的 UTC，解析后按**机器本地时区**显示、分组的「今天 / 昨天」也按本机日期——沿用旧实现，没有走 `AppTimeZone`（日志不是账单，不涉及统计边界；应用时区默认就是运行环境本地时区，两者一致）。若以后允许用户改应用时区，日志页需要一并改走 `AppTimeZone`，见待判断项。
- **E2E 的专用日志目录**：Web.Server 自己不写文件日志，E2E 得往目录里写日志行造数据，而「清除日志」会删掉目录里的 `app-*.log`——绝不能碰开发机上真实的日志。开发环境下配置 `E2E:LogDirectory`（仅 `tests/e2e/server.ps1` 设置；生产环境误带该变量也不生效，免得「清除日志」删到真实日志）时 Web.Server 的 `ILogViewerService` 读那个专用目录并暴露 `GET /__e2e/log-directory`；
  不设置时端点不存在、行为与改造前一致，MAUI 应用不引用它（与 `E2E:FakeCapture` 同一套做法）。

  也正是降级路径下加载页方块的颜色（见下）。
- **两个新令牌，散在多处的取值必须一致**：`--ft-splash-bg` / `--ft-splash-tile`。底色在 `tokens.css`、`FinanceTracker.App.csproj` 的 `MauiSplashScreen` 与 `MauiIcon` 的 `Color`、`MainPage.xaml` 的 `BackgroundColor`
  （WebView 画出来之前露出来的就是它）各写一份；方块在 `splash.svg` 与 `.ft-boot__logo`（96 / 30）；钱包图形（MDI `wallet-outline`）在应用图标前景、`splash.svg`、两个宿主页里各抄一份——
  改一处漏另一处，真机上就是一道色差或一次跳变，`DesignTokensTests` 逐项守住。应用图标一并换成同一个 Logo（渐变背景层 + 白色钱包前景层），点开图标不再变色；旧的 `appicon.png` 删除。
- **加载页是纯 HTML + CSS，标记写在 `#app` 之外**：`#ft-boot` 放在两个宿主页（MAUI `index.html`、Web.Server `_Layout.cshtml`，标记一字不差，单元测试逐字比对）里 `#app` 的旁边，不依赖网络与脚本就能出现；
  Blazor 一启动就接管 `#app`，所以加载页必须由 `wwwroot/js/boot.js` 在首屏就绪之后才收走。样式 `boot.css` 加载在 `ui.css` 之后（§2 的加载顺序在末尾追加这一项）；层级盖过 Toast（`--ft-z-toast + 1`）；旧的「正在加载…」文字删除。
  **玻璃层预算**：整屏只有 Logo 方块一层玻璃（沿用 `.ft-glass-dark`，与登录页同一块）。
  **降级时方块不跟着令牌变色**：令牌层的三条降级路径（§26：系统「降低透明度」/ 根开关 `data-ft-solid` / 不支持 `backdrop-filter`）会把深色玻璃换成另一个实色（`#6A42F2`），
  而系统启动画面里的方块只能是 `--ft-splash-tile`（`#7E3EFF`）——换色放在加载页上就是一次色跳；更要紧的是根开关由宿主在 Blazor 启动之后才写（`UiRuntime`），加载页还在时就会翻转，
  而宿主判定为低端设备的恰恰看加载页最久。所以 `boot.css` 在这三条路径下各有一条覆盖，方块一律回到 `--ft-splash-tile` 并不再模糊——这是对「组件只引用令牌、不为降级写分支」（§26）的有意例外。
  E2E `boot_test` 的 I 节用实际像素验证根开关翻转前后、系统降低透明度下方块没有色跳；单元测试守住三条覆盖都在，且令牌层的降级路径数量没变（增删了路径会拦住，提醒这里同步）。
  **登录交接是个例外的最后一步**：降级下登录页里的真方块是 `#6A42F2`（令牌里的不透明深色玻璃），加载页的方块在 `handoff-login` 状态下随滑行的 400 ms 一路换成它——
  滑行结束、加载页收走、真方块露出来的那一刻没有色跳（真方块在滑行期间是 `visibility: hidden`，不换的话那一刻是一次瞬时的变色）。常态下两边本来是同一块玻璃，这条规则没有可见效果；
  E2E I 节走宿主判定的真实链路（假实现 → `UiRuntime` → 根开关）验证。
- **交接由「就绪」决定，不由定时器**：两个信号都到才收走加载页——**外壳就绪**：Blazor 完成首次交互渲染（`StartupHost` 放在 `Main.razor` 根部，`OnAfterRenderAsync(firstRender)` 调 `FtBoot.shellReady()`；
  Blazor Server 的预渲染阶段不算，电路接管之后才算——此前点按没有反应，不能把加载页收走）；**首屏就绪**：页面根节点声明 `data-ft-ready="home|login"`（首页读完登录状态与首页数据才声明，骨架阶段不声明；登录页渲染出来即就绪）。
  页面只声明一个属性，不调用脚本——`boot.js` 用 `MutationObserver` 观察，所以「未登录时从首页 Replace 到登录页」这类换页也自然重新判定。
  **外壳就绪之后最多再等 `capMs`（1.5 s）**，到点仍没就绪就带着现状交出——不让任何人为了看一段动画多等。启动路径不是 `/` 与 `/login`（浏览器深链接）没有「首屏」可等，外壳就绪即交。
- **三种交接**（`<html data-ft-boot>` 依次写成 `handoff-home` / `handoff-login` / `handoff-fade`）：**首页**——幕布收拢成 Hero（高度 = 实测的真实 Hero 高度，写在 `--ft-boot-hero-h`；圆角长到 `--ft-radius-hero`；`--ft-dur-sheet` 约 400 ms；收到位后幕布淡出，露出下面同一块渐变的真 Hero）；
  **登录**——Logo 组整体滑到登录页里 Logo 的位置（`--ft-boot-dx/dy` 是量出来的中心差），白色面板升起；**其它 / 深链接 /「减弱动态效果」**——整体淡出（`--ft-dur-page` 180 ms；减弱动态效果下 `--ft-dur-reduced` 约 100 ms，不位移、不收拢）。
  交接要等多久直接读样式表里的 transition 时长（`longestTransitionMs`），改令牌不用改脚本；量不到目标（Hero / Logo 不在，或高度为 0）退回淡出。
  **量 Hero 不能用 `getBoundingClientRect`**：页面栈的 Tab 根页面刚挂上时有 0.985 → 1 的入场缩放，本地库读得快时交接恰好发生在缩放途中，量到的是缩小后的值，幕布就比 Hero 矮一截；
  改为沿 `offsetParent` 链累加布局位置（不含 transform）。E2E 在交接结束的位置上断言幕布高度与 Hero 一致（< 0.6 px）、登录 Logo 与加载页 Logo 重合（< 0.5 px）。
- **慢与失败要有出口**：启动超过 `spinnerMs`（0.6 s）才出现转圈（快启动不闪）；`watchdogMs`（12 s）内外壳还没就绪 → 玻璃 Alert「启动失败 / 重新加载」（标记与 `GlassAlert` 同一套，只有一个按钮，文案是固定字符串，点按整页重载，焦点放在容器上）；
  之后外壳又起来了（只是慢）自动撤掉卡片。再下一层兜底是 CSS：加载页自带 30 s 的 `ft-boot-expire` 动画，到点 `visibility: hidden`——`boot.js` 一直没加载出来也绝不永远盖住应用（失败卡片出现时撤掉这个动画，卡片不会自己消失）。
  三个时间常量是**建议值，没有实测数据**，真机上量过「点图标 → 外壳就绪」的分布再调；宿主页可在脚本之前设置 `window.FT_BOOT_TIMINGS = { spinnerMs, capMs, watchdogMs }` 覆盖（E2E 用它缩短看门狗）。
- **CDN 资源从首次绘制的路径上拿掉**：图标字体 CSS（MDI）与 ECharts 原来是 `<head>` 里的同步 CDN 资源——慢网 / 离线时连加载页都出不来，还拖住 `window load`（MAUI 的 `BlazorWebView` 在页面加载完成之后才启动 Blazor）。
  现在由 `boot.js` 在 `load` 之后注入（地址写在脚本标签的 `data-css` / `data-font` / `data-scripts` 上）：交接前只等图标字体就绪（或到 `capMs` 上限），ECharts 不挡交接。
- **后果与对策：图表一律经 `EChartsView`**：用户可能在 ECharts 下载完之前就进到带图表的页面，而 MASA 的 `MECharts` 不检查全局对象就 `echarts.init`——`ReferenceError` 被 Blazor 当成未处理异常，整个界面（电路 / WebView）失效（探针复现过，不是推测）。
  所以所有图表都经 `Ui/EChartsView`：先等 `FtBoot.chartsReady()`（脚本都加载完或失败之后兑现，值 = 全局 `echarts` 是否可用），等待期间是与图表同高的骨架（`data-testid="chart-pending"`），
  脚本没能加载则显示说明「图表组件未能加载（需要联网），联网后重新打开应用即可」（`chart-unavailable`）——**这顺带修了「离线时进统计页同样会崩」的老问题**。页面里不得直接写 `<MECharts>`，`DesignTokensTests` 扫描全部 `.razor` 守住。
  已知取舍：CDN 连得上却一直不返回时，图表位置会一直是骨架，直到浏览器自己判定超时。
- **原生部分**：`splash.svg` 画布 108×108、方块四周各留 6（Android 12+ 的启动图 drawable 由 MAUI 生成，固定把图拉成 108dp，画布正好 108 才没有尺寸跳变；csproj 的 `BaseSize="108,108"`，Resizetizer 把 `Color` 直接烤进启动图）；
  Android 启动主题 `Ft.SplashTheme`（`Platforms/Android/Resources/values/styles.xml`，继承 MAUI 生成的 `Maui.SplashTheme`，只把状态栏图标改成白色，`MainActivity` 的 `Theme` 指向它；XML 注释里不能出现 `--`）；
  iOS `Info.plist` 的 `UIStatusBarStyle = UIStatusBarStyleLightContent`（只管启动那一刻，启动后仍由 `StatusBarService` 按页面接管，§5）；`MainPage.xaml` 的 `BackgroundColor` 取启动底色、`SafeAreaEdges="None"`（沿用 02 号 ticket）。
- **观察接口**：`<html data-ft-boot="booting|handoff-login|handoff-home|handoff-fade|failed|done">`（同值写在 `#ft-boot[data-state]`）、`window.FtBoot.state` / `assetsSettled` / `chartsReady()`，均登记在 `tests/e2e/README.md`。
  E2E 基座的 `wait_circuit_ready` 现在等到加载页收走且 CDN 资源都已加载完或失败，各脚本此后看到的与以往一样是干净的首屏；`boot_test.py` 覆盖慢启动 / 失败兜底 / 两种交接 / 深链接 / 慢 CDN / 图表等待 / 减弱动态效果。

### 26. 无障碍与降级加固（23 号 ticket 起）

降级的回退全部放在令牌层 / 根节点，页面样式不为降级写分支；验收是一套覆盖整个应用的自动扫描（`tests/e2e/a11y_degradation_test.py` + `a11y_probes.py`），读屏与真机体验仍是人工验收。

- **材质降级：三条触发路径，一组不透明令牌**：系统「降低透明度」（`@media (prefers-reduced-transparency: reduce)`）、应用根开关 `<html data-ft-solid="true">`、浏览器不支持 `backdrop-filter`（`@supports not (…)`）——
  三处的声明逐条一致（`DesignTokensTests` 校验，改一处漏另两处会被拦住）。组件样式只引用 `--ft-glass-*` / `--ft-voice-*` 令牌，所以不用逐页写降级样式。
  不透明取值：浅色玻璃 → 白底 + 一圈细描边（压在白卡 / Sheet 上时靠它分出边界）；深色玻璃（Hero 之上）→ `#6A42F2`（比 Hero 渐变中段略亮的紫，白字 ≥ 4.5:1）；语音覆盖层 → 各自的实色。遮罩 `--ft-scrim` 只变暗、不透出内容，不算玻璃，保持不变。
  E2E 的 M 节：「系统降低透明度」路径逐个扫九类场景（首页 / 账单 / 统计 / 我的 / 账本 / 记一笔 Sheet / 删除 Alert / Toast / 语音覆盖层）加登录页——没有任何元素还带 `backdrop-filter`、玻璃表面底色不透明、不透明表面上的文字仍达标；
  根开关与宿主判定两条路径验证令牌取值与媒体路径逐条一致、关掉后玻璃恢复、宿主判定变化不刷新页面即时跟随且重载后仍按宿主判定；降级期间 Tab 切换 / 记一笔保存 / 账单列表照常。
- **宿主判定链路**：`IRenderingProfileService.PreferSolidMaterials`（Web 层接口，由 MAUI 宿主实现）→ `UiRuntime` 订阅（先订阅再读当前值，变化事件即时跟随，用户在系统里切换不必重启）→ `ui.js` 的 `setSolid` 写根开关。
  Android 的判据是「系统标记的低内存设备（`ActivityManager.isLowRamDevice`），或系统报告的总内存 < 3 GiB」（`LowEndDeviceCriteria`，纯函数，单元测试覆盖边界）：毛玻璃每一层都多一次离屏渲染与整块模糊，掉帧最先出现在内存小、GPU 弱的机型上，
  内存是 Android 上唯一稳定可读、不需要权限的相关信号；报告值比标称值少一截（标称 3 GB 约报 2.7–2.9 GiB、4 GB 约报 3.6–3.8 GiB），3 GiB 的门槛刚好把「标称 3 GB 及以下」判为低端；读不到内存时不降级，宁可保持质感也不误降级。
  **这个门槛是建议值，没有真机分布数据**，低端机验收之后再调。iOS 读 `UIAccessibility.IsReduceTransparencyEnabled` 并监听状态变化通知；Web.Server 与其余宿主是恒为 false 的空实现。
  E2E 用 `E2ERendering.cs` 的假实现（与 `E2ECapture` 同一个开关，`server.ps1` 启动时打开）经 `POST /__e2e/rendering` 驱动整条链路。**Android 与 iOS 的原生实现只验证过能随 `dotnet build FinanceTracker.sln` 编译通过，没有在真机 / 模拟器上运行过**。
- **Sheet 升起时页面与 Tab 栏的玻璃让位**：`ui.js` 把「有 Sheet 升起」写在 `<html data-ft-sheet-open>` 上，被遮罩盖住的页面与 Tab 栏关掉 `backdrop-filter`，Sheet 自己里面的玻璃（标题栏圆钮）用特异性更高的规则重新打开；
  Sheet 一开始收起（`.ft-sheet-host--closing`）属性就撤掉，页面的玻璃赶在页面复位之前恢复。不用 `:has()`（兼容性）——Sheet 可能渲染在页面栈之外、也可能在某个页面里面，同级选择器表达不了。
  这一条取代了 §11 记下的「账单 Tab 打开 Sheet 时 4 层」的例外：**所有屏幕、所有状态下的玻璃层 ≤ 3**。唯一的例外是 Toast（盖在最上面的瞬时反馈，几秒后自己消失），E2E 里单独列出而不计入预算，理由写在 `GLASS_NOTES`。
- **减弱动态效果：令牌层 + MASA 兜底 + 组件规则三层**：① `tokens.css` 的 `@media (prefers-reduced-motion: reduce)` 把全部 `--ft-dur-*` 一处压成 `--ft-dur-reduced`（100 ms），组件只要用令牌就自动受益；不压的只有金额光标闪烁周期与语音循环周期
  （循环动画由各自的规则关掉，把循环周期压成 100 ms 反而成了频闪）；② 弹簧 / 位移 / 缩放这些「运动本身」由各组件的 reduce 规则与脚本去掉；③ MASA 组件自带的 0.2–0.3 s `transition` 用 `ui.css` 末尾的兜底压到同一时长——
  必须 `!important`（MASA 的图标用 `.m-icon.m-icon` 叠类名提特异性），也不能压成 0（MASA 依赖 `transitionend` 收尾，压成 0 会卡住），只压 `transition-duration`、不碰 `animation`。
  「简短」的口径定为 ≤ 150 ms，E2E 的 R 节按它扫描整个应用（Tab 切换 / 记一笔升起与保存 / 筛选 Sheet / 页面入栈出栈 / Alert / Toast / 语音覆盖层），并断言没有无限循环的装饰动画；
  加载转圈保留（它是唯一的「正在进行」反馈），放慢到 2.4 s 一圈，允许清单里逐项写明理由。
  **踩过的坑：reduce 覆盖规则必须写在被覆盖的基础规则之后**（同选择器同优先级，后写的赢）：预算页金额光标的 reduce 规则原先写在基础规则前面，光标在 reduce 下照闪——是扫描抓到的真 bug；
  `DesignTokensTests` 现在解析 CSS 规则顺序守住这一点，并检查「reduce 下所有动效令牌取同一个简短时长」。
- **对比度（文字 ≥ 4.5:1，大号文字 ≥ 3:1）**：按 WCAG 2.x 的相对亮度计算，大号 = ≥ 24px 或 ≥ 18.66px 加粗。扫描先按计算样式与背景链解析出前景 / 背景，再用截图像素复核。审计结果与取舍：
  `--ft-label-2`（次要文字，占位文字也用它）的不透明度由 .62 加深到 .76——iOS 原生是 .60，那在白卡上只有 3.6:1、在页面底色与搜索框底上更低，加深后白卡 5.3 / 页面底色 5.0 / 搜索框底 4.6；
  `--ft-success-text`（#127436，「可编辑」徽标，压在 16% 绿浅底上）；`--ft-herocard-scrim`（首页 Hero 小卡里一层暗纱，小卡压在渐变最亮的一角时白色说明文字也 ≥ 4.5:1）；
  图表用的红 / 绿 / 主色浅底改成设计令牌（`DesignTokens.ExpenseColor` / `IncomeColor` / `BrandTintColor`，与 `--ft-expense` / `--ft-income` 一致，单元测试守住）。
  `--ft-label-3` 只能用于图形、不能用于文字（对比度约 1.8:1）。放行清单（点击热区与对比度）**当前都是空的**——没有需要豁免的元素，以后新增放行项必须同时写明理由。
- **点击热区 ≥ 44 × 44**：量的是「实际点得到的区域」而不是盒子大小——从元素中心沿水平 / 垂直方向用 `elementFromPoint` 逐像素取样，量连续点得到它的长度（伪元素扩出来的热区也算；容差 1 px）。
  元素被视口边缘 / 滚动容器 / 吸底键盘切掉一截时，射线只能量到露出来的那段，会误报：探针对不达标的元素当场把滚动容器滚到顶端、底端、正中各量一次取最大，量完还原滚动位置——最好的位置上也点不全的才算真问题。
  扫描量出了一处真问题：预算卡片「编辑」用负外边距扩出来的 12px 热区压在下一行金额的行框下面，点在那 12px 上命中的是金额，实际只有 32px 高——加 `position: relative; z-index: 1` 修好。
- **大字号（系统字体放大到 130%）**：Z 节用「样式改写」模拟系统字号放大——把 `--ft-type-*` 令牌、样式表里的 px 字号 / 行高与根字号整体放大 1.3 倍。**这是近似，不等价于真实的 Android `fontScale` / iOS Dynamic Type**（图标字体与第三方样式表不被缩放），真机大字号验收另列。
  在 390 与 320 两个宽度下扫描四个 Tab、记一笔 Sheet、各二级页面、登录页：没有横向溢出、没有元素越出视口、没有文字被固定高度裁掉、可点击元素仍 ≥ 44 × 44。
  为此做过的调整：Hero 主指标与小卡金额按字符数收缩（`--ft-amount-fit-xl` / `--ft-amount-fit-card`，系数里已含 1.3 倍余量，装得下 ¥99,999,999.99 这种最宽的数字）；
  `ui.css` 开头加了 `.m-application p { margin-bottom: 0 }`——MASA 给全局 `<p>` 写了下外边距，本应用的文字块都按「X 0 0」写，之前每个页面各自绕开（`p.ft-…` 选择器、「不用 `<p>`」的约定），现在全局归零，那些绕开的写法留着无害（24 号评估后不收回，§27）。
  验收阶段（24 号）按设计稿改完版面后，这一节扫描又抓到两处回归，修法成了约定：①「标题 + 灰色备注」这类要省略的尾段，写成标题盒里的 flex 子项（`ListCell` 的 `TitleNote`，前一段按内容宽、后一段占剩余宽度并自己省略），不要写成行内元素——行内元素的盒子会比被 `overflow` 裁住的标题盒还宽，大字号下会被「没有元素越出视口」抓到；②设计稿给了行高的网格（记一笔的分类网格 77pt），行高写成 `minmax(令牌, auto)`、名称行不收缩——固定行高在 130% 字号下会裁掉名称下沿，100% 字号下像素不变。
- **状态不只靠颜色**：T 节逐项验证——Tab 栏（文字标签 + `aria-selected` + 选中项下的高光块）、统计分段（文字 + `aria-pressed` + 滑块）、多选（`role=checkbox` / `aria-checked` + 圈内对勾，未选是空心圈）、
  金额（收入带 +、支出带 -）、预算三档（「剩余 / 仅剩 / 超支」文字 + 读屏文案「接近上限 / 已超支」，总预算圆环超支时标签是「超支」）、云端同步行（「N 条待同步」文字 + 云图标）、
  账本成员角色（文字徽标）、日志级别（文字里写着级别名）、登录表单错误（文字 + `role=alert` + `aria-invalid`）。圆环与图例的色点是装饰（`aria-hidden`），名称、占比、金额都以文字呈现。
- **两个文字警示色令牌统一为一个**：`--ft-warning-text` 与 `--ft-callout-warning-text` 合并成同一个 `#9A5000`（§20 记下的「留给 23 号的全局统一」）：#A15500 压在「16% 橙叠在页面底色」上只有 4.39:1，合并后在白底、橙浅底、页面底色叠橙上都 ≥ 4.5:1。
- **不在 23 号范围、仍然开着的**：完整的读屏（VoiceOver / TalkBack）适配审计；Sheet / 语音覆盖层升起时底下页面的 `inert` 与焦点陷阱；Android 系统返回键先收起 Sheet / 覆盖层（要改原生宿主、只能真机验证）。三项见「已知限制」。
- **E2E 的结构**：`a11y_degradation_test.py`（M 材质降级 / S 逐屏扫描 / Z 大字号 / R 减弱动态效果 / T 状态不只靠颜色，可带小节名只跑指定小节）+ `a11y_probes.py`（页面探针：取数的 JS 片段与逐屏扫描驱动）；`A11Y_VERBOSE=1` 打印每屏的明细。
  脚本先造一份「什么都有」的数据（自建账本 + 加入的共享账本 + 待处理邀请、四十多天含超长备注 / 巨额金额 / 历史无账本 / 同步失败的账单、总预算与分类预算含超支、待确认账单、自定义分类与支付渠道、错误日志），再逐屏扫描。
  需要 Pillow / numpy（像素复核对比度），已写进 `tests/e2e/requirements.txt`。扫描期间不要同时跑别的会改本地库 / 重启服务的脚本——探针对「页面停稳」敏感。

### 27. 收尾清理与全量回归（24 号 ticket 起）

迁移到这里结束：清掉旧视觉的遗留，并留下守卫防止它们被加回来。**只清遗留、不改行为**——清理前后的页面、数据、接口、同步与权限语义一致（逐项审计记在 24 号 ticket）。

- **清掉了什么**：
  - `app.css` 里的迁移期兼容层（让旧页面在沉浸式下不被状态栏盖住的 `.m-page-stack-item__bar` / `.container` / 工具栏按钮规则）整体删除；其中唯一仍有用的一条——二级页面内容区的上内边距——升为 `ui.css` 的正式规则（§7）。
    `app.css` 现在只剩「禁止长按选择」与四个 `--ft-safe-*` 变量。
  - `tabBar.js` 与 E2E 基座里「找不到 `data-scroll-root` 就退回旧 `.container`」的兜底删除——所有页面都有滚动根标记，兜底留着只会让漏标的新页面「恰好正常」。
  - 没有任何引用的 `LedgerSelect`（旧账本下拉）删除；`BillFilterChip` 在「已设置条件」时直接渲染通用件 `ConditionChip`（条件标签的标记与样式只剩一份，渲染出来的 DOM 不变）。
  - 15 个 E2E 脚本各抄一份的「玻璃层数」探针合并成 `e2e_base.GLASS_LAYERS_JS`，口径只有一处。
- **兜底页面按设计系统重做**（`Main.razor`）：「页面未找到」= 套 `AuthLayout` 的通用空状态（`EmptyState` + 主按钮 `GlassButton`「返回首页」），「组件渲染发生异常」= 不依赖任何布局的整屏卡片 + 可长按复制的错误详情（出错的可能就是布局本身，所以它自带字体与底色）。
  两者都是 `position: fixed` 四边贴齐的整屏一层、只引用令牌（`ui.css`「兜底页面」一节）；之前用的是 MASA 的 `MContainer` / `MRow` / `MButton` 与写死的 `height: 100vh`、内联样式——那是应用里最后一处旧视觉。
  可观察属性：`not-found`（根，带 `data-statusbar-bg="light"`）、`not-found-empty`、`not-found-home`、`render-error`。
- **图表的颜色常量补齐**：`DesignTokens` 增加 `ChartAxisTextColor`（= `--ft-label-2`）/ `ChartGridLineColor` / `ChartEmptyCellColor`（= `--ft-bg`）/ `ChartEmptyCellBorderColor`；
  `StatisticsChartOptions` 的坐标轴文字原先停在 23 号之前的 `.62`（注释写着与 `--ft-label-2` 相同，其实已经漂移），日历热力图的空格子也是写死的色值——现在都取常量，单元测试守住与令牌同值、坐标轴文字在白卡上 ≥ 4.5:1。
- **守卫（`VisualSystemGuardTests`，只扫描源码）**：Razor 里只允许白名单内的 MASA 标记（`MApp` / `MErrorHandler` / `PPageStack` / `PStackPageBar` / `MECharts`）；没有静态内联样式（运行时算出来的 `style="…@…"` 除外）；
  共享组件库的 `.razor` / `.cs` 里除 `DesignTokens.cs` 外没有写死的颜色；`app.css` 里没有依赖页面栈内部 DOM 的规则；二级页面内容区的正式规则存在；`tabBar.js` 没有旧容器兜底。
  往后有人把旧视觉加回来，单元测试直接拦；确实需要新的 MASA 控件时，先确认视觉与降级（§26）都由组件层接管，再把它加进白名单并在本 ADR 记一笔。
- **评估后没有动的**（改了没有用户可见收益，只增加风险）：① `p.ft-…` / `p.ft-login__…` 这类绕开 `<p>` 外边距的选择器与「不用 `<p>`」的约定——23 号已全局归零，保留无害；
  ② `StatisticsRedirect` / `StatisticsSegmentRequest`——旧地址的兜底，保留（§14）；
  ③ 几个页面里相近的文案常量（短信识别页与导入页各有一份「加载中… / 加载失败，点按重试」）与各页的账本行展示——两三个字符串，抽出来要让两页互相依赖，成本大于收益。
- **E2E 的结构**：`not_found_test.py`（A 结构与样式 / B 刘海与手势条 / C 宽屏 / D 回首页，可带小节名只跑指定小节）；「组件渲染发生异常」那一支没法在 E2E 里注入渲染失败，样式与结构靠上面的守卫，页面本身走查代码 + 人工验收。
  `GLASS_LAYERS_JS` 与 `scroll_root_*` 等通用探针都在 `e2e_base.py`，新增脚本直接导入，不要再各抄一份。

## 考虑的替代方案

- **换掉 MASA Blazor / 重写成原生 SwiftUI + Compose**：共享的 Web 层是整个应用的价值所在（App 与 Web.Server 共用一套页面），
  重写成本远超这次重构的目标。只换视觉层。
- **自己写页面栈**：`PageStack` 已经提供 iOS 式的推入 / 返回转场与 Tab 保活，缺的只是视觉，不值得重造。
- **在 `MBottomNavigation` 上叠样式**：它不支持独立的圆钮、滑块高光、在二级页面隐藏的过渡，改造等于重写，
  所以直接做 `GlassTabBar` 并移除旧的底部导航。
- **按平台分支样式（iOS 用玻璃、Android 用 Material）**：双倍样式维护与测试成本，且 E2E 只能覆盖网页层。
  统一风格，平台差异只留在原生能力抽象里。
- **每个页面各自定义颜色 / 圆角**：无法统一改版，也无法在「降低透明度」时一处回退。所以令牌是唯一来源。
- **冷启动：加载页用固定时长的定时器收走（如 1.5 s 后淡出）**：快的设备白等，慢的设备露出半成品。改为「外壳就绪 + 首屏就绪」两个信号决定，定时器只留作上限与看门狗（§25）。
- **冷启动：只做原生启动画面、不做 Web 加载页**：启动画面结束到 Blazor 首次渲染之间（WebView 载入 + .NET 启动）仍有一段空白，白屏恰恰来自那一段；加载页接上这一段，且能做渐变与动效。
- **冷启动：启动画面本身做成渐变 / 动画**：iOS 启动图与 Android 12+ 的系统启动画面只能是「底色 + 静态图」（动画图标在 Android 12+ 受限且各厂商表现不一），所以启动画面做成扁平方块，把渐变与动效留给加载页。
- **冷启动：ECharts 与图标字体继续留在 `<head>` 同步加载**：最省事，但慢网 / 离线时挡住首次绘制与 `load`，冷启动要解决的正是这个；代价（图表要等脚本）由 `EChartsView` 承担。
- **降级：每个组件各写一份降级样式**：几十处样式各改各的，漏一处就在某个屏幕上露出半透明；也没法一个开关切换。改为令牌层一处回退，组件只引用令牌（§26）。
- **降级：按 UA / WebView 版本 / 实测帧率判定低端设备**：UA 里没有可靠的设备档次信息，WebView 版本与流畅度不相关，运行时测帧率则要先让用户看一段卡顿才降级。内存与系统的低内存标记在 Android 上稳定可读、与毛玻璃的开销相关（§26）。
- **减弱动态效果：全局 `transition: none` / `animation: none`**：MASA 组件依赖 `transitionend` 收尾（对话框、菜单的显隐），压成 0 会让它们卡在中间态；改为压到同一个简短时长，只关掉装饰性的循环动画（§26）。
- **次要文字保持 iOS 原生的 60% 不透明度**：与系统一致，但白卡上只有 3.6:1、搜索框底上约 3.2:1，达不到 AA；放弃与系统逐值一致，加深到 76%（§26）。
- **收尾：兼容层留一段时间以防回归**：兼容层依赖页面栈内部 DOM 与旧 `.container`，每个页面都已自己使用安全区变量；留着只会让新页面「恰好正常」而掩盖遗漏。删除后由 E2E 的沉浸式扫描与 `VisualSystemGuardTests` 兜底（§27）。
- **收尾：兜底页沿用 MASA 默认样式**：它只在地址不存在时出现，但那是应用里最后一处旧控件，留着就得给「Razor 里没有 MASA 控件」的守卫开白名单缺口；改为复用 `EmptyState` + `GlassButton`（§27）。

## 已知限制

- E2E 只能覆盖网页层。玻璃模糊在 Android WebView / iOS WKWebView 上的真实渲染与性能、手势条不遮挡 Tab 栏、
  状态栏图标颜色真正切换，必须在真机 / 模拟器上人工验收（各 ticket 的「人工验收」清单）。
- `backdrop-filter` 在较老的 Android WebView 上可能不被支持：已由 23 号 ticket 处理——`@supports not (backdrop-filter)`、根开关 `data-ft-solid`、系统「降低透明度」三条路共用同一组不透明令牌（§26）。
  但「低端设备上降级后滚动与切换是否真的流畅」「判据（系统标记的低内存设备或总内存 < 3 GiB）是否合适」只能真机验证（23 号 ticket 的人工验收）。
- 弹簧手感、触感反馈（iOS 轻触 / Android 时钟刻度）与中端 Android 上的切换 / 滚动流畅度无法自动化，只能真机 / 模拟器人工验收（04 号 ticket）。
- Tab 高光（`translate` / `scale`）与图标按下缩放（`scale`）用的是 CSS **独立变换属性**（不是 `transform`）：它们需要 Safari / WKWebView 14.1（iOS 14.5）+、Chrome / Android WebView 104+。
  应用的最低系统是 iOS 14.0 / Android 9（API 28）：iOS 14.0–14.4 的 WKWebView 不认这两个属性（WKWebView 版本跟系统走，不能单独升级），Tab 高光会停在最左边、不跟随选中项；
  Android 的系统 WebView 由应用商店升级，只有长期不更新 / 被禁用 WebView 的设备才会低于 104。两者都没有降级写法，也没有在这些系统上验证过——属于人工验收项（04 号 ticket），
  若需要兼容，要把 `tabBar.js` 与 `ui.css` 改回 `transform` 组合写法（同时改 E2E 里读 `style.translate` / `style.scale` 的断言），或把最低 iOS 提到 14.5。
- 左滑行的松手手感、Sheet 弹起 / 拖拽收起的跟手度、软键盘弹出时 Sheet 的避让只能真机验收（05 号 ticket）。左滑托盘用 `inert` 防止被盖住的按钮被聚焦，
  `inert` 需要 iOS 15.5+ / Android WebView 102+；更老的系统上它被忽略，但托盘仍有 `aria-hidden` 且被内容层盖住，不影响点按，只是键盘 / 开关控制可以聚焦到它。
- 首页 Hero 真正顶到屏幕最顶端、状态栏图标颜色随滚动真正切换、下拉刷新的跟手与回弹手感、灵动岛下转圈的位置、Hero 上半透明小卡在真机上的观感，
  只能真机 / 模拟器人工验收（07 号 ticket）。
- 账单 Tab 的大标题折叠手感（尤其滚动惯性中途折叠的平滑度）、左滑「编辑 / 删除」的松手手感、下拉刷新与系统橡皮筋的配合、
  Tab 根页面切走再切回时隐藏页面的滚动位置是否保留（WKWebView / Android WebView），只能真机 / 模拟器人工验收（08 号 ticket）。
- 筛选 Sheet / 归属账本 Sheet 的弹簧与下拉把手收起手势、条件条的横向滑动手感与惯性、底部操作栏在不同底部安全区（手势条 / 三键导航）上与 Tab 栏的间距、
  `<input type="date">` 在 iOS 原生日期选择器与 Android 日期选择器里的样子与交互，只能真机 / 模拟器人工验收（09 号 ticket）。
- 搜索框在 iOS / Android 软键盘上的真实表现——系统「搜索」键是否出现且触发提交、真实输入法（拼音 / 手写 / 语音输入）下组词期间不提交、停顿提交是否顺手、
  键盘弹出时搜索框与列表的布局（搜索框在页面顶部，一般不被键盘遮挡；结果列表在键盘下面时是否需要点别处收起键盘）——E2E 只能用事件模拟，必须真机验收（10 号 ticket）。
  Android 上的 Gboard 在敲拉丁字母时通常也走「组词」（`isComposing` 为真，直到空格 / 回车 / 失焦才结束），这时「停顿提交」要等词结束才触发，回车 / 失焦不受影响——待真机确认。
- 占位文字（`--ft-label-2`，叠在 `--ft-fill` 上）原先的对比度约 3.2:1（与 iOS 原生搜索框相当，但低于 WCAG AA 的 4.5:1）：已在 23 号 ticket 把 `--ft-label-2` 的不透明度从 .62 加深到 .76，
  白卡、页面底色、搜索框底上都 ≥ 4.5:1（`DesignTokensTests` 计算并守住）——与 iOS 系统的次要标签色（60%）相比略深，是为 AA 付出的视觉代价（§26 判断项）。
- 统计 Tab 在真机上的观感与手感——圆环（SVG 描边虚线弧 + 段间缺口）与 ECharts 三张图表在 Android / iOS WebView 里的渲染、月份切换时图表重绘的流畅度、
  大标题折叠与下拉刷新的跟手度、账本菜单在小屏上的滚动手感——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（11 号 ticket）。
- 圆环 / 图例的色板里黄色、灰色与白底的对比度偏低：圆环与圆点只是装饰（圆环 `aria-hidden`），名称、占比、金额都以文字呈现，信息不单靠颜色承载；
  统计里 ECharts 的三张图表（分类排行 / 支出日历 / 累计收支）的配色已在 23 号 ticket 改成设计令牌（§26）。
- 趋势 / 年度在真机上的观感与手感——ECharts 折线在 Android / iOS WebView 里的渲染、在图表上纵向滑动是否会卡住页面滚动、时间范围菜单与系统手势条的配合、
  明细表排序表头的点按手感、年份连点上一年 / 下一年时视图重载的流畅度——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（12 号 ticket）。
  趋势折线图的横轴只含「有账单的日期」（后端不补零），没有账单的日子之间折线直接相连，看起来比实际更平滑——改成补零会改变统计服务的返回形态，留待判断（见待判断项）。
- 「我的」Tab 在真机上的观感与手感——下拉刷新的跟手与回弹、分组列表在 iOS / Android 上的字体渲染与行高、短信读取权限的真实授权状态与摘要「已开启 / 未开启」是否与系统设置一致、
  退出登录后回到登录页的转场——只能真机 / 模拟器人工验收。**「立即同步」的成功路径**依赖真实云端（假云端只实现登录与成员接口），E2E 只验证云端不可用时的失败提示、按钮恢复、数量不变、不登出，
  成功路径（待同步数量清零、同步后摘要刷新）留给集成环境的人工验收（13 号 ticket）。
- 退出登录的「已退出登录」Toast 因布局切换被丢弃（见 §15），属于既有行为；同步失败的 Toast 目前直接带上系统返回的错误文字（如「同步失败: 无法连接云端…」），文字是否需要本地化 / 简化留待判断。
- 分类管理与支付渠道页在真机上的观感与手感——42 个图标的网格在小屏上的点选手感与 Sheet 内滚动、键盘弹出时名称框与 Sheet 的避让、左滑松手手感、预设项菜单与 Alert 的转场——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（14 号 ticket）。
  表单里没有颜色选择（实体无颜色列，见 §16）：与设计稿 11 有出入，是否新增 `Color` 列留待判断。
- 记一笔 Sheet 在真机上的手感——Sheet 升起与背景缩放（整页 `transform` + 圆角 + `overflow: hidden` 在 WKWebView / 低端 Android WebView 上是否掉帧）、备注的系统键盘与自定义键盘之间的切换
  （键盘弹出时 Sheet 是否被顶起或遮挡、`data-typing` 与真实键盘事件的配合）、长按退格清空与键盘按键的点按手感与触感、分类网格的横向滑动与 Sheet 下拉收起手势是否互相抢手势、麦克风的按住说话——
  E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（15 号 ticket）。
- 记一笔 Sheet 升起时，底下的页面仍在 DOM 里、可被读屏 / 键盘焦点到达（没有 `inert` 与焦点陷阱）；Android 系统返回键目前不会先收起 Sheet（走页面栈的返回）——
  这两项原本记在 23 号 ticket 名下，但 23 号的验收项不含它们（完整的读屏适配审计明确不在范围内，返回键要改原生宿主、只能真机验证），**23 号没有处理，仍然开着**，需要单独立项。
  深链 `/?add-bill=1`（含编辑的 `/?add-bill={BillId}`）在 Sheet 关闭后不会从地址栏剥离，刷新页面会再次升起 Sheet（只影响直接访问旧地址 `/add-bill` / `/add-bill/{BillId}` 的书签用户）。
- 编辑账单在真机上的手感——点按行 / 左滑「编辑」升起 Sheet 的观感、底部红字「删除账单」行滚到底时会不会被固定在底部的数字键盘遮住与点按面积、删除确认 Alert 的转场、放弃修改确认——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（16 号 ticket）。
  只读成员的「无权限」路径与别人记的账单只读用 E2E 的假云端覆盖，真实云端联调留给人工验收。
- 语音覆盖层在真机上的手感——MAUI 原生按住说话（按住即升起、上滑 / 滑开进入取消区的跟手度与阈值是否顺手、权限弹窗期间松手、被来电打断）、流式部分结果高频到达时「每段都解析一次」的流畅度、`backdrop-filter: blur(28px)` 整屏在 WKWebView / 低端 Android WebView 上是否掉帧、
  真实识别服务的网络环境与 Web Speech 在各浏览器的支持——E2E 只能用假识别器覆盖点按形态，必须真机验收（17 号 ticket）。覆盖层打开时底下的 Sheet 仍可被键盘 / 读屏到达（`aria-modal` 已标，但没有 `inert` 与焦点陷阱），Android 返回键不先关覆盖层——与上一条同样，23 号没有处理，仍然开着。
  预设分类的口语同义词表按短名（餐饮、交通……）建、预设名是「餐饮美食」「交通出行」，同义词查表对不上，说「午饭」认不出分类（说全名才认得出）——属于既有的解析缺陷，17 号按「解析规则不变」没有动，见待判断项。
- 预算页在真机上的手感——左滑「编辑 / 删除」的松手手感、点按整行的按下底色、新建 / 编辑 Sheet 的弹簧与自定义键盘的点按手感、进度环（SVG 描边虚线 + 圆角端点 + 500ms 弧长过渡）在 Android / iOS WebView 里的渲染与帧率、
  320pt 窄屏的实际观感（E2E 只量了几何，没有量观感）、超支本地通知（沿用旧逻辑，未改动）——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（18 号 ticket）。
  行内只显示「已用 / 额度」与右上角的剩余文字，使用率只出现在环中心与读屏文案里（整数、向下取整）；旧页面每行都写「已使用 87.1%」（一位小数），设计稿 09 的行里没有百分比文字，是否要补回留待判断。
- 待确认账单与短信识别页在真机上的真实链路与手感——`NotificationListenerService` 收到微信 / 支付宝通知、短信广播收到银行扣款短信并写入待确认列表、系统权限弹窗与「通知使用权」设置页往返、
  卡片与按钮的点按手感、「确认账单」Sheet 的弹簧与自定义键盘、`<input type="date">` 在 iOS / Android 原生日期选择器里的样子、320pt 窄屏与大字号下卡片 / 状态条的实际观感——
  E2E 只能用 `/__e2e/capture` 假实现覆盖网页层（权限状态、读到的短信、平台服务被调用的次数），必须真机 / 模拟器人工验收（19 号 ticket）。
  **从系统设置页开启「通知使用权」后回到应用，页面不会自动重新读取权限状态**（只在进入页面时读一次，旧页面同样如此），要重新进入页面才会变成「已开启」——补上「回到前台自动刷新」是新增行为，留待判断。
  卡片上的分类是「入账时会使用的分类」（识别结果里没有分类，一律是「其他支出 / 其他收入」的回退），卡片与 Sheet 里都不能直接改分类，设计稿 10 里卡片上的「餐饮」之类分类名只是示意——是否要在识别阶段做分类推断、是否在 Sheet 里加分类选择留待判断。
  短信识别页的读取结果已按用户决定改成先进待确认账单（见 §21）：识别不出金额的短信直接跳过（取消了「手动补全」）、已确认入账的短信重新读取会再次出现在待确认列表里（去重只对着待确认列表）——这两处取舍请在真机上确认可接受。
- 导入账单页在真机上的真实链路与手感——系统文件选择器（`accept=".csv"` 在 Android WebView 里是否生效、能否从微信 / 支付宝 / 文件管理器的下载目录选到导出的账单）、MAUI Blazor Hybrid（WebView 进程内通道）下 `InputFile` 的读流（E2E 走的是 Web.Server 下 SignalR 分片的版本）、
  真实的微信 / 支付宝导出文件走完整流程（含编码）、`UtcOffsetMinutes` 在真机时区下的换算、320pt 窄屏的实际观感——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（20 号 ticket）。
  **支付宝解析器已在第 2 轮评审后修复（用户拍板）**：原先 `CsvParserService.ParseAlipayCsvAsync` 按固定位置取列，与真实导出的列布局对不上（把「收/支」当成商户、收入判断读错了列——真实导出的金额不带符号，所以真实的收入会被记成支出、把「交易状态」当成订单号）；
  现在改为**按表头名称定位各列**（`AlipayColumns`，新旧版导出的叫法都认；收入 / 支出看「收/支」列，「不计收支」与「交易关闭」等无效状态的行不计入——与微信的口径一致，这是修复之外的小扩展），并新增 `CsvParserServiceTests`（真实导出格式的样本，含制表符 / 行尾逗号 / 表头前的说明行）。
  假云端的解析镜像与 E2E 的支付宝 fixture 已同步为真实的列布局；真实导出文件走完整流程（含编码）仍归真机人工验收。导入不做去重、只列自己的账本（不能导入到共享账本，用户已确认 `own_only`）。
- 自定义报表在真机上的真实表现——系统日期选择器（iOS 滚轮 / Android 日历）的手感，以及 `min` / `max`（2000–2100 年）是否真的限制了各平台选择器的可选范围；系统分享面板；320pt 窄屏与大字号下的实际观感——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（21 号 ticket）。
  **导出 CSV 的文件在 MAUI Blazor Hybrid 里是否真的存盘、存到哪里尚未验证**：Blob + `<a download>` 在 Web.Server（桌面浏览器）里可用且 E2E 已验证文件名与内容，但 Android WebView 需要宿主设置 `DownloadListener` 才会处理下载，iOS WKWebView 对 blob 下载的支持有限；
  旧页面用的 data URI + `a[download]` 在这两个 WebView 里有同样的问题，所以这是既有风险、不是这次引入的。若真机确认不可用，需要补原生的「保存 / 分享文件」通道（新增原生能力，不在本次重构范围内），留待判断。
  「报表生成失败」占位与 Snackbar 无法在 E2E 里自动触发（读库失败没法注入）：文案由单元测试锁定，页面状态机的这一支走查代码 + 人工验收。分类排行（ECharts）的配色与统计 Tab 一样，已在 23 号 ticket 改成设计令牌（§26）。
- 登录页与错误日志页在真机上的真实表现——登录页：软键盘弹出时面板与按钮是否真的被顶进可视区（Android `adjustResize` / iOS WKWebView 是否缩小视口、`100vh` 在键盘弹出后的取值）、渐变真正铺到屏幕顶端与状态栏白色图标真正切换、号码键盘与「前往」键、系统自动填充；
  错误日志页：**真机上能否读到 Serilog 写的日志**（本次修了日志目录，首次真机验证）、复制到剪贴板（MAUI WebView 里 `navigator.clipboard` 是否可用）、导出文件的落点与用户可达性（是否需要原生的保存 / 分享通道，与 21 号的 CSV 下载同属待判断）、
  「⋯」菜单与详情 Sheet 的手感、320pt 窄屏与大字号下的观感——E2E 只能覆盖网页层，必须真机 / 模拟器人工验收（22 号 ticket）。
  沿用旧行为、没有改的几个小缺口（留待判断）：手机号只检查「11 位且以 1 开头」，不检查是否全是数字（`PhoneValidator` 是登录与邀请成员共用的规则，spec 约定不改规则）；`maxlength=11` 会截断粘贴进来的带空格 / 连字符的号码（「138 0013 8000」被截成前 11 个字符，旧页面一样，要先去格式再截断就得在输入事件里改写输入框的值，与「不受控」的做法冲突）；
  设计稿登录面板底部的「用户协议」一行没有做（应用没有协议文本，spec 也没要求）；登录说明文字（`--ft-label-2`，白底）原先的对比度约 3.2–3.6:1，已随 `--ft-label-2` 的加深在 23 号 ticket 达标（§26）；退出登录后登录页不显示一次性提示（见 §15）。日志时间按机器本地时区而不是 `AppTimeZone`（见 §24）。
- 云端相关的账本操作（共享邀请的接受 / 拒绝、成员管理）由 E2E 里的**假云端**（`tests/e2e/fake_cloud.py`，06 号 ticket 引入）覆盖成功与失败路径；
  假云端镜像真实控制器的状态码 / 消息 / 过滤规则，但不是真实的 Api + PostgreSQL，真实联调留给（可选的）人工验收。
- 冷启动只有「加载页之后」的 Web 层被自动化验证（`boot_test.py`，Chromium）；**原生部分与真机时序没有验证过，必须真机 / 模拟器人工验收**：
  ① Android 12+ 的系统启动画面（图标是否被圆形遮罩裁切、底色是否与加载页首帧无色差）与 Android 11 及以下的 `windowBackground` 路径、各厂商 ROM 的表现；iOS 启动图（`splash.svg` 生成）到加载页首帧是否有一帧色差或跳变。
  本次只在本机构建验证过 Android 目标（生成的资源与尺寸），没有构建 iOS，也没有在真机 / 模拟器上点开过。
  ② `Ft.SplashTheme` 与 `UIStatusBarStyle` 对「启动那一刻状态栏图标是白色」的实际效果；应用图标（Android 自适应图标、iOS 圆角蒙版）的实际观感，以及删除 `appicon.png` 之后各平台的图标生成。
  ③ 三个时间常量（`spinnerMs` 600 / `capMs` 1500 / `watchdogMs` 12000）是建议值，需要在真机上量过「点图标 → 外壳就绪」的分布再调；加载页在低端 Android WebView 上的帧率
  （幕布收拢是 `height` + `border-radius` 过渡，虽然只发生在 `position: fixed` 的加载页里，但没有在低端机上测过）。
  ④ MAUI Blazor Hybrid 下「页面 load 之后注入 CDN 资源」是否确实让 Blazor 更早启动：Chromium 里验证过 CDN 被拖慢时加载页照常出现、应用照常启动（`boot_test.py` G 节），WebView 里 `load` 的实际时点没有量过；离线启动时图标缺失、图表位置给出说明属于预期降级。
  ⑤ CDN 连得上却一直不返回（挂起）时，统计页图表位置会一直是骨架直到浏览器自己判定超时——只验证过「脚本加载失败」与「脚本很晚才到」两种情形。
- 无障碍与降级只有 Web 层被自动扫描过（`a11y_degradation_test.py`，Chromium 手机视口）；**以下必须真机 / 模拟器人工验收（23 号 ticket 的人工验收清单，均未完成）**：
  ① Android 系统「字体大小」调到最大 / 「显示大小」放大后的各页面（自动扫描用的是样式改写模拟，与真实 `fontScale` 不等价）；iOS 的 Dynamic Type（更大字体）同理；
  ② 低端 Android 设备上降级是否触发（3 GiB / 低内存标记的门槛是建议值）、降级后滚动与 Tab 切换是否真的更流畅；
  ③ iOS 系统「降低透明度」「减弱动态效果」开关切换后应用的即时跟随（`RenderingProfileService` 的通知监听）；Android 系统「移除动画」是否被 WebView 映射成 `prefers-reduced-motion`，取决于系统与 WebView 版本；
  ④ 对比度抽查：Hero 渐变上的白字、玻璃上的文字在真机屏幕、强光与低亮度下的可读性（自动扫描按样式与截图像素算，不含屏幕差异）；
  ⑤ 读屏（VoiceOver / TalkBack）下的朗读顺序与焦点行为——**整套读屏适配审计不在 23 号范围内**；Sheet / 语音覆盖层升起时底下页面的 `inert` 与焦点陷阱、Android 返回键先收起 Sheet / 覆盖层也未处理（见上面两条）。
- 兜底页面在真机上的观感——「页面未找到」只被 Chromium 手机视口与宽屏扫描过；**「组件渲染发生异常」没有被任何自动化触发过**（渲染失败没法注入），它的样式 / 结构由源码守卫保证，实际观感与「长按复制错误详情」要在真机上故意制造一次渲染异常人工验收（24 号 ticket）。
- 24 号的「全量回归」没有覆盖的部分：真机 / 模拟器上 18 条路由的逐页走查，以及 iOS 的 CI 构建（需要 macOS 环境；本地只验证过随 `dotnet build FinanceTracker.sln` 编译通过的目标）——它们留在各 ticket 与 24 号的「人工验收」清单里，未勾选。
